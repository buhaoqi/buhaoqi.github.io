## 知识点

### 1.呈现是系统的"最后一公里"

**数据处理的结论再正确，如果没人看得懂，价值就等于零。**

呈现要解决三个问题：

1. **看得见**——数据在哪、怎么打开；
2. **看得懂**——一眼能看出结论，不用自己算；
3. **用得上**——能支持下一步动作（决策、处置、上报）。

**好呈现的判断标准（一句话）**：**让读者在 10 秒内得到你想让他得到的那个结论。**

### 2.六种常见呈现形式

| 形式 | 特点 | 适用 |
|---|---|---|
| **表格** | 精确、可查、信息密度高 | 明细清单、对账、需要看具体数值 |
| **统计图表** | 直观、突出趋势与对比 | 汇报、分析、发现规律 |
| **报表** | 表格＋图表＋说明，成体系 | 周报月报、成绩单、财务报表 |
| **仪表盘（`Dashboard`）** | 多指标集中一屏 | 运营监控、系统状态 |
| **数据大屏** | 大尺寸、远距离可读、动态刷新 | 指挥中心、展厅、校园总览 |
| **地图／热力图** | 带空间位置 | 区域分布、门店覆盖、疫情分布 |

**选择逻辑**：**要精确看表格，要看趋势用图，要全局看大屏，要位置用地图。**

### 3.图表选用（高频考点，必须形成条件反射）

| 分析目的 | 首选图表 | 理由 |
|---|---|---|
| **比较大小**（谁多谁少） | **柱形图**（竖）／条形图（横） | 长度差异最易比较 |
| **看趋势**（随时间变化） | **折线图** | 连续线条体现走向 |
| **看占比**（部分与整体） | **饼图**／环形图 | 扇形面积体现比例 |
| **看分布**（数据落在哪） | **直方图** | 分箱统计频数 |
| **看相关性**（两者关系） | **散点图** | 点的聚集形态显示相关 |
| **看构成对比** | **堆积柱形图** | 同时看总量与构成 |
| **看多维比较** | **雷达图** | 多个维度一眼对比 |
| **看密度／热点** | **热力图** | 颜色深浅表示数值高低 |
| **看流程转化** | **漏斗图** | 各环节流失情况 |

**记忆口诀**：**比大小用柱、看趋势用线、看占比用饼、看分布用直方、看关系用散点。**

**四个常见误用（考试爱考"该用哪个图"）**：

1. **用饼图比较十几个类别**——扇形太接近，根本看不出差别，应改条形图；
2. **用折线图表示无序类别**（如各班人数）——折线暗示"连续变化"，误导；
3. **用柱形图看趋势**——柱子之间的"陡峭感"不如折线准确；
4. **3D 饼图／3D 柱形**——透视变形导致面积失真，**纯属误导**，专业场合禁用。

**饼图使用的两条硬规矩**：**类别不超过 6 个**；**各部分之和必须是 100%**。

### 4.可视化工具

| 工具 | 类型 | 优点 | 适用 |
|---|---|---|---|
| **Excel／WPS** | 桌面工具 | 上手快、图表类型全 | 教学、日常报表 |
| **`matplotlib`** | Python 库 | 精细可控、可批量生成 | 数据分析报告 |
| **`pyecharts`／`ECharts`** | 图表库 | 交互强、可嵌入网页 | 网页系统、大屏 |
| **`Tableau`／`Power BI`** | `BI` 工具 | 拖拽式分析、联动强 | 企业分析 |
| **前端框架组件** | 组件库 | 与系统无缝集成 | 信息系统页面 |

**教学路径建议**：**Excel 打基础 → Python 做批量化 → ECharts 做网页化**。三步走，能力层层递进。

### 5.Web 系统的呈现原理（本节技术重点）

**信息系统的图表不是"画"出来的，而是"数据驱动"生成的。**

**三步流程**：

**后端查数据 → 接口返回 `JSON` → 前端用图表库渲染**

**（1）后端返回数据（接口）**

```json
{
  "title": "各班平均分",
  "data": [
    { "class": "计算机1班", "avg": 82.5 },
    { "class": "计算机2班", "avg": 78.1 },
    { "class": "计算机3班", "avg": 85.3 }
  ]
}
```

**（2）前端渲染图表（以 `ECharts` 为例）**

```javascript
const chart = echarts.init(document.getElementById('main'));
chart.setOption({
  title: { text: '各班平均分' },
  tooltip: {},
  xAxis: { type: 'category', data: ['计算机1班', '计算机2班', '计算机3班'] },
  yAxis: { type: 'value', name: '平均分' },
  series: [{ type: 'bar', data: [82.5, 78.1, 85.3] }]
});
```

**（3）关键理解（三条）**

1. **数据与展示分离**——后端只给数据，前端只管画，换图表类型不用改后端；
2. **接口要稳定**——字段名一改，前端图表就空；
3. **图表要能刷新**——定时拉取接口，就实现了"实时监控"。

**这就是"数据大屏"的技术本质**：**定时请求接口 → 更新图表数据 → 画面滚动刷新**，并不是什么神秘技术。

### 6.数据大屏设计要点

| 要点 | 说明 |
|---|---|
| **远距离可读** | 字号要大，一屏不超过 6~8 个核心指标 |
| **分区清晰** | 顶部总览、左侧分类、中间主图、右侧排行 |
| **颜色有含义** | 同一含义全屏统一（如红色＝告警） |
| **动态但不炫技** | 滚动与切换服务于信息，不是为动而动 |
| **有数据更新时间** | 让人知道数据"新不新" |
| **适配分辨率** | 常见按 1920×1080 设计，等比缩放 |

**大屏最常见的失败**：**指标堆太多**。屏幕上二十个数字，观众一个也记不住。**大屏是"讲故事"，不是"搬数据库"。**

### 7.呈现的五条设计原则

| 原则 | 含义 | 反例 |
|---|---|---|
| **准确** | 数据与坐标轴不能失真 | 纵轴不从 0 开始夸大差距 |
| **简洁** | 去掉无用元素（网格线、阴影、3D） | 花哨背景盖住数据 |
| **重点突出** | 用颜色／标注引导视线 | 所有柱子一个颜色，没有重点 |
| **可比较** | 同类数据用同一尺度 | 两张图纵轴刻度不同还放一起比 |
| **可交互（网页）** | 支持悬停看数值、下钻看明细 | 只有一张静态图，看不到具体数 |

**"数据墨水比"这个概念值得讲给学生**：**图里每一滴"墨水"都应该承载信息**。多余的网格、边框、渐变、阴影，都是在稀释信息。

### 8.八种常见的"图表骗局"（识图题必考）

| 手法 | 怎么骗人 | 破法 |
|---|---|---|
| **纵轴不从 0 开始** | 微小差距被放大成"暴涨" | 看纵轴起点 |
| **截断坐标轴** | 中间断开，视觉上差距变大 | 看有无断轴标记 |
| **双纵轴滥用** | 两条曲线"看起来相关" | 看两边刻度是否被人为凑合 |
| **3D 效果** | 透视让面积／体积失真 | 要求看平面图或原始数据 |
| **面积误导** | 用图形"大小"表示数值，实际按边长缩放 | 面积应按数值的平方根缩放 |
| **选择性时间范围** | 只截取有利区间 | 看完整时间轴 |
| **只报比例不报基数** | "增长 300%"其实从 1 到 4 | 追问绝对数 |
| **平均数的陷阱** | 平均工资被少数高值拉高 | 看中位数与分布 |

**教学价值**：这一节不只是"识图"，更是**批判性思维训练**——**看到图表先问"它想让我相信什么"**。

### 9.表格与文字的呈现

**表格的三条规范**：

1. **有表头且单位写清**（"金额（元）"而不是"金额"）；
2. **数字右对齐、文字左对齐**，小数位数统一；
3. **重点行加粗或用底色**，不要整表标红。

**"表格 + 一句话结论"是最实用的组合**：

- 表格给**证据**（具体数字）；
- 一句话给**结论**（"3 班平均分最高，比最低的 2 班高 7.2 分"）。

**只给表格不给结论**，读者要自己算；**只给结论不给表格**，读者无法验证。**两者都给，才算完整的呈现。**

**文字呈现的技巧**：

- **标题写结论，不写主题**——"3 班平均分领先 7.2 分"优于"各班平均分统计"；
- **一页一个核心信息**；
- **用对比代替形容词**——"提升了 12%"比"大幅提升"有力。

### 10.移动端与多端适配

| 考虑 | 做法 |
|---|---|
| **屏幕小** | 减少一屏信息量，优先展示核心指标 |
| **触控操作** | 图表支持点按查看数值，不依赖悬停 |
| **横竖屏** | 大屏图表建议横屏或提供旋转提示 |
| **网络环境** | 图片与数据要压缩，弱网下有加载提示 |
| **响应式** | 同一页面在手机、平板、电脑都能正常显示 |

**一句话**：**同一份数据，在不同设备上应该"以最合适的形式"出现，而不是简单缩小。**

### 11.完整示例：教室环境监测的呈现设计

| 页面区域 | 内容 | 图表类型 |
|---|---|---|
| **顶部** | 当前温度、湿度、光照三个数字卡片 | 数字卡片＋状态色 |
| **左中** | 今日温湿度变化 | **双折线图**（时间轴） |
| **右中** | 各教室当前温度对比 | **条形图**（按温度排序） |
| **左下** | 温度区间分布 | **直方图** |
| **右下** | 异常记录列表 | **表格**（时间、教室、异常类型） |

**设计说明**：

1. **数字卡片**给"现在的状态"，**折线图**给"变化的趋势"，**表格**给"要处理的问题"——三种形式各司其职；
2. **异常用红色**，正常用绿色或灰色，颜色含义全页统一；
3. 所有图表**共享同一时间范围**，避免"这张图是今天、那张图是本周"的混乱。

**这个例子可以直接作为学生的课程作业模板。**

### 13.课堂提示（讲课参考）

- **"选图"练习要做成抢答**：给 10 个真实场景（班级人数、月考排名变化、手机品牌占比、身高分布、学习时长与成绩的关系……），学生举牌选图并说理由。这个练习 10 分钟能做 20 题，效果远好于讲表格。
- **图表骗局一定要"现场造假"**：用同一组数据做两张柱形图，一张纵轴从 0 开始、一张从 80 开始，投影对比。学生亲眼看到"同一组数据讲出两个相反的故事"，批判性思维就建立起来了。
- **`JSON` 到图表的过程建议现场跑一遍**：改一下接口返回的数字，刷新页面，柱子立刻变了。学生会真正理解"图表是数据驱动生成的"，而不是"画上去的"。
- **大屏设计让学生"挑毛病"**：找一张网上典型的炫酷大屏截图，让学生数有几个指标、能不能记住、红色代表什么。多数大屏都经不起这三问——顺势讲"少即是多"。
- **作业建议**：为第 3.4 节处理完的班级成绩数据设计一页呈现——一张表、两张图、三句结论。评价标准只有一条：**不看你的说明，别人能不能在 10 秒内说出结论。**
