## 知识点

### 1.什么是远程控制

**定义**：**远程控制**是指通过**通信网络**，在**异地**对目标设备进行操作、监视与管理，使其按指令完成动作的技术。

**关键点有三个**：

1. **异地**——操作端与被控端不在同一地点；
2. **有指令通道**——通过网络传递控制命令；
3. **有反馈**——被控端的状态能回传（否则就是"盲控"）。

**远程控制 ≠ 远程访问**：

- **远程访问**侧重"**看和取**"（查看文件、读取数据）；
- **远程控制**侧重"**操作和改变**"（点鼠标、开关设备、调节参数）。

### 2.系统的基本角色：客户端与服务端

**几乎所有远程控制系统都遵循"请求—响应"的基本模型**：

| 角色 | 作用 | 举例 |
|---|---|---|
| **客户端（控制端）** | 发出指令、显示结果 | 你的手机 `APP`、办公室电脑 |
| **服务端（被控端）** | 接收指令、执行动作、回传状态 | 家里电脑、田里的控制器 |
| **通信链路** | 双向传输指令与数据 | 互联网、`Wi-Fi`、4G／5G |
| **中转平台（可选）** | 解决"找不到对方"的问题 | 云平台、内网穿透服务器 |

**两种常见架构**：

| 架构 | 全称 | 特点 | 举例 |
|---|---|---|---|
| **`C/S`** | 客户端／服务器 | 需装专用客户端，功能强、效率高 | 远程桌面、TeamViewer |
| **`B/S`** | 浏览器／服务器 | 只需浏览器，免安装、跨平台 | 网页版后台管理、云平台控制页 |

**趋势**：物联网系统普遍采用 **`B/S` 或"`APP`＋云平台"** 的方式——设备主动连到云端，用户通过网页或 `APP` 操作，**绕开了"找不到设备"的难题**。

### 3.远程控制是怎么"找到对方"的

这是本节**最容易被忽略、也最容易考**的部分。

**问题**：家里和学校的网络大多是**内网**（`192.168.x.x`），外网根本"看不见"这些设备。

**三种解决办法**：

| 方案 | 做法 | 优缺点 |
|---|---|---|
| **公网 `IP`** | 向上级申请固定公网 `IP`，直接访问 | 稳定但**成本高、地址稀缺** |
| **端口映射（`NAT` 转发）** | 在路由器上把外网某端口的访问转发到内网某台设备 | 免费，但需路由器管理权限，**暴露端口有风险** |
| **内网穿透／云平台中转** | 设备**主动**连接云端服务器并保持长连接，用户访问云端 | **最常用**，无需公网 `IP`，天然适合物联网 |

**云平台中转的原理（讲清楚这一段，学生就懂物联网为什么能远程）**：

1. 设备上电后**主动**向云平台注册，建立并保持连接；
2. 用户用手机登录云平台，发出指令；
3. 云平台把指令**下发**给设备；
4. 设备执行后**上报**结果，云平台再推给手机。

**要点**：**因为连接是设备"主动发起"的，所以不需要公网 `IP`，也不需要改路由器设置**——这是它流行的根本原因。

### 4.两类控制：开环与闭环

| 类型 | 是否有反馈 | 特点 | 举例 |
|---|---|---|---|
| **开环控制** | **无反馈** | 结构简单、成本低，但**无法纠偏** | 定时浇水（不管土干不干，到点就浇） |
| **闭环控制** | **有反馈** | 能根据实际结果调整，**更准确** | 土壤湿度低于阈值才浇，达到上限停止 |

**闭环控制的四个环节**：**检测 → 比较 → 调整 → 再检测**。

**远程控制系统一定是闭环更可靠**——因为网络本身可能延迟、丢包，只有拿到反馈才能确认"指令真的执行了"。

**另一个维度：实时控制与延时控制**

| 类型 | 要求 | 举例 |
|---|---|---|
| **实时控制** | 毫秒到秒级响应 | 无人机、工业机械臂、远程手术 |
| **延时控制** | 分钟级可接受 | 远程开空调、远程浇灌、远程下载 |

**时延的来源**：网络传输、云端处理、设备响应。**远距离 + 无线 + 多级中转 = 时延大**，这是设计时要评估的。

### 5.系统的硬件组成

一个典型的远程控制系统由五部分组成：

| 组成 | 作用 | 举例 |
|---|---|---|
| **主控单元** | 采集数据、执行逻辑、收发指令 | 微控制器、单片机、工控机 |
| **传感器** | 采集现场状态（反馈的来源） | 土壤湿度、温度、光照、门磁 |
| **执行器** | 完成实际动作 | 继电器、水泵、电机、电磁阀、LED |
| **通信模块** | 与网络／云平台通信 | `Wi-Fi` 模块、4G 模块、`NB-IoT` 模块 |
| **供电** | 保证长期运行 | 电源适配器、电池＋太阳能 |

**继电器的作用必须讲清**：微控制器输出的是**弱电信号**（3.3 V／5 V），而水泵、电机需要**强电**（220 V）。**继电器就是"用小电流控制大电流"的开关**，是弱电控制强电的桥梁。**这是本节的实操关键件。**

### 6.组建步骤（六步，实操必考）

**第一步：明确需求与控制对象**

- 控制什么？（水泵、灯、电机、电脑）
- 采集什么？（湿度、温度、开关状态）
- 谁在什么地方控制？（手机、电脑、浏览器）
- 响应时间要求？（实时还是可延时）

**第二步：方案设计**

- 选通信方式（有 `Wi-Fi` 用 `Wi-Fi`，野外无网用 4G／`NB-IoT`）；
- 选平台（云平台／自建服务器／内网穿透）；
- 画系统框图：**传感器 → 主控 → 通信 → 云 → 用户 → 指令回传 → 执行器**。

**第三步：硬件连接**

1. 传感器接主控的输入引脚；
2. 继电器接主控的输出引脚，**继电器触点串在水泵／灯的供电回路中**；
3. 通信模块接主控；
4. **检查供电与共地**（这一步接错最容易烧板子）。

**第四步：编写与配置程序**

1. 连接 `Wi-Fi`、注册云平台、获得设备标识；
2. 循环读取传感器、按阈值判断、按需上报；
3. 订阅控制主题，收到指令后驱动继电器；
4. 上报执行结果（形成**闭环**）。

**第五步：联调测试**

| 测试项 | 检查什么 |
|---|---|
| 数据上报 | 云端能否看到实时数据 |
| 指令下发 | 手机点"开"，继电器是否吸合 |
| 状态回传 | 执行后状态是否更新 |
| 断网恢复 | 断网再连，能否自动重连 |
| 异常处理 | 传感器故障时是否有告警 |

**第六步：部署与运维**

- 防水防尘、固定走线、避开强电干扰；
- 设置**看门狗**（程序卡死自动重启）；
- 记录日志，便于排查。

### 7.实例一：远程浇灌系统

| 部分 | 具体配置 |
|---|---|
| 感知 | 土壤湿度传感器插入花坛 |
| 主控 | 掌控板／Arduino |
| 执行 | 继电器＋电磁阀（或小水泵） |
| 通信 | 家庭 `Wi-Fi` |
| 应用 | 云平台＋手机 `APP` |

**控制逻辑**：

1. 每 10 分钟读一次土壤湿度；
2. 湿度**低于下限**（如 30%）→ 打开电磁阀；
3. 湿度**达到上限**（如 60%）→ 关闭电磁阀；
4. 每次动作**上报**云端，手机可随时手动开关。

**设计要点**：

- **设上下限（迟滞区间）**，避免在阈值附近反复开关（"抖动"）；
- **加超时保护**——连续浇水超过 20 分钟强制关闭，防止传感器失效导致水淹；
- 野外无 `Wi-Fi` 时改用 `NB-IoT`，配太阳能供电。

### 8.实例二：远程控制教室灯光／空调

| 部分 | 具体配置 |
|---|---|
| 感知 | 光敏传感器、人体红外、温度传感器 |
| 执行 | 智能开关／红外码发射器（控制空调） |
| 通信 | 校园 `Wi-Fi` |
| 应用 | 管理平台＋手机端 |

**功能**：放学后管理员在手机上确认"无人"后一键断电；假期定时通风；光敏＋人体双条件控制走廊灯（**有人且光线暗才开**），避免"白天也亮灯"的浪费。

**要点**：**多条件组合判断**比单一阈值更合理，这也是物联网"智能"的体现——**不是简单地"超了就开"，而是"综合判断后再决定"**。

### 9.远程控制的安全风险与防范（重点）

远程控制本质上是**把设备的操作权开放到网络上**，风险随之而来。

| 风险 | 说明 | 后果 |
|---|---|---|
| **弱口令／默认密码** | 设备出厂口令未改 | 被批量扫描后接管（摄像头、路由器最常见） |
| **端口直接暴露公网** | 为图方便把管理端口映射出去 | 被扫描、爆破、利用漏洞 |
| **明文传输** | 指令与密码未加密 | 被窃听、被重放 |
| **软件漏洞** | 远控软件版本旧 | 被利用提权 |
| **授权失控** | 多人共用同一账号，无审计 | 出了问题查不到人 |

**六条防范措施（答题可直接用）**：

1. **改默认口令**，用强密码，**定期更换**；能开双因素认证的一定开；
2. **不裸奔端口**——优先用云平台或 `VPN` 中转，必须映射时**改默认端口＋限源 `IP`**；
3. **加密传输**——用 `HTTPS`／`TLS` 加密通道，不用明文协议；
4. **最小权限**——按角色分配"只看""可控制""可管理"三级权限；
5. **留审计日志**——记录谁在何时下发了什么指令，便于追溯；
6. **及时更新固件**，并**关闭不必要的服务与端口**。

**一条底线**：**凡是能从外网控制物理设备的系统，都必须假设"有人在扫描它"。**

### 11.课堂提示（讲课参考）

- **先做一次"现场远控"演示**：用手机远程点亮讲台上的一个灯泡（掌控板＋继电器＋云平台），学生看到"手机一点、灯泡就亮"，比任何定义都有说服力。演示时故意断一下网，再说明"为什么必须要有反馈"。
- **"内网找不到"这个难点要用生活类比**：内网地址像"某某小区 3 号楼 502"，小区外的人不知道你在哪个小区，所以寄不到。云平台相当于"快递驿站"——你主动去驿站登记，包裹就能转给你。学生一次就懂"为什么设备要主动连云端"。
- **继电器务必实物演示**：让学生看到"3.3 V 的小信号"怎么控制"220 V 的灯泡"，并强调**接线时断电、强电部分不让学生单独操作**。这是安全教育的天然契机。
- **开环／闭环用浇花对比**：定时浇水（开环） vs 看土干了才浇（闭环），再追问"如果传感器坏了会怎样"，引出超时保护与异常处理，把"可靠性设计"的意识带进来。
- **安全部分建议做成"事故复盘"**：讲几个真实的摄像头被入侵、路由器被劫持案例，让学生讨论"哪一步做错了"，再总结六条防范措施。比直接罗列条款记得牢。
