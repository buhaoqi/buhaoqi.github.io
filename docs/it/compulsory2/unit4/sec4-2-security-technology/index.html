4.2 信息系统安全技术

知识点​

1.技术防护的五个层次​

安全防护不是"装个杀毒软件"就完事，而是分层设防——一层被突破，还有下一层。

层次保护对象主要手段
物理安全机房、设备、线路门禁、监控、消防、UPS、防雷、防盗
网络安全传输与边界防火墙、VPN、入侵检测、网段隔离
主机安全服务器与终端打补丁、防病毒、最小服务、口令策略
应用安全系统与接口身份认证、权限控制、输入校验、防注入
数据安全数据本身加密存储、备份、脱敏、审计

核心思想：纵深防御（Defense in Depth）——不指望任何单一手段万无一失，而是让攻击者必须连续突破多层才能得手。

这条原则是本节的"纲"：后面所有技术，都是在某一层上加强。

2.加密技术：让数据"看不懂"​

基本术语（必背）：

术语含义
明文加密前的原始数据
密文加密后的数据
密钥控制加密与解密的关键参数
加密明文 → 密文
解密密文 → 明文

核心认识：安全性依赖密钥的保密，而不是算法的保密（算法是公开的，人人可研究）。

（1）对称加密

项说明
特点加密与解密用同一把密钥
代表算法DES（已不安全）、AES（主流）
优点速度快，适合大数据量
缺点密钥分发困难——怎么把密钥安全地交给对方？

（2）非对称加密（公钥加密）

项说明
特点一对密钥：公钥加密、私钥解密（或反之用于签名）
代表算法RSA、ECC
优点解决密钥分发难题，公钥可公开
缺点速度慢，一般只用于加密"密钥"或做签名

公钥与私钥的关系（务必理解）：

  • 公钥：可以公开给任何人；
  • 私钥：只有自己保管，绝不外传；
  • 用公钥加密的数据，只有对应私钥能解。

（3）两者怎么配合（实际系统的做法）

用非对称加密传"对称密钥"，再用对称密钥加密数据——兼顾安全与效率。这就是 HTTPS 握手的核心思路。

（4）哈希（散列）函数

项说明
作用把任意长度的数据映射成固定长度的摘要
特点单向不可逆、同样的输入必得同样的输出、输入微变则输出大变
代表算法MD5（已不安全）、SHA-256
用途校验完整性、存储密码（加盐哈希）

关键区分（极易混）：

  • 加密是可逆的（能解回明文）；
  • 哈希是不可逆的（不能"解回"，只能比对）。

所以网站存的不是密码，而是密码的哈希值——即使数据库泄露，攻击者拿到的也是摘要。

（5）数字签名与数字证书

数字签名：用发送方私钥对摘要加密，接收方用其公钥验证。

保证什么说明
身份真实只有私钥持有者才能签
完整性内容一改，摘要就变，验签失败
不可否认签了就不能抵赖

数字证书：由权威认证机构（CA） 签发的"网络身份证"，把公钥与身份绑定。

为什么需要证书：公钥在网上传递时可能被调包（中间人攻击）。证书由可信第三方背书，解决了"这个公钥到底是不是他的"这个问题。

（6）HTTPS 的工作过程（常考流程题）

  1. 客户端向服务器发起连接，服务器返回数字证书（含公钥）；
  2. 客户端验证证书是否由可信 CA 签发、是否过期、域名是否匹配；
  3. 验证通过后，客户端生成一个随机的对称密钥，用服务器公钥加密后发过去；
  4. 服务器用私钥解密，双方获得同一个对称密钥；
  5. 之后所有通信都用这个对称密钥加密（快）。

一句话总结：非对称加密解决"密钥怎么安全送达"，对称加密解决"数据怎么快速加密"，证书解决"公钥是不是真的"。

3.身份认证：证明"你是你"​

方式原理强度问题
口令（密码）只有你知道的东西中弱口令、撞库、被钓
动态口令（OTP）短信验证码、令牌、认证器 APP较高短信可被劫持
生物特征指纹、人脸、虹膜高不可更改（泄露即永久）、有误识
数字证书／U 盾私钥持有证明高需携带介质
双因素认证（2FA）口令＋另一种因子很高略麻烦

三种认证因子的分类（理解这张表，认证题就不会错）：

因子含义举例
你知道的知识因子密码、密保问题
你拥有的持有因子手机、U 盾、令牌
你是什么生物因子指纹、人脸

双因素认证的价值：即使密码泄露，攻击者还缺第二个因子。这是目前性价比最高的安全措施之一，重要系统（网银、邮箱、后台）都该开。

口令策略（管理+技术结合）：

  1. 足够长（12 位以上优于复杂但短的）；
  2. 不用个人信息（生日、姓名、学号）；
  3. 不同系统不同口令（防撞库）；
  4. 定期更换（尤其怀疑泄露时）；
  5. 加盐哈希存储（系统侧，不能明文存密码）。

4.访问控制：谁能做什么​

模型全称思路适用
ACL访问控制列表给每个对象列一份"谁能访问"的清单文件共享、目录权限
RBAC基于角色的访问控制先定角色，再给角色配权限，最后把人放进角色信息系统（最常用）
ABAC基于属性的访问控制按属性与条件动态判断（时间、地点、部门）复杂场景

RBAC 为什么好用："学生""教师""教务员""管理员"四个角色，权限配一次，人员调动只改角色归属——不用逐个改权限。

最小权限原则：只授予完成工作所必需的最小权限。

权限设计的三个常见错误：

  1. 一刀切——所有人都是管理员；
  2. 只增不减——人员调岗后旧权限没收回；
  3. 只控菜单不控接口——页面上看不到按钮，但直接调接口仍能操作（这是最常见的越权漏洞）。

重要提醒：权限校验必须做在后端。前端隐藏按钮只是"看不见"，不是"做不到"。

5.防火墙：网络边界的"门卫"​

类型工作方式特点
包过滤防火墙按源／目的 IP、端口、协议逐包检查快、简单，配置粒度粗
状态检测防火墙记录连接状态，判断是否属于已建立的会话更智能，主流
应用代理防火墙代理应用层请求，深度检查内容更安全，性能开销大
下一代防火墙（NGFW）集成应用识别、入侵防御、病毒过滤功能全面

防火墙的基本策略（理解思路比记型号重要）：

  • 默认拒绝，按需放行——只开业务必需的端口（如 80／443），其余全部拒绝；
  • 不要"默认放行"——那等于没设防。

防火墙的局限（常考）：

  1. 挡不住内部攻击——内部人员绕过边界；
  2. 挡不住应用层漏洞——SQL 注入走的是 80 端口，防火墙认为是"正常流量"；
  3. 挡不住社会工程学——人自己把密码交出去了。

所以防火墙必须与入侵检测、应用加固、管理措施配合。

6.入侵检测与防御​

系统作用特点
IDS（入侵检测系统）发现异常与攻击行为，告警只"看"不"拦"，旁路部署
IPS（入侵防御系统）发现并阻断串联部署，能主动拦截

检测方法：

方法原理优点缺点
特征检测匹配已知攻击特征库准确、误报少挡不住新攻击
异常检测建立正常行为基线，偏离即告警能发现未知攻击误报较多

一句话区分：IDS 是"监控摄像头"，IPS 是"带拦截功能的门禁"。

7.VPN：在公网上建"专用通道"​

VPN（虚拟专用网）：在公用网络上，通过加密隧道建立逻辑上的专用网络。

用途说明
远程接入在家安全访问校内资源
分支互联多个校区通过公网连成一个内网
公共网络安全在不安全的 Wi-Fi 上加密通信

核心价值：加密＋身份认证——数据在公网上传输也是密文，即使被截获也看不懂。

常见协议：IPsec、SSL VPN（浏览器直接接入，最常用）、L2TP。

注意：VPN 是技术工具，必须依法依规使用，不得用于绕过监管。

8.备份与容灾：最后一道防线​

备份的三种方式（必考对比）：

方式备份什么速度恢复空间
完全备份全部数据慢最快（一份就够）占用最大
增量备份上次备份之后变化的数据快慢（要依次恢复多次）最小
差异备份上次完全备份之后变化的数据中中（完全＋最后一次差异）中

实用组合：每周一次完全备份 ＋ 每天一次增量备份——兼顾空间与恢复速度。

3-2-1 备份原则（业界共识，非常好记）：

  • 3 份数据副本；
  • 2 种不同介质；
  • 1 份异地／离线存放。

为什么必须"离线"：勒索软件会加密所有能访问到的备份。联网的备份等于没有备份。

容灾的层次：

层次说明恢复时间
数据备份只保数据小时到天
应用容灾备用服务器可接管分钟到小时
业务容灾双活数据中心，业务不中断秒到分钟

RAID（磁盘阵列）：多块硬盘组合，提升可靠性或性能。

  • RAID 0：条带化，性能最高但无冗余（一块坏全丢）；
  • RAID 1：镜像，可靠性高，容量利用率 50%；
  • RAID 5：条带＋校验，兼顾容量与可靠性（允许坏一块）；
  • RAID 10：镜像＋条带，性能与可靠性都好，成本高。

提醒：RAID 不是备份。它防硬件故障，但防不了误删、病毒、火灾——删掉的数据在所有盘上同时消失。

9.恶意代码防护​

手段作用注意
防病毒软件特征扫描＋行为监控病毒库要及时更新
系统补丁修补已知漏洞及时安装，但先在测试环境验证
关闭不必要服务与端口减少攻击面用不到就关
应用白名单只允许运行可信程序有效但管理成本高
邮件与附件过滤拦截恶意附件与链接配合用户教育

"补丁"这件事要强调：大多数大规模攻击利用的都是"已经发布补丁、但用户没打"的老漏洞。打补丁不酷，但最有效。

10.数据脱敏与水印​

技术作用举例
脱敏隐藏敏感字段的部分内容手机号 138****5678、身份证 1101**********1234
加密存储即使拿到库也看不懂密码加盐哈希、证件号加密列
水印标记数据来源，防外泄导出文件盖"仅限内部使用＋工号"
数据分级按敏感程度分级管理公开／内部／秘密／机密

脱敏的价值：让"该看的人看全，不该看的人看遮"——既满足业务需要，又降低泄露风险。客服查订单只需看后四位手机号，不需要看全。

11.日志与审计​

日志记录什么：谁、在什么时间、从哪个地址、做了什么、结果如何。

日志类型内容
登录日志登录成功／失败、来源 IP
操作日志增删改查的关键操作
安全日志攻击告警、权限变更、配置修改
系统日志服务启停、错误与异常

审计的三个作用：

  1. 事后追查——出问题能还原过程；
  2. 威慑——知道有日志，内部人员不敢乱来；
  3. 发现异常——如"凌晨 3 点有人从境外登录管理员账号"。

关键要求：日志要独立存放、防篡改、保留足够长时间（不少规范要求 6 个月以上）。日志存在被攻破的同一台机器上，等于没有。

12.技术组合示例：一个校园系统的防护设计​

层次措施
物理机房门禁＋监控＋UPS＋消防
网络边界防火墙（默认拒绝）＋IPS＋内外网隔离＋VPN 远程接入
主机系统补丁自动更新＋防病毒＋关闭多余端口＋强口令策略
应用双因素登录＋RBAC 权限＋参数化查询＋后端校验＋HTTPS
数据密码加盐哈希＋证件号加密＋列表脱敏＋每日增量＋每周完全＋异地离线备份
审计全量日志集中存储＋异常登录告警＋定期审计

这份表格就是"纵深防御"的具体落地——答辩、方案、简答题都可以按这六层写。

14.课堂提示（讲课参考）​

  • 加密这一节必须"动手算一次"：用最简单的凯撒密码或异或加密，让学生亲手把一句话加密再解密；再演示哈希（同一句话哈希值相同、改一个字完全不同）。"可逆 vs 不可逆"这个关键区别，算一次就懂。
  • HTTPS 用"寄保险箱"类比：服务器把"带锁的空箱子（公钥）"寄给你，你把"对称密钥"放进去锁好寄回，之后双方用这把钥匙通信。证书相当于这个箱子上的"官方防伪标"。这个类比可以完整覆盖整个握手流程。
  • 对称与非对称用"快递"类比：对称加密像"一把钥匙开一把锁，但钥匙得先送给对方"；非对称像"公开的投递口，只有主人有开箱钥匙"。效率与安全的权衡自然浮现。
  • 备份环节务必做一次"删库恢复"演练：让学生亲手删掉一份数据，再从备份恢复。没做过恢复演练的备份，不能算备份——这句话学生做一次就信了。
  • RBAC 用班级职务类比：班长、学习委员、劳动委员，各有权责；换人只换"谁当班长"，不改"班长能干什么"。学生一听就明白"角色"和"人"要分开。
