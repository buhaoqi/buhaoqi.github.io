## 知识点

### 1.技术防护的五个层次

安全防护不是"装个杀毒软件"就完事，而是**分层设防**——一层被突破，还有下一层。

| 层次 | 保护对象 | 主要手段 |
|---|---|---|
| **物理安全** | 机房、设备、线路 | 门禁、监控、消防、UPS、防雷、防盗 |
| **网络安全** | 传输与边界 | 防火墙、`VPN`、入侵检测、网段隔离 |
| **主机安全** | 服务器与终端 | 打补丁、防病毒、最小服务、口令策略 |
| **应用安全** | 系统与接口 | 身份认证、权限控制、输入校验、防注入 |
| **数据安全** | 数据本身 | 加密存储、备份、脱敏、审计 |

**核心思想：纵深防御（`Defense in Depth`）**——**不指望任何单一手段万无一失**，而是让攻击者必须连续突破多层才能得手。

**这条原则是本节的"纲"**：后面所有技术，都是在某一层上加强。

### 2.加密技术：让数据"看不懂"

**基本术语（必背）**：

| 术语 | 含义 |
|---|---|
| **明文** | 加密前的原始数据 |
| **密文** | 加密后的数据 |
| **密钥** | 控制加密与解密的关键参数 |
| **加密** | 明文 → 密文 |
| **解密** | 密文 → 明文 |

**核心认识**：**安全性依赖密钥的保密，而不是算法的保密**（算法是公开的，人人可研究）。

**（1）对称加密**

| 项 | 说明 |
|---|---|
| **特点** | 加密与解密用**同一把密钥** |
| **代表算法** | `DES`（已不安全）、`AES`（主流） |
| **优点** | **速度快**，适合大数据量 |
| **缺点** | **密钥分发困难**——怎么把密钥安全地交给对方？ |

**（2）非对称加密（公钥加密）**

| 项 | 说明 |
|---|---|
| **特点** | 一对密钥：**公钥加密、私钥解密**（或反之用于签名） |
| **代表算法** | `RSA`、`ECC` |
| **优点** | **解决密钥分发难题**，公钥可公开 |
| **缺点** | **速度慢**，一般只用于加密"密钥"或做签名 |

**公钥与私钥的关系（务必理解）**：

- **公钥**：可以公开给任何人；
- **私钥**：只有自己保管，**绝不外传**；
- **用公钥加密的数据，只有对应私钥能解**。

**（3）两者怎么配合（实际系统的做法）**

**用非对称加密传"对称密钥"，再用对称密钥加密数据**——兼顾安全与效率。这就是 `HTTPS` 握手的核心思路。

**（4）哈希（散列）函数**

| 项 | 说明 |
|---|---|
| **作用** | 把任意长度的数据映射成**固定长度的摘要** |
| **特点** | **单向不可逆**、同样的输入必得同样的输出、**输入微变则输出大变** |
| **代表算法** | `MD5`（已不安全）、`SHA-256` |
| **用途** | 校验完整性、存储密码（加盐哈希） |

**关键区分（极易混）**：

- **加密是可逆的**（能解回明文）；
- **哈希是不可逆的**（不能"解回"，只能比对）。

**所以网站存的不是密码，而是密码的哈希值**——即使数据库泄露，攻击者拿到的也是摘要。

**（5）数字签名与数字证书**

**数字签名**：**用发送方私钥对摘要加密**，接收方用其公钥验证。

| 保证什么 | 说明 |
|---|---|
| **身份真实** | 只有私钥持有者才能签 |
| **完整性** | 内容一改，摘要就变，验签失败 |
| **不可否认** | 签了就不能抵赖 |

**数字证书**：由**权威认证机构（`CA`）** 签发的"网络身份证"，把**公钥与身份绑定**。

**为什么需要证书**：公钥在网上传递时可能被调包（中间人攻击）。**证书由可信第三方背书，解决了"这个公钥到底是不是他的"这个问题。**

**（6）`HTTPS` 的工作过程（常考流程题）**

1. 客户端向服务器发起连接，服务器返回**数字证书**（含公钥）；
2. 客户端**验证证书**是否由可信 `CA` 签发、是否过期、域名是否匹配；
3. 验证通过后，客户端生成一个**随机的对称密钥**，用服务器**公钥加密**后发过去；
4. 服务器用**私钥解密**，双方获得**同一个对称密钥**；
5. 之后所有通信都用这个**对称密钥加密**（快）。

**一句话总结**：**非对称加密解决"密钥怎么安全送达"，对称加密解决"数据怎么快速加密"，证书解决"公钥是不是真的"。**

### 3.身份认证：证明"你是你"

| 方式 | 原理 | 强度 | 问题 |
|---|---|---|---|
| **口令（密码）** | 只有你知道的东西 | 中 | 弱口令、撞库、被钓 |
| **动态口令（`OTP`）** | 短信验证码、令牌、认证器 `APP` | 较高 | 短信可被劫持 |
| **生物特征** | 指纹、人脸、虹膜 | 高 | 不可更改（泄露即永久）、有误识 |
| **数字证书／`U` 盾** | 私钥持有证明 | 高 | 需携带介质 |
| **双因素认证（`2FA`）** | **口令＋另一种因子** | **很高** | 略麻烦 |

**三种认证因子的分类（理解这张表，认证题就不会错）**：

| 因子 | 含义 | 举例 |
|---|---|---|
| **你知道的** | 知识因子 | 密码、密保问题 |
| **你拥有的** | 持有因子 | 手机、`U` 盾、令牌 |
| **你是什么** | 生物因子 | 指纹、人脸 |

**双因素认证的价值**：**即使密码泄露，攻击者还缺第二个因子**。这是目前**性价比最高的安全措施**之一，重要系统（网银、邮箱、后台）都该开。

**口令策略（管理+技术结合）**：

1. **足够长**（12 位以上优于复杂但短的）；
2. **不用个人信息**（生日、姓名、学号）；
3. **不同系统不同口令**（防撞库）；
4. **定期更换**（尤其怀疑泄露时）；
5. **加盐哈希存储**（系统侧，不能明文存密码）。

### 4.访问控制：谁能做什么

| 模型 | 全称 | 思路 | 适用 |
|---|---|---|---|
| **`ACL`** | 访问控制列表 | 给**每个对象**列一份"谁能访问"的清单 | 文件共享、目录权限 |
| **`RBAC`** | **基于角色的访问控制** | 先定**角色**，再给角色配权限，最后把人放进角色 | 信息系统（**最常用**） |
| **`ABAC`** | 基于属性的访问控制 | 按属性与条件动态判断（时间、地点、部门） | 复杂场景 |

**`RBAC` 为什么好用**：**"学生""教师""教务员""管理员"四个角色，权限配一次，人员调动只改角色归属**——不用逐个改权限。

**最小权限原则**：**只授予完成工作所必需的最小权限**。

**权限设计的三个常见错误**：

1. **一刀切**——所有人都是管理员；
2. **只增不减**——人员调岗后旧权限没收回；
3. **只控菜单不控接口**——页面上看不到按钮，但直接调接口仍能操作（**这是最常见的越权漏洞**）。

**重要提醒**：**权限校验必须做在后端**。前端隐藏按钮只是"看不见"，不是"做不到"。

### 5.防火墙：网络边界的"门卫"

| 类型 | 工作方式 | 特点 |
|---|---|---|
| **包过滤防火墙** | 按源／目的 `IP`、端口、协议**逐包检查** | 快、简单，配置粒度粗 |
| **状态检测防火墙** | 记录连接状态，判断是否属于已建立的会话 | 更智能，主流 |
| **应用代理防火墙** | 代理应用层请求，深度检查内容 | 更安全，性能开销大 |
| **下一代防火墙（`NGFW`）** | 集成应用识别、入侵防御、病毒过滤 | 功能全面 |

**防火墙的基本策略（理解思路比记型号重要）**：

- **默认拒绝，按需放行**——只开业务必需的端口（如 `80`／`443`），其余全部拒绝；
- **不要"默认放行"**——那等于没设防。

**防火墙的局限（常考）**：

1. **挡不住内部攻击**——内部人员绕过边界；
2. **挡不住应用层漏洞**——`SQL` 注入走的是 `80` 端口，防火墙认为是"正常流量"；
3. **挡不住社会工程学**——人自己把密码交出去了。

**所以防火墙必须与入侵检测、应用加固、管理措施配合。**

### 6.入侵检测与防御

| 系统 | 作用 | 特点 |
|---|---|---|
| **`IDS`（入侵检测系统）** | **发现**异常与攻击行为，**告警** | 只"看"不"拦"，旁路部署 |
| **`IPS`（入侵防御系统）** | **发现并阻断** | 串联部署，能主动拦截 |

**检测方法**：

| 方法 | 原理 | 优点 | 缺点 |
|---|---|---|---|
| **特征检测** | 匹配已知攻击特征库 | 准确、误报少 | **挡不住新攻击** |
| **异常检测** | 建立正常行为基线，偏离即告警 | 能发现未知攻击 | 误报较多 |

**一句话区分**：**`IDS` 是"监控摄像头"，`IPS` 是"带拦截功能的门禁"**。

### 7.VPN：在公网上建"专用通道"

**`VPN`（虚拟专用网）**：在公用网络上，通过**加密隧道**建立**逻辑上的专用网络**。

| 用途 | 说明 |
|---|---|
| **远程接入** | 在家安全访问校内资源 |
| **分支互联** | 多个校区通过公网连成一个内网 |
| **公共网络安全** | 在不安全的 `Wi-Fi` 上加密通信 |

**核心价值**：**加密＋身份认证**——数据在公网上传输也是密文，即使被截获也看不懂。

**常见协议**：`IPsec`、`SSL VPN`（浏览器直接接入，最常用）、`L2TP`。

**注意**：`VPN` 是**技术工具**，**必须依法依规使用**，不得用于绕过监管。

### 8.备份与容灾：最后一道防线

**备份的三种方式（必考对比）**：

| 方式 | 备份什么 | 速度 | 恢复 | 空间 |
|---|---|---|---|---|
| **完全备份** | 全部数据 | 慢 | **最快**（一份就够） | 占用**最大** |
| **增量备份** | 上次备份**之后**变化的数据 | 快 | 慢（要依次恢复多次） | **最小** |
| **差异备份** | 上次**完全备份**之后变化的数据 | 中 | 中（完全＋最后一次差异） | 中 |

**实用组合**：**每周一次完全备份 ＋ 每天一次增量备份**——兼顾空间与恢复速度。

**`3-2-1` 备份原则（业界共识，非常好记）**：

- **3** 份数据副本；
- **2** 种不同介质；
- **1** 份**异地／离线**存放。

**为什么必须"离线"**：勒索软件会加密所有**能访问到**的备份。**联网的备份等于没有备份。**

**容灾的层次**：

| 层次 | 说明 | 恢复时间 |
|---|---|---|
| **数据备份** | 只保数据 | 小时到天 |
| **应用容灾** | 备用服务器可接管 | 分钟到小时 |
| **业务容灾** | 双活数据中心，业务不中断 | 秒到分钟 |

**`RAID`（磁盘阵列）**：多块硬盘组合，提升**可靠性**或**性能**。

- **`RAID 0`**：条带化，**性能最高但无冗余**（一块坏全丢）；
- **`RAID 1`**：镜像，**可靠性高**，容量利用率 50%；
- **`RAID 5`**：条带＋校验，**兼顾容量与可靠性**（允许坏一块）；
- **`RAID 10`**：镜像＋条带，性能与可靠性都好，成本高。

**提醒**：**`RAID` 不是备份**。它防硬件故障，但**防不了误删、病毒、火灾**——删掉的数据在所有盘上同时消失。

### 9.恶意代码防护

| 手段 | 作用 | 注意 |
|---|---|---|
| **防病毒软件** | 特征扫描＋行为监控 | **病毒库要及时更新** |
| **系统补丁** | 修补已知漏洞 | 及时安装，但先在测试环境验证 |
| **关闭不必要服务与端口** | 减少攻击面 | 用不到就关 |
| **应用白名单** | 只允许运行可信程序 | 有效但管理成本高 |
| **邮件与附件过滤** | 拦截恶意附件与链接 | 配合用户教育 |

**"补丁"这件事要强调**：**大多数大规模攻击利用的都是"已经发布补丁、但用户没打"的老漏洞**。打补丁不酷，但最有效。

### 10.数据脱敏与水印

| 技术 | 作用 | 举例 |
|---|---|---|
| **脱敏** | 隐藏敏感字段的部分内容 | 手机号 `138****5678`、身份证 `1101**********1234` |
| **加密存储** | 即使拿到库也看不懂 | 密码加盐哈希、证件号加密列 |
| **水印** | 标记数据来源，防外泄 | 导出文件盖"仅限内部使用＋工号" |
| **数据分级** | 按敏感程度分级管理 | 公开／内部／秘密／机密 |

**脱敏的价值**：**让"该看的人看全，不该看的人看遮"**——既满足业务需要，又降低泄露风险。客服查订单只需看后四位手机号，不需要看全。

### 11.日志与审计

**日志记录什么**：**谁、在什么时间、从哪个地址、做了什么、结果如何**。

| 日志类型 | 内容 |
|---|---|
| **登录日志** | 登录成功／失败、来源 `IP` |
| **操作日志** | 增删改查的关键操作 |
| **安全日志** | 攻击告警、权限变更、配置修改 |
| **系统日志** | 服务启停、错误与异常 |

**审计的三个作用**：

1. **事后追查**——出问题能还原过程；
2. **威慑**——知道有日志，内部人员不敢乱来；
3. **发现异常**——如"凌晨 3 点有人从境外登录管理员账号"。

**关键要求**：**日志要独立存放、防篡改、保留足够长时间**（不少规范要求 6 个月以上）。**日志存在被攻破的同一台机器上，等于没有。**

### 12.技术组合示例：一个校园系统的防护设计

| 层次 | 措施 |
|---|---|
| **物理** | 机房门禁＋监控＋`UPS`＋消防 |
| **网络** | 边界防火墙（默认拒绝）＋`IPS`＋内外网隔离＋`VPN` 远程接入 |
| **主机** | 系统补丁自动更新＋防病毒＋关闭多余端口＋强口令策略 |
| **应用** | 双因素登录＋`RBAC` 权限＋参数化查询＋后端校验＋`HTTPS` |
| **数据** | 密码加盐哈希＋证件号加密＋列表脱敏＋每日增量＋每周完全＋异地离线备份 |
| **审计** | 全量日志集中存储＋异常登录告警＋定期审计 |

**这份表格就是"纵深防御"的具体落地**——**答辩、方案、简答题都可以按这六层写**。

### 14.课堂提示（讲课参考）

- **加密这一节必须"动手算一次"**：用最简单的凯撒密码或异或加密，让学生亲手把一句话加密再解密；再演示哈希（同一句话哈希值相同、改一个字完全不同）。**"可逆 vs 不可逆"这个关键区别，算一次就懂。**
- **`HTTPS` 用"寄保险箱"类比**：服务器把"带锁的空箱子（公钥）"寄给你，你把"对称密钥"放进去锁好寄回，之后双方用这把钥匙通信。**证书相当于这个箱子上的"官方防伪标"**。这个类比可以完整覆盖整个握手流程。
- **对称与非对称用"快递"类比**：对称加密像"一把钥匙开一把锁，但钥匙得先送给对方"；非对称像"公开的投递口，只有主人有开箱钥匙"。**效率与安全的权衡**自然浮现。
- **备份环节务必做一次"删库恢复"演练**：让学生亲手删掉一份数据，再从备份恢复。**没做过恢复演练的备份，不能算备份**——这句话学生做一次就信了。
- **`RBAC` 用班级职务类比**：班长、学习委员、劳动委员，各有权责；换人只换"谁当班长"，不改"班长能干什么"。学生一听就明白"角色"和"人"要分开。
