4.1 信息系统安全风险

知识点​

1.本单元要学什么​

单元主题：信息系统的安全——先知道"哪里会出事"，再学"怎么防"，最后懂"怎么管"。

小节核心问题
4.1 信息系统安全风险有哪些威胁？从哪来？为什么挡不住？
4.2 信息系统安全技术有哪些技术手段？各自防什么？
4.3 信息系统安全管理为什么"技术不是万能"？制度和人的作用是什么？

一句话主线：风险 → 技术 → 管理。三者缺一不可：不懂风险防不住，只有技术管不好，没有管理守不住。

2.信息安全要保护什么（五要素，必背）​

要素英文含义被破坏的例子
保密性Confidentiality信息只被授权者看到成绩单被泄露到网上
完整性Integrity信息未被非法篡改成绩被人偷偷改高
可用性Availability授权者需要时能用服务器被攻击瘫痪，教务系统打不开
可控性Controllability信息传播与使用可被管控内部文件被随意转发无法追溯
不可否认性Non-repudiation行为事后不能抵赖声称"我没提交过这个申请"

记忆口诀：保密（不让看）、完整（不让改）、可用（不让瘫）、可控（不乱传）、不可否认（赖不掉）。

最常考的组合：保密性、完整性、可用性合称 CIA 三要素，是信息安全的基础目标。

注意"可用性"容易被忽视：很多学生只想到"别泄露"，但系统打不开、数据取不出，同样是严重的安全事故（如医院系统宕机、考试报名系统崩溃）。

3.风险的来源：威胁与脆弱性​

安全事件 = 威胁利用脆弱性造成损失。这个公式要理解透：

概念含义举例
威胁可能造成损害的外部或内部因素黑客、病毒、内部人员误操作
脆弱性（漏洞）系统自身的薄弱点弱口令、未打补丁、配置不当
风险威胁利用脆弱性造成损失的可能性与后果弱口令被爆破，导致数据泄露

关键认识：没有脆弱性，威胁就无从下手；没有威胁，脆弱性也不会造成损失。所以防护有两条路：降低威胁（防） 和 减少脆弱性（补）。

风险来源的两大分类：

分类具体来源
人为因素外部：黑客、犯罪团伙、竞争对手；内部：员工误操作、离职人员报复、内部人员窃密
自然因素火灾、水灾、地震、雷击、停电、温湿度失控

最容易被低估的是"内部威胁"——统计上，相当比例的数据泄露与内部人员有关（误操作、越权访问、被收买）。这也是 4.3 强调管理的原因。

4.恶意代码：最常见的威胁​

类型特点传播方式典型危害
计算机病毒寄生在文件或程序中，需宿主，可自我复制拷贝文件、下载、邮件附件破坏文件、拖慢系统
蠕虫独立运行，不需要宿主，可自行在网络中传播网络漏洞、共享目录大量占用带宽，造成网络瘫痪
木马伪装成正常程序，隐藏在系统中捆绑下载、钓鱼附件远程控制、窃取账号密码
勒索软件加密用户文件，索要赎金钓鱼邮件、漏洞利用、弱口令文件被锁，业务中断
间谍软件秘密收集用户行为与信息捆绑安装隐私泄露
广告软件强制推送广告捆绑安装干扰使用

病毒与蠕虫的核心区别（高频考点）：

  • 病毒需要宿主（寄生在文件里，用户运行才激活）；
  • 蠕虫不需要宿主（自己能独立传播，主动扫描漏洞）。

木马与病毒的核心区别：

  • 病毒重在"破坏"；
  • 木马重在"控制与窃取"（不破坏，反而尽量隐蔽）。

勒索软件为什么危险：它不偷数据，而是锁住数据。对学校、医院这类"数据就是业务"的单位，一旦中招几乎无法运转。唯一的有效防线是"离线备份"——备份在网络上，同样会被加密。

5.网络攻击手段​

手段原理典型表现防范
钓鱼伪造可信来源骗取账号密码假登录页、假中奖短信核对域名、不点陌生链接
社会工程学利用人的信任与疏忽套取信息冒充客服要验证码不轻信、多核实、不透露验证码
暴力破解／撞库反复试密码；用泄露的账号密码去试其他网站账号被盗强密码、不同网站用不同密码、双因素认证
DDoS用大量"肉鸡"同时请求，耗尽资源网站打不开流量清洗、带宽扩容、云防护
SQL 注入在输入框里拼入 SQL 语句，操纵数据库绕过登录、拖库参数化查询、输入校验、最小权限
跨站脚本（XSS）在页面注入恶意脚本窃取 Cookie、弹窗劫持输出转义、内容过滤
中间人攻击截获并可能篡改通信公共 Wi-Fi 窃密HTTPS、不连陌生热点
APT（高级持续性威胁）长期潜伏、定向渗透长期窃密不被发现威胁情报、异常行为监测

"撞库"必须讲清：不是攻破你的密码，而是拿别的网站泄露的账号密码来试。所以"一个密码走天下"极其危险——一个网站泄露，所有账号沦陷。

"社会工程学"是技术之外的攻击：它攻的不是系统，而是人。冒充"教务处老师"打电话要学生身份证号，成功率远高于任何黑客技术。这也是"管理"必须存在的原因。

6.系统自身的脆弱性​

脆弱性说明后果
弱口令／默认口令123456、admin、生日被轻易猜中或爆破
未打补丁系统或软件漏洞未修复被已知漏洞攻击
配置不当端口对外开放、权限过宽、目录可浏览敏感信息暴露
权限混乱所有人都是管理员越权操作、误删数据
缺乏日志出事无记录无法追查
无备份数据只有一份一旦损坏全丢
传输不加密明文传输密码被窃听
开发缺陷注入、越权、上传漏洞被直接利用

结论：大多数被攻破的系统，不是被"高明的黑客"攻破，而是栽在"默认密码没改、补丁没打"这类低级问题上。

"最小权限原则"值得单独强调：每个账号只给完成工作所必需的最小权限。一个只需要查成绩的账号，不该有修改成绩的权限——这样即使账号被盗，损失也可控。

7.校园与生活中的典型风险场景​

场景风险正确做法
公共 Wi-Fi中间人窃听、假热点不传敏感信息，用 HTTPS
U 盘拷贝病毒传播先查毒再打开，关闭自动运行
钓鱼邮件假附件、假链接核对发件人域名，不轻易点开
弱密码账号被盗强密码＋不同网站不同密码
社交平台晒信息泄露学校、班级、住址、行程少晒证件、车票、门牌
随手扫码恶意二维码指向钓鱼页只扫可信来源的码
公共电脑保存密码下一个使用者直接登录用完退出、不勾"记住密码"

特别提醒学生："身份证照片 + 手机号 + 验证码"这三样凑齐，几乎可以冒充你办成很多事。任何情况下都不外传验证码。

8.安全事件的影响​

影响维度表现
数据层面数据泄露、被篡改、被删除、被加密勒索
业务层面系统瘫痪、业务中断、考试／挂号／支付无法进行
经济层面直接损失（赎金、赔偿）＋间接损失（停工、恢复成本）
法律层面违反《网络安全法》《个人信息保护法》，面临处罚与民事赔偿
声誉层面信任崩塌，用户流失

"恢复成本远高于防护成本" 是安全领域的基本规律——事前投入一元，胜过事后补救一百元。

9.速查表​

序号考点结论
1安全五要素保密性、完整性、可用性、可控性、不可否认性
2CIA 三要素保密、完整、可用
3最易被忽视的要素可用性
4安全事件公式威胁 × 脆弱性 → 风险
5风险来源两大类人为因素、自然因素
6最易被低估的来源内部威胁
7病毒的特点需宿主、可自我复制
8蠕虫的特点不需宿主、可自行传播
9木马的特点伪装隐藏，远程控制与窃密
10勒索软件的核心危害加密文件索要赎金
11勒索软件唯一有效防线离线备份
12钓鱼攻击的目标骗取账号密码等凭据
13社会工程学攻击对象人，不是系统
14撞库的原理用别站泄露的密码来试
15DDoS 的目的耗尽资源，使服务不可用
16SQL 注入的防范参数化查询＋输入校验
17中间人攻击的防范HTTPS、不连陌生热点
18最常见的低级漏洞默认口令未改、补丁未打
19最小权限原则只给工作必需的权限
20验证码铁律任何情况不外传
21成本规律恢复成本远高于防护成本

10.课堂提示（讲课参考）​

  • 开场做一个"钓鱼实验"：课前用问卷工具做一个仿冒"校园网登录"页面，课上展示有多少同学填了账号。不发真实收集，只为说明"技术手段再强，也挡不住人主动把密码交出去"。这个体验比讲十条定义都深刻。
  • 五要素用"成绩单"一条线讲透：成绩被同学看到＝保密性失守；被改成 100 分＝完整性失守；教务系统打不开＝可用性失守；被转发到外校＝可控性失守；学生说"我没提交过改分申请"＝不可否认性失守。一个场景讲完五个概念，学生不会混。
  • 病毒与蠕虫的区别要落到"要不要宿主"上：用"寄生虫"和"自己会走路的虫子"类比，再各举一例（U 盘里的病毒／冲击波蠕虫）。这个对比几乎不会记错。
  • 勒索软件建议讲真实案例：某医院／学校中招后业务停摆数天，最终靠离线备份恢复。顺势强调"备份必须离线，联网的备份会一起被加密"。
  • "撞库"让学生自查：问"有多少人微信、QQ、游戏账号用同一个密码"，然后讲一个网站泄露的连锁后果。这是最贴近学生生活的安全课。
