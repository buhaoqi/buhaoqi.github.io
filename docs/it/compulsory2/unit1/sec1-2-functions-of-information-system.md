## 知识点

### 1.从"组成"到"功能"

1.1 把系统"拆开"看要素，1.2 把系统"合上"看功能。两节的关系可以用一句话概括：

**有什么要素，决定了能做什么功能；有什么功能，决定了该配什么要素。**

| 要素 | 主要支撑的功能 |
|---|---|
| 输入设备、传感器 | 输入 |
| 处理器、程序 | 处理 |
| 存储器、数据库 | 存储 |
| 显示、打印、网络 | 输出 |
| 操作系统、管理制度 | 控制 |

**答题时的通用思路**：问"功能"，答"五功能"；问"靠什么实现"，把要素一一对应上去。

### 2.信息系统的五项基本功能（必背）

**输入 → 处理 → 存储 → 输出 → 控制**

| 功能 | 定义 | 关键动作 | 举例 |
|---|---|---|---|
| **输入** | 把原始数据采集并送入系统 | 采集、录入、校验、转换 | 扫码、刷卡、键盘录入、传感器上报 |
| **处理** | 按既定规则对数据进行运算与判断 | 计算、比对、分类、汇总、排序、检索 | 计算总分、判断余额、统计各科平均分 |
| **存储** | 把数据与结果长期保存，供再次使用 | 写入、更新、索引、备份 | 存入数据库表、写入日志文件 |
| **输出** | 把处理结果以人能理解的形式呈现 | 显示、打印、导出、推送 | 成绩单、报表、短信通知、网页图表 |
| **控制** | 协调各环节有序运行，保证正确与安全 | 流程控制、权限控制、异常处理、日志审计 | 余额不足拒绝交易、越权访问被拦截 |

**容易混的两个概念**：

- **"处理"是对数据做运算，"控制"是对过程做管理**。计算平均分是处理；规定"只有教务员才能改成绩"是控制。
- **"输出"是给用户看结果，"存储"是给系统留底**。同一份数据，既要输出给人，也要存起来备查。

### 3.输入功能：数据从哪来

**输入是系统的"入口"，输入质量直接决定输出质量**——这就是"**垃圾进、垃圾出**"（GIGO）。

**常见的五种输入方式**：

| 方式 | 说明 | 优点 | 缺点／适用 |
|---|---|---|---|
| **人工录入** | 键盘输入 | 灵活、无需设备 | 慢、易错，适合小批量 |
| **设备识读** | 扫码枪、读卡器、`RFID` | 快、准 | 需标签或卡片 |
| **传感器采集** | 温湿度、光敏、红外等自动上报 | 自动、连续、实时 | 需部署硬件 |
| **文件导入** | 批量导入 Excel、CSV | 效率高 | 需规范模板 |
| **网络获取** | 接口调用、网页表单、系统对接 | 跨系统共享 | 依赖对方接口与授权 |

**输入环节的两个关键要求**：

1. **准确**——通过**校验**保证（格式校验、范围校验、必填校验、逻辑校验）；
2. **规范**——编码统一（如学号规则、日期格式 `YYYY-MM-DD`），否则后续处理会出错。

### 4.处理功能：系统的"大脑"

**处理是信息系统的核心价值所在**——同样的数据，处理方式不同，产出的价值完全不同。

**处理的四种基本类型**：

| 类型 | 做什么 | 举例 |
|---|---|---|
| **计算** | 加减乘除、求平均、累计 | 计算总分、算折扣 |
| **比对判断** | 与规则或历史数据比较 | 密码是否正确、库存是否不足 |
| **分类汇总** | 按条件分组统计 | 按班级统计平均分、按品类统计销量 |
| **检索排序** | 查找与排序 | 按学号查人、按成绩排名 |

**处理的两条实现路径**：

1. **程序自动处理**——由代码按算法执行，快、准、可重复，是主流方式；
2. **人工辅助处理**——异常情况、复杂判断由人介入，系统提供提示与依据。

**性能关注点**：处理能力通常用**响应时间**与**并发处理量**衡量。像 12306 抢票、双十一秒杀，考验的就是"高并发下的处理能力"。

### 5.存储功能：系统的"记忆"

**存储解决"数据留得住、找得到、取得快"三个问题。**

**存储的三个层次**（从快到慢、从贵到便宜）：

| 层次 | 介质 | 特点 | 用途 |
|---|---|---|---|
| **内存** | 内存条 | 速度极快、断电丢失、容量小 | 程序运行时的临时数据 |
| **外存** | 硬盘、固态硬盘、U盘 | 速度较慢、断电保留、容量大 | 长期保存数据与文件 |
| **云存储** | 云端服务器 | 可远程访问、可扩容、依赖网络 | 备份、跨设备共享 |

**信息系统中的存储组织**：**数据库**是主要形式，它把数据按表结构组织，支持高效查询、并发访问与权限控制（第3单元详讲）。

**存储必须考虑的三件事**：

1. **容量**——数据会持续增长，要预留空间；
2. **备份**——防止硬件损坏、误删、勒索病毒（第4单元详讲）；
3. **安全**——敏感数据要加密存储，访问要有权限。

### 6.输出功能：结果怎么给人看

**输出的本质是"把数据翻译成人能理解、能决策的形式"。**

| 输出形式 | 说明 | 适用场景 |
|---|---|---|
| **屏幕显示** | 界面、弹窗、指示灯 | 实时查询与操作反馈 |
| **打印输出** | 报表、票据、证件 | 需要纸质凭证 |
| **文件导出** | Excel、PDF、图片 | 二次加工与存档 |
| **消息推送** | 短信、微信、邮件、APP 通知 | 主动提醒（成绩发布、缴费提醒） |
| **可视化大屏** | 图表、地图、仪表盘 | 集中监控与汇报 |
| **控制信号** | 继电器、电机指令 | 物联网系统的"动作输出" |

**输出的三条设计原则**：

1. **准确**——不能有歧义（金额、单位、时间格式必须清楚）；
2. **简洁**——一屏之内看到关键信息，不堆砌；
3. **有用**——面向使用者的决策需要，而不是"把所有数据都列出来"。

### 7.控制功能：系统的"指挥"

**控制是让前四项功能"协同成一个整体"的关键**，也是最容易被学生忽略的一项。

**控制的四个层面**：

| 层面 | 控制什么 | 举例 |
|---|---|---|
| **流程控制** | 各环节的先后顺序与触发条件 | 先校验再入库；提交后锁定不可改 |
| **权限控制** | 谁能做什么 | 学生只能查自己成绩，教务员可录入 |
| **异常控制** | 出错时怎么处理 | 网络中断重试、数据非法时提示并拒绝 |
| **审计控制** | 留下可追溯的记录 | 记录谁在什么时间改了什么 |

**控制的价值**：保证系统的**正确性、安全性与可靠性**。一个没有控制的信息系统，数据再准也会被误操作毁掉。

**闭环控制（拓展，2.5 会用到）**：

- **开环控制**：按设定执行，不检测结果（定时浇水，不管土干不干）；
- **闭环控制**：检测结果并反馈修正（土壤湿度低于阈值才浇水）。

### 8.信息系统的五类（按业务层次）

这是本小节**第二个必背考点**，五类系统的服务对象逐层升高。

| 类型 | 英文缩写 | 服务对象 | 主要任务 | 举例 |
|---|---|---|---|---|
| **事务处理系统** | TPS | **一线操作人员** | 处理日常具体业务，快而准 | 收银、订票、借还书、刷卡 |
| **管理信息系统** | MIS | **中层管理者** | 用数据支持计划、组织、控制 | 成绩管理、库存管理、人事管理 |
| **决策支持系统** | DSS | **高层决策者** | 提供分析模型与方案比较 | 销售预测、选址分析、招生计划测算 |
| **专家系统** | ES | 需要**专业经验**的场景 | 模拟专家推理给出建议 | 疾病辅助诊断、设备故障诊断 |
| **办公自动化系统** | OA | **全体办公人员** | 公文流转、协同办公、信息发布 | 请假审批、通知公告、会议安排 |

**记忆线索**：**TPS 管"事"、MIS 管"人"、DSS 管"策"、ES 管"专"、OA 管"文"**。

**层次关系（常考简答）**：

- TPS 处于**最底层**，产生原始业务数据；
- MIS 在 TPS 之上，把数据汇总成管理信息；
- DSS 在 MIS 之上，用模型辅助非结构化决策；
- **下层为上层提供数据，上层对下层提出要求**。

### 9.信息系统的特点

| 特点 | 含义 | 举例 |
|---|---|---|
| **开放性** | 能与外部系统交换数据，可扩展 | 教务系统与支付平台对接 |
| **共享性** | 数据与资源可被多用户同时使用 | 多位教师同时录入成绩 |
| **实时性** | 能在业务发生时即时响应 | 刷卡秒级扣款、抢票实时锁座 |
| **可靠性** | 长时间稳定运行、故障可恢复 | 银行系统 7×24 小时服务 |
| **交互性** | 人与系统之间有来有往 | 查询—反馈—修正 |
| **可维护性** | 易修改、易升级、易排错 | 模块化设计，功能可插拔 |
| **安全性** | 数据不被非法获取、篡改、破坏 | 加密传输、权限分级 |

**答题提醒**：特点类题目**不要只写"方便、快捷"**这类空话，要写出"**哪个特点 + 具体表现 + 带来什么价值**"。

### 10.功能分析示例：校园一卡通

**（1）功能拆解**

| 功能 | 具体实现 |
|---|---|
| **输入** | 刷卡／扫码读取卡号，食堂 POS 机输入消费金额 |
| **处理** | 查余额、判断是否足够、扣款、累计当日消费 |
| **存储** | 写入消费流水表，更新卡内余额与账户余额 |
| **输出** | POS 机显示扣款金额与余额，微信推送消费提醒 |
| **控制** | 余额不足拒绝交易；单笔限额；挂失后立即冻结 |

**（2）它属于哪类系统**

- 按范围：**局域网系统**（校内）；
- 按用途：**以事务处理（TPS）为主**，同时向管理部门提供统计报表（**兼有 MIS 功能**）。

**（3）价值分析（答"意义类"题可用）**

1. **提高效率**——替代现金，几秒完成交易；
2. **降低风险**——减少现金保管与找零差错；
3. **沉淀数据**——消费数据可用于分析就餐规律、优化档口配置；
4. **便于管理**——挂失、冻结、限额等手段保障资金安全。

### 12.课堂提示（讲课参考）

- **五项功能用"食堂刷卡"一条线讲完**：刷卡（输入）→ 查余额扣款（处理）→ 写流水（存储）→ 显示余额（输出）→ 余额不足拒绝（控制）。学生每天都在用，抽象概念立刻具体。
- **"控制"要让学生自己找**：提问"如果一卡通没有控制功能，会出现什么问题"，学生能说出"钱扣成负数""一卡多人用""丢了被人刷爆"，比教师讲四条定义更有效。
- **五类系统建议"层层盖楼"画图**：底部写 TPS（收银员），中间写 MIS（教务员），顶部写 DSS（校长），旁边挂 ES 和 OA，讲清"越往上人越少、决策越不结构化"。
- **易错点强调**：学生常把"处理"和"控制"混为一谈，也常把"输出"只理解成"打印"。可以用一个对比小题当场检测：**"系统提示'密码错误，请重试'"属于哪项功能？**（答案：控制＋输出，控制做判断、输出做提示）。
- **作业建议**：让学生任选身边一个系统（快递驿站、奶茶店点单、图书馆借阅），填"五要素 + 五功能 + 属于哪一类"三张表，下节课互评，正好为第2单元的"集成"做铺垫。
