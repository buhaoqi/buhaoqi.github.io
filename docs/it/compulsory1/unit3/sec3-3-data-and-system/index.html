3.3 数据与系统

知识点​

1.数据为什么要"管理"​

单个数据没有价值，大量数据放在一起才需要组织：怎么存、怎么找、怎么改、怎么保证不出错。

数据管理：对数据进行分类、组织、编码、存储、检索和维护的活动，是数据处理的核心。

2.数据管理技术的三个阶段（必考，按顺序背）​

阶段时间存储方式数据与程序的关系特点主要问题
人工管理阶段20 世纪 50 年代中期以前纸带、卡片、磁带，无专门软件程序与数据不可分数据不保存、不共享、无独立性数据面向特定程序，冗余极大
文件系统阶段50 年代后期 ~ 60 年代中期磁盘，有文件系统管理程序与文件有了一定分离数据可长期保存、以文件为单位管理数据冗余大、共享性差、独立性差、数据不一致
数据库系统阶段60 年代后期至今数据库，由 DBMS 统一管理程序与数据相互独立数据结构化、共享性高、冗余度低、独立性高、由 DBMS 统一控制需要专门的设计与维护

记忆线索："数据跟着程序走 → 数据跟着文件走 → 数据独立存在"。

数据库阶段的四个优势（答题落点）：

  1. 数据结构化——数据按统一模型组织，而不只是"一堆记录"；
  2. 共享性高、冗余度低——一处存储、多处使用，避免重复；
  3. 数据独立性高——数据的逻辑结构改变时，应用程序不必修改（物理独立性 + 逻辑独立性）；
  4. 由 DBMS 统一管理与控制——并发控制、完整性、安全性、故障恢复。

3.三个最容易混的概念​

概念英文含义类比
数据库DB（Database）按一定结构组织、存储在一起的、相互关联的数据集合仓库
数据库管理系统DBMS（Database Management System）管理数据库的软件，位于用户与操作系统之间仓库管理员
数据库系统DBS（Database System）数据库 + DBMS + 应用程序 + 人员 + 硬件 的完整系统仓库 + 管理员 + 业务流程 + 人 + 场地

关系（必考）：DBS 包含 DB 与 DBMS；DB 是数据本身，DBMS 是软件，DBS 是整体系统。

常见 DBMS：MySQL（开源、Web 应用最常用）、SQL Server（微软）、Oracle（大型企业）、Access（桌面小型）、SQLite（嵌入式，手机 App 常用）。

DBMS 的主要功能：

  1. 数据定义（建表、建索引）；
  2. 数据操纵（增、删、改、查）；
  3. 数据控制（安全性、完整性、并发控制、故障恢复）；
  4. 数据维护（备份、恢复、性能优化）。

4.关系模型（本小节重点）​

关系模型：用二维表来表示实体与实体之间的联系，是当今最常用的数据模型。

核心术语（表与术语一一对应）：

术语对应二维表中的什么举例（学生表）
关系一张二维表学生表
元组（记录）表中的一行张三的全部信息
属性（字段）表中的一列学号、姓名、性别、成绩
域某列的取值范围性别只能取"男／女"
主键（主关键字）能唯一标识一条记录的字段（或字段组合）学号
外键（外码）引用另一张表主键的字段，用于建立表间联系成绩表中的"学号"

主键的三个条件：

  1. 唯一——不能有两个记录的主键相同；
  2. 非空——主键不能为空值；
  3. 稳定——不轻易改动（所以"姓名"不能当主键，会重名；"身份证号"可以）。

示例：

学生表（学号为主键）

学号姓名性别班级
2026001张三男高一(1)
2026002李四女高一(1)

成绩表（学号 + 课程号 为复合主键，学号为外键）

学号课程号成绩
2026001C0192
2026002C0188

两张表的联系：通过学号（学生表的主键 = 成绩表的外键）关联，这就是**关系数据库"表间关联"**的实现方式。

关系模型的三条完整性规则（了解）：

  • 实体完整性：主键不能为空、不能重复；
  • 参照完整性：外键的值必须是另一张表中存在的主键值（或为空）；
  • 用户定义完整性：如"成绩必须在 0~100 之间"。

5.SQL：操作数据库的语言​

SQL（Structured Query Language，结构化查询语言）是关系数据库的标准操作语言，主要分四类：

类别作用主要语句
数据查询查数据SELECT
数据操纵增删改INSERT、UPDATE、DELETE
数据定义建表、改表、删表CREATE、ALTER、DROP
数据控制权限GRANT、REVOKE

（1）查询：SELECT（最重要）​

基本结构：

SELECT 字段列表
FROM 表名
WHERE 条件
ORDER BY 排序字段 [ASC|DESC];

示例：

-- 查询所有学生的学号与姓名
SELECT 学号, 姓名 FROM 学生表;

-- 查询全部字段（用 * 表示所有列）
SELECT * FROM 学生表;

-- 查询成绩大于 90 的记录
SELECT * FROM 成绩表 WHERE 成绩 > 90;

-- 按成绩降序排列
SELECT * FROM 成绩表 ORDER BY 成绩 DESC;

-- 模糊查询：姓"张"的学生（% 代表任意多个字符）
SELECT * FROM 学生表 WHERE 姓名 LIKE '张%';

-- 统计人数
SELECT COUNT(*) FROM 学生表;

-- 分组统计：每门课的平均分
SELECT 课程号, AVG(成绩) FROM 成绩表 GROUP BY 课程号;

条件运算符：= 、> 、< 、>= 、<= 、<>（不等于）、AND 、OR 、NOT、BETWEEN … AND …、IN ( … )、LIKE。

五个易错点：

  1. SQL 中"等于"是一个等号 =（不是 ==）；
  2. 字符串要用单引号 '张三'（不是双引号）；
  3. ASC 升序（默认）、DESC 降序；
  4. COUNT(*) 统计行数，COUNT(字段) 不统计该字段为空的记录；
  5. 语句以分号 ; 结束（命令行中必需）。

（2）增删改​

-- 插入一条记录
INSERT INTO 学生表 (学号, 姓名, 性别, 班级)
VALUES ('2026003', '王五', '男', '高一(2)');

-- 修改
UPDATE 成绩表 SET 成绩 = 95 WHERE 学号 = '2026001' AND 课程号 = 'C01';

-- 删除（务必带 WHERE，否则删全表！）
DELETE FROM 学生表 WHERE 学号 = '2026003';

安全提示：UPDATE 与 DELETE 不带 WHERE 会作用于全部记录，这是数据库操作最危险的一类失误。

（3）建表​

CREATE TABLE 学生表 (
    学号   CHAR(10) PRIMARY KEY,     -- 主键
    姓名   VARCHAR(20) NOT NULL,
    性别   CHAR(2),
    班级   VARCHAR(20)
);

常用数据类型：INT（整数）、CHAR(n)（定长字符）、VARCHAR(n)（变长字符）、DATE（日期）、DECIMAL（精确小数）。

6.信息系统​

（1）定义​

信息系统：由人、硬件、软件、数据和通信网络组成，能够对信息进行采集、加工、存储、传输、检索和利用，以支持组织决策与业务运行的人机系统。

（2）五大组成（必背）​

组成内容举例（校园一卡通系统）
硬件计算机、服务器、终端、网络设备、POS 机刷卡机、服务器
软件系统软件 + 应用软件一卡通管理软件、数据库
数据系统的核心资源学生信息、消费记录、余额
通信网络局域网、互联网、无线网络校园网
用户（人员）操作者、管理者、维护者学生、食堂员工、管理员

关键观念：数据是信息系统的核心，人是最活跃的因素（系统最终由人设计、使用与维护）。"三分技术、七分管理、十二分数据" 是业界常说的一句话。

（3）五项基本功能​

功能含义举例（超市收银）
输入采集并录入原始数据扫商品条码
处理计算、分类、汇总计算总价、打折
存储保存数据与结果存销售记录
输出以报表、票据、界面呈现打印小票、生成日报
控制监控与调节系统运行权限校验、库存告警

记忆："入—处—存—出—控"。

（4）常见信息系统类型​

类型功能例子
业务处理系统（TPS）处理日常事务性业务收银系统、银行存取款
管理信息系统（MIS）支持中层管理与报表教务管理、人事管理
决策支持系统（DSS）为高层决策提供分析招生计划分析、库存决策
办公自动化系统（OA）公文流转与协同办公电子公文、审批流
专家系统（ES）模拟专家经验推理疾病诊断、故障诊断

生活中的例子：教务管理系统、图书管理系统、医院挂号系统、12306 售票系统、外卖平台、导航软件。

7.数据与系统的关系（思想落点）​

  1. 数据是系统的"血液"——没有数据，系统只是空壳；
  2. 系统是数据发挥价值的"工厂"——同样的数据，在不同系统里产生不同价值；
  3. 系统的质量取决于数据的质量——GIGO（垃圾进，垃圾出）；
  4. 数据安全是系统的底线——泄露、篡改、丢失都会造成严重后果（见 3.4 加密与必修2 安全部分）。

社会影响（两面看）：

积极需警惕
提高效率、降低成本个人信息被过度采集
支撑科学决策数据垄断与"杀熟"
促进公共服务均等化系统故障导致社会运行受阻
催生新业态数字鸿沟（老年人不会用）

9.课堂提示（讲课参考）​

  • 用"班级通讯录"演三阶段：手写小本（人工）→ 每人一个 txt 文件（文件系统，同一个人的电话在三个文件里重复）→ Excel 一张表 + 查询（数据库），冗余与共享的差别学生自己就能说出。
  • 主键用"学号 vs 姓名"对比：问"班里有没有同名同姓"，学生立刻懂"姓名不能做主键"。
  • SQL 一定要上机：在 MySQL 或在线 SQL 练习平台上跑一遍 SELECT，比看语法有效十倍。
  • DELETE 不带 WHERE 的后果当场演示（在练习库上），并强调"生产环境先备份"。
  • 信息系统五组成让学生拆解"学校食堂刷卡"，从刷卡机到后台数据库全链路点一遍，比背定义扎实。
