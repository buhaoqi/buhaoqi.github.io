## 知识点

### 一、IP协议基础

### 1.IP协议在TCP/IP参考模型中处于哪一层？

IP协议是互联网层（网络层）的核心协议。

### 2.IP协议的主要作用是什么？

- 定义数据包格式：数据包头 + IP负载
- 编址：为每台设备分配IP地址
- 数据包转发：从源主机到目标主机

### 3.IP协议的特点是什么？

- 面向无连接：传递数据包之前，通信双方无需先就本次数据交换建立连接。
- 不可靠：IP数据包在传输途中可能丢失、传输无序、被人复制或延迟到达，IP本身不负责差错恢复，而是把纠错任务交给更高层协议（如TCP）。

### 4.IP数据包由哪两部分组成？

IP数据包 = IP数据包头 + IP负载

- IP数据包头：是每个 IP 数据包最前面的一段控制信息，相当于寄快递时外面贴的那张 "快递单"—— 里面写清楚这个包从哪来、到哪去、多大、走了多远、里面装的是什么。
- IP负载：是上层递交下来的数据块（如TCP段、UDP消息，也可以是ICMP数据）。

### 二、IP数据包头字段

### 5.IP数据包头中各关键字段的作用是什么？

| 字段 | 作用 |
|---|---|
| 版本 | 是 IPv4 还是 IPv6，不同版本使用不同数据包格式 |
| 首部长度 | 包头占多少字节（一般 20 字节），告诉负载从哪开始 |
| 服务类型 | 标识数据包的服务质量要求 |
| 数据包长度（总长度） | 整个包（头 + 负载）多大，最大 65535 字节 |
|标识、标志、偏移|三件套，负责包太大时分段和到目的地后重组|
| 标识（16位） | 管理分段和重组，识别一个分段属于哪个数据包 |
| 标志（3位） | 第1位保留；第2位"不分段"位（DF），置1则不分段；第3位"更多段"位（MF），置1表示后面还有段，置0表示最后一段 |
| 偏移字段（13位） | 确认一个段在原始数据包中的位置，以8字节为单位 |
| TTL(寿命) | 每经过一台路由器TTL减1，减到0则丢弃。防止数据包在网络中无限循环； |
| 上层协议 | 指明数据部分交给哪个传输层协议；值6=TCP，值17=UDP |
| 源IP地址 | 发货人地址（32 位） |
| 目的IP地址 | 收货人地址（32 位） |
| 首部检验和 | 检查包头中的位错误；将头部每两个字节当成一个数，用反码运算求和 |

### 6.IP数据包理论最大长度是多少？

理论最大长度为65535B；实际很少超过1500B，因为受限于链路MTU（如以太网链路MTU为1500B）。

### 7.TTL是什么？

- TTL = Time To Live，IP 数据包的 "寿命"（生存时间）最多中转次数
- 是 IP 数据包头里的一个字段。
- 作用：给数据包设一个 "倒计时"，防止数据包在IP网络中无休止地循环传播。
   - 一开始由**源主机**设一个初始值（常见是 64、128 或 255）
   - 每经过一台路由器，TTL减1；
   - 当TTL减为0时，该数据包必须被丢弃。

### 8.IP首部检验和的计算方法是什么？

将IP包头的每两个字节当成一个数，用反码运算对这些数求和，用于检查包头中的位错误。


### 三、IP数据包的分段与重组

### 9.MTU是什么？

- MTU = Maximum Transmission Unit 即：最大传输单元
- 一条网络链路一次能扛住(承载)的最大数据长度（单位：字节）


### 10.为什么IP数据包需要分段？

不同物理网络的链路承载能力不同（以太网≤1500B，广域网≤576B）。

当路由器从某条链路收到一个数据包，而输出端链路无法承载原数据包长度时，就将IP负载拆成多个较小的"段"，分别封装成小包发出，以适应不同链路的承载能力。

### 11.IP分段和重组在什么设备上进行？
- 分段：在路由器上进行（当 outgoing 链路MTU不足时）。
- 重组：在目的主机上进行，中间路由器不重组。因为传输层希望从网络层收到完整的未分段数据包。

### 12.目的主机如何判断哪些段属于同一个包

靠IP包头里**三个字段**配合判断，就像快递公司按面单上的"运单号+箱号+位置"把分箱包裹拼回去：


| 看哪个字段 | 判断什么 | 怎么判断 |
|---|---|---|
| **16位标识号（Identification）** | 是不是**同一单货** | 从同一个原始包拆出来的所有分段，标识号**完全相同** |
| **标志位 MF（第3位）** | 哪件是**最后一箱** | MF=0 表示"这是最后一段"；MF=1 表示"后面还有" |
| **13位偏移字段（Offset）** | 这一箱**装在原包的哪个位置** | 以8字节为单位，指出该段数据从原包的第几个字节开始 |

拼包过程（以教材例子：3000B大包拆3段）

原始包标识号 = **555**

| 段 | 负载大小 | 标识号 | 偏移字段 | MF标志 | 含义 |
|---|---|---|---|---|---|
| 第1段 | 1480B | 555 | 0 | 1（后面还有） | 从原包第0字节开始 |
| 第2段 | 1480B | 555 | 185（=1480÷8） | 1（后面还有） | 从原包第1480字节开始 |
| 第3段 | 20B | 555 | 370（=2960÷8） | 0（最后一段） | 从原包第2960字节开始 |

目的主机做三件事：

1. **收齐标识号=555的所有段** → 它们是同一单货；
2. **等到 MF=0 的那一段到达** → 说明货齐了；
3. **按偏移字段排好顺序** → 185×8=1480、370×8=2960，知道每段该放在哪个位置，拼成完整的2980B负载，再交给TCP。

为什么目的主机来重组，而不是中间路由器？

因为**只有目的主机才需要完整的包**；中间路由器拆完就扔，不需要拼回去。这样路由器可以做得简单、转发快。



### 四、IP地址基础

### 13.IP地址是什么？

- IP地址是接入互联网中每台主机（或路由器接口）的逻辑地址
- 长度32位（4字节）用点分十进制表示
- 用于在互联网上标识一台主机或路由器的网络接口


### 14.IP地址的书写格式举例


基本格式

**点分十进制：`w.x.y.z`**

- 一共 **4 段**，用英文句点 `.` 分隔（不是中文句号，也不是逗号）
- 每段 1 个字节 = **8 位二进制**
- 每段取值范围 **0 ~ 255**（即 2⁸−1）
- 拼起来就是一个 **32 位**的IP地址

```
w . x . y . z
↑   ↑   ↑   ↑
8位 8位 8位 8位
←──── 共32位 ────→
```


#### 例1：十进制 → 二进制（教材原题）

**IP地址：`192.168.3.32`**

把每一段单独转成8位二进制：

| 十进制 | 计算过程 | 8位二进制 |
|---|---|---|
| 192 | 128 + 64 | `11000000` |
| 168 | 128 + 32 + 8 | `10101000` |
| 3 | 2 + 1 | `00000011` |
| 32 | 32 | `00100000` |

合起来：

```
192 . 168 . 3 . 32
 ↓     ↓    ↓    ↓
11000000 10101000 00000011 00100000
```

---

#### 例2：二进制 → 十进制（教材原题）

**二进制地址：`11000001 00100000 11011000 00001001`**

先按8位一组切开：

```
11000001 | 00100000 | 11011000 | 00001001
```

每组算出十进制值：

| 二进制 | 计算过程 | 十进制 |
|---|---|---|
| 11000001 | 128 + 64 + 1 | **193** |
| 00100000 | 32 | **32** |
| 11011000 | 128 + 64 + 16 + 8 | **216** |
| 00001001 | 8 + 1 | **9** |

点分十进制写法：

```
193.32.216.9
```


#### 例3：私有地址 `10.0.0.1`

```
10 .  0  .  0  .  1
 ↓    ↓    ↓    ↓
00001010 00000000 00000000 00000001
```

#### 例4：有限广播地址 `255.255.255.255`

```
255 . 255 . 255 . 255
 ↓     ↓     ↓     ↓
11111111 11111111 11111111 11111111
```

（32位全1，就是广播地址）

---

#### 容易写错的反面例子 ❌

| 写法 | 错在哪 |
|---|---|
| `192,168,3,32` | 用了逗号，必须用英文句点 |
| `192.168.3.256` | 256超过0~255范围，每段最大255 |
| `192.168.3` | 只有3段，必须是4段 |
| `192．168．3．32` | 用了中文句号，必须是英文句点 `.` |
| `192.168.03.32` | 一般不写前导零 |


### 15.32位IP地址共有多少个可能的地址？
共有2³² ≈ 40亿个（约42.9亿）不同的IP地址。


### 五、IP地址结构与编址规则

### 16.IP地址的结构是什么

> **一个32位IP地址被切成两截：前面一截表示"在哪个网络"（网络号），后面一截表示"这网络里的第几台机器"（主机号）。**

```
┌──────────────────────────────────────────┐
│            32 位 IP地址                  │
├─────────────────────┬────────────────────┤
│    网络号（网络ID）   │   主机号（主机ID）   │
│   （在哪个子网）      │  （子网里第几台机） │
└─────────────────────┴────────────────────┘
```
某台主机IP = **192.168.7.32**，拆开来：

```
192 . 168 . 7 . 32
└──────┬──────┘ └┬┘
   网络ID=       主机ID=
 192.168.7.0      32
```

意思是：**这台机器在192.168.7.0这个子网里，是编号32的那台。**


#### 为什么要分这两截？

路由器转发数据包时只看**网络ID**：

```
目的IP = 192.168.7.32
          ↓
   提取网络ID = 192.168.7.0
          ↓
   查路由表：192.168.7.0 往左边那条线走
          ↓
   把包发到左边子网后，再靠主机ID=32找到具体那台机器
```

### 17.分配网络ID的两条规矩

1. **网络ID在整个IP网络中必须唯一**——不能两个子网撞号；
2. **网络ID不能以0或127开头**——0代表"本网络"，127是回送测试地址，都留用了。

### 18.分配主机ID的两条规矩

1. **主机ID在同一个子网内必须唯一**——同一个网里不能两台机器同号；
2. **主机ID不能全0，也不能全1**：
   - 全0 = **代表这个子网本身**（如192.168.7.0），不分配给具体主机；
   - 全1 = **子网广播地址**（如192.168.7.255），用来给子网里所有机器发广播。

### 六、IP地址分类（A/B/C/D/E）

# IP地址分类一览表

| 类别 | 最高位特征 | 首字节范围 | 网络ID位数 | 主机ID位数 | 可用网络数 | 每个网络可用主机数 | 用途 |
|---|---|---|---|---|---|---|---|
| **A类** | 最高位 = `0` | **1 ~ 126** | 8位（实际7位） | 24位 | 2⁷−2 = **126** | 2²⁴−2 = **16 777 214** | 大型网络 |
| **B类** | 高2位 = `10` | **128 ~ 191** | 16位（实际14位） | 16位 | 2¹⁴ = **16 384** | 2¹⁶−2 = **65 534** | 中型/大型网络 |
| **C类** | 高3位 = `110` | **192 ~ 223** | 24位（实际21位） | 8位 | 2²¹ = **2 097 152** | 2⁸−2 = **254** | 小型网络 |
| **D类** | 高4位 = `1110` | **224 ~ 239** | — | — | — | — | 多播（组播）地址 |
| **E类** | 高4位 = `1111` | **240 ~ 255** | — | — | — | — | 试验性用途（保留） |



#### 速判口诀（看第一个字节就知道类别）

```
1 ──────── 126 │ A类（头一位是 0）
128 ────── 191 │ B类（头两位是 10）
192 ────── 223 │ C类（头三位是 110）
224 ────── 239 │ D类（组播，头四位是 1110）
240 ────── 255 │ E类（保留，头四位是 1111）
```

#### 为什么都要"减2"？

> 因为**主机ID全0**代表"本子网本身"，**主机ID全1**代表"本子网广播"——这两个不能分配给具体主机，所以可用主机数要 **−2**。
> A类网络数减2是因为 `0000000`（0）和 `1111111`（127）被保留了。

#### 举例判断

| IP地址 | 第一个字节 | 类别 |
|---|---|---|
| `10.0.0.1` | 10（1~126） | **A类** |
| `172.16.5.20` | 172（128~191） | **B类** |
| `192.168.1.100` | 192（192~223） | **C类** |
| `224.0.0.1` | 224（224~239） | **D类（组播）** |
| `250.10.20.30` | 250（240~255） | **E类（保留）** |
