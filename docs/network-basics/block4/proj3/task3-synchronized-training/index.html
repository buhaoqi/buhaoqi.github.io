3.问答题参考答案​

1. 描述 TCP/IP 模型。

TCP/IP 参考模型把网络通信功能分为 4 个层次，从上到下依次为：应用层、传输层、互联网层、网络接口层。

层次数据单位核心内容
应用层报文合并了 OSI 会话层与表示层的功能，为应用程序提供网络服务接口，含 HTTP、FTP、DNS、SMTP 等协议
传输层数据段为应用进程提供端到端通信，含 TCP（可靠面向连接）与 UDP（不可靠无连接）
互联网层数据包负责编址、路由与分组转发，实现异构网互联，含 IP、ARP、RARP、ICMP、IGMP
网络接口层帧/比特对应 OSI 的数据链路层与物理层，负责在具体链路上收发数据帧

其特点是：先有协议、后有模型，与底层网络技术无关，扩展性好，是事实上的工业标准。

2. TCP/IP 模型分为几层？各层的功能是什么？每层包含什么协议？

分为 4 层。

层次功能主要协议
应用层为用户应用程序提供网络服务，定义应用间交换数据的规则；合并会话层和表示层功能HTTP、FTP、SMTP、DNS、DHCP、Telnet、SNMP、RIP、POP3、IMAP
传输层为应用层提供会话和数据报通信服务，实现端到端（进程到进程）的数据传输与流量控制TCP、UDP
互联网层定义数据包格式与编址规则，完成寻址、路由选择、分组转发和拥塞控制，实现异构网互联IP、ARP、RARP、ICMP、IGMP（IPv6 为 IPv6、ICMPv6、NDP、MLD）
网络接口层为 IP 模块发送和接收数据，为 ARP/RARP 发送请求和接收应答；解决封装成帧、透明传输、差错检测以太网、无线局域网、帧中继、ATM 等链路层协议

3. 简述 OSI 参考模型与 TCP/IP 参考模型的异同点。

相同点：

  1. 都采用分层的体系结构，将复杂的通信问题分解
  2. 都基于协议栈的概念，各层通过接口向上提供服务
  3. 都有网络层（互联网层） 负责寻址与路由、传输层负责端到端通信
  4. 目的相同：实现异构系统之间的互联互通

不同点：

比较项OSITCP/IP
层数7 层4 层
制定背景ISO 制定的国际标准，理论先导由 ARPANET 实践发展而来，事实标准
会话层、表示层独立两层并入应用层
数据链路层、物理层独立两层合并为网络接口层
通用性通用性强，但体系复杂、实现困难实用性强，与具体网络技术无关，应用广泛
服务/接口/协议三者定义清晰、区分严格未严格区分服务、接口与协议

4. TCP 协议与 UDP 协议各有什么特点？它们之间有什么区别和联系？

TCP 的特点：面向连接；提供可靠的、有序的、无差错的数据传输（排序、确认、重传）；面向字节流；有流量控制（滑动窗口）与拥塞控制；一对一通信；首部 20 字节，开销大。

UDP 的特点：无连接；不可靠（不保证到达、不保证顺序、不重传）；面向报文（不拆分不合并）；无流量控制；可一对一、一对多；首部仅 8 字节，开销小、速度快。

区别：

比较项TCPUDP
连接面向连接（三次握手，四次挥手）无连接
可靠性可靠不可靠
数据形式字节流报文
首部20 字节8 字节
流量控制有无
适用文件传输、Web、电子邮件视频会议、聊天、流媒体、DNS、DHCP、RIP

联系：

  1. 两者都工作在传输层，都建立在 IP 协议之上，都通过端口号标识进程
  2. 都为应用层提供服务，应用可根据对可靠性与实时性的不同需求选择
  3. 两者可以共存于同一主机，由 IP 首部的协议字段（6 表示 TCP，17 表示 UDP）区分

5. 简述 DNS 协议的工作过程。

  1. 用户在浏览器中输入域名（如 www.qq.com），操作系统先检查本地 DNS 缓存中是否有映射，有则直接完成解析
  2. 若缓存没有，则查本机 hosts 文件，有则完成解析
  3. 若都没有，则向 TCP/IP 参数中设置的首选 DNS 服务器（本地 DNS 服务器） 发起查询；该服务器若在其 DNS 数据库中有记录，直接返回结果
  4. 若数据库中没有，但服务器已缓存过该映射，则调用缓存完成解析
  5. 若仍失败，则按设置决定查询方式：
    • 未启用转发：本地 DNS 向 13 台根 DNS 服务器发问，根服务器返回负责该顶级域（如 .com） 的服务器地址；本地 DNS 再逐级查询 .com → qq.com，直至找到目标主机的 IP（迭代查询）
    • 启用转发：把请求转发给上一级 DNS 服务器，由其解析；不行再向上级或根服务器转发（递归查询）
  6. 最终结果逐级返回到本地 DNS 服务器，再由它返回给客户机，浏览器用得到的 IP 地址与 Web 服务器建立 TCP 连接

6. IPv4 中的地址有几种类型？它们是怎样分类的？判断下列地址属于哪类 IP 地址？

IPv4 地址分为 5 类（A、B、C、D、E），按第一个字节的取值范围（即地址的高位特征）分类：

类别首字节范围高位特征网络 ID / 主机 ID用途
A 类1~126最高位为 01 字节 / 3 字节大型网络
B 类128~191前两位为 102 字节 / 2 字节中型网络
C 类192~223前三位为 1103 字节 / 1 字节小型网络
D 类224~239前四位为 1110—多播（组播） 地址
E 类240~255前四位为 1111—试验性用途

判断结果：

（2）133.12.6.50133（128~191）B 类
（3）192.168.1.1192（192~223）C 类（且为私有地址）
（4）233.2.5.9233（224~239）D 类（多播地址）

7. 在 IPv4 中，什么是子网掩码？子网掩码的作用是什么？

定义：子网掩码是一个 32 位的二进制数，其中与 网络 ID 对应的位全部置 1，与主机 ID 对应的位全部置 0；通常用点分十进制表示，如 255.255.255.0，也可写为 /24。

作用：

  1. 区分网络 ID 与主机 ID：通过与运算求出 IP 地址的网络 ID（子网地址），从而判断该地址属于哪个网络
  2. 判断两台主机是否在同一子网：将两主机 IP 分别与掩码相与，结果相同则在同一子网，可直接通信；不同则需经网关转发
  3. 支持子网划分：从主机位借位作为子网号，形成"网络 ID + 子网 ID + 主机 ID"三级结构，提高地址利用率并便于管理
  4. 求主机地址范围与广播地址（主机位全 0 为网络地址，全 1 为广播地址）

地址数量约 40 亿个约 3.4×10 的 38 次方个

首部固定 20 字节，含检验和、标识、标志、偏移基本头部固定 40 字节，取消检验和，可选字段移入扩展头部
分片路由器可分片由源节点分片，路由器不再分片
地址配置手工或 DHCP支持无状态自动配置（链路本地地址自动生成）
安全性需额外 IPsec内置认证与机密处理
广播有广播地址取消广播，改用组播
地址类型单播、广播、组播单播、组播、任意播

9. IPv6 的地址是如何分类的，每类地址有什么特征？

IPv6 地址分为单播、组播、任意播三类：

类型特征
单播标识单一接口，发往单播地址的数据包只送到一个接口。包括：全球单播地址（前 3 位 001，全球可路由）、链路本地地址（FE80::/10，同一链路内通信、自动配置与邻居发现，路由器不转发）、本地站点地址（FEC0::/10，相当于 IPv4 私网地址，可跨路由器但不能在互联网使用）、唯一本地地址（FC00::/7，常用 FD00::/8）、其他单播地址（:: 未指定、::1 回送、::w.x.y.z 兼容 IPv4、::FFFF:w.x.y.z IPv4 映射）
组播（多播）标识一组接口，发往组播地址的数据包送到多个接口。以 FF00::/8 开始，结构为：8 位前缀 + 4 位标志（0 为 IANA 固定分配、1 为临时）+ 4 位范围（1 本地接口、2 本地链路、5 本地专用）+ 112 位组 ID
任意播标识一组接口（一般属于不同节点），发往任意播地址的数据包只送到路由距离最近的那个接口。格式与单播相同、无法从地址本身区分；由路由协议定义，不能手工配置；只能用作目的地址，不能作为源地址

补充：IPv6 中取消了广播地址，原来广播的功能由组播实现。
