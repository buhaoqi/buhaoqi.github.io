## 知识点

### 1.任务描述：诊断靠什么

**教材原句**：网络诊断可以使用包括**局域网或广域网分析仪**在内的多种工具，如**路由器诊断命令、网络管理工具和其他故障诊断工具**。

**教材给出的四条思路**：

1. 一般情况下，**查看路由表**可以**初步判断**网络故障发生的位置；
2. **ICMP 协议**支持的 **Ping、Tracert** 命令是**获取故障信息**的网络工具；
3. 可以使用**一个或多个命令**收集、验证相应的信息；
4. 根据网络故障的**具体情况**，选择**恰当的命令**获取所需信息，并根据信息**分析、查找出一个或多个故障原因**。

**本任务内容**：介绍网络故障的**分类**及**分层诊断**方法。

### 2.网络故障通常有哪几种可能（按层次）

**教材原句**：网络故障通常有以下几种可能：

| 层次 | 可能的原因 |
|---|---|
| **物理层** | **物理设备相互连接失败**，或者**硬件及线路本身**的问题 |
| **数据链路层** | **网络设备的接口配置**问题 |
| **网络层** | **网络协议配置或操作错误** |
| **传输层** | **协议性能**或**通信拥塞**问题 |
| **上三层 / 应用** | **网络应用程序错误** |

**这五种可能正好对应"从下往上"的顺序**，为下面的分层诊断做了铺垫。

### 3.分层诊断的总原则（必考）

**教材原句**：网络故障的诊断过程应该**沿着 OSI 七层模型从物理层开始向上进行**，首先检查**物理层**，然后检查**数据链路层**，以此类推，设法**确定通信失败的故障点**，直到**系统通信正常**为止。

**为什么必须"从下往上"**：

- 下层是上层的基础——**物理层不通，上面六层再正确也没用**；
- 下层故障会**伪装**成上层故障（网线没插，浏览器当然打不开网页）；
- 从下往上查，每层都能**排除**一批可能，**收敛**最快。

**口诀**：**先看灯（物理）→ 再看口（链路）→ 再查址（网络）→ 最后查应用**。

### 4.网络故障的分类（两组划分，别混）

**教材原句**：根据网络故障的**性质**把网络故障分为**物理故障与逻辑故障**；也可以根据网络故障的**对象**把网络故障分为**线路故障、路由故障和主机故障**。

| 划分依据 | 类别 |
|---|---|
| 按**性质** | **物理故障、逻辑故障** |
| 按**对象** | **线路故障、路由故障、主机故障** |

**注意**：这是**两套独立的分法**，同一台故障设备既可以按性质叫"逻辑故障"，也可以按对象叫"路由故障"。

#### （1）物理故障与逻辑故障

| 类别 | 定义（教材原句） | 典型表现 |
|---|---|---|
| **物理故障** | 指**设备或线路损坏、插头松动、线路受到严重电磁干扰**等情况 | 网线断、水晶头松、交换机电源坏、强电干扰 |
| **逻辑故障** | **最常见的情况就是配置错误**，指因为**网络设备的配置原因**而导致的网络异常或故障 | 路由器**端口参数设置**有误；路由器**路由配置错误**以致**路由循环或找不到远端地址**；**路由掩码设置错误**；操作系统中安装的**通信协议受损**；**防病毒软件对某协议的屏蔽** |

**判别的关键**：**看得见摸得着的（线、口、电）→ 物理；配出来的（参数、路由、掩码、协议）→ 逻辑**。

#### （2）线路故障、路由故障和主机故障

| 类别 | 说明 | 排查方法（教材原句） |
|---|---|---|
| **线路故障** | **最常见的情况就是线路不通** | ① 首先检查该线路上**是否还有网络流量**；② 然后用 **Ping** 命令检查**线路远端的路由器端口能否响应**；③ 用 **Traceroute** 命令检查**路由器配置是否正确**，找出问题依次解决 |
| **路由故障** | 线路故障中很多情况都**涉及路由器**，因此也可以把一些线路故障**归结为路由器故障** | 检测路由器故障需要利用 **MIB 浏览器**，通过它收集路由器的**路由表、端口流量数据、计费数据、路由器 CPU 的温度、负载以及内存使用情况和余量**等数据。通常情况下网络管理系统有**专门的管理进程**不断检测路由器的**关键数据**，并及时向管理员**报警** |
| **主机故障** | **主机中与网络相关的软、硬件**出现了问题 | 可能原因：**网络协议不能正常运行**、**参数配置不当**、**硬件损坏或连接不正常**等 |

**记忆线索**：**线（通不通）→ 路（怎么走）→ 机（自己有没有病）**。

### 5.网络故障的分层诊断（重点，四层方法）

#### （1）物理层及诊断

- **地位**：物理层是 **OSI 分层结构体系中最基础的一层**，它建立在**通信媒体**的基础上，实现**系统和通信媒体的物理接口**，为数据链路各实体之间进行**透明传输**，对**建立、保持和拆除**计算机及网络之间的**物理连接**提供服务。
- **故障主要表现**：设备的**物理连接方式**是否恰当、**连接电缆**是否正确。
- **具体方法（考点）**：对于网络中经常使用的**路由器**来说，确定路由器**端口物理连接是否完好**的**最佳方法是运行 `show interface` 命令**，检查每个端口的**状态**，解释屏幕输出信息，查看**端口状态、协议建立状态和 EIA 状态**。

**为什么是 `show interface`**：它能同时给出**物理层状态（up/down）**与**协议状态（line protocol up/down）**，一眼分清是"**线没通**"还是"**线通了但协议没起来**"。

#### （2）数据链路层及诊断

- **主要任务**：使**网络层无需了解物理层的特征**而获得**可靠的传输**。
- **具体工作**：对通过物理层的数据进行**封装和拆封装**、**差错检测和一定的校正操作**，并**协调共享介质**。
- **诊断方法**：查找和排除数据链路层的故障，可以通过**查看主机或路由器的路由表**来进行**综合判断**。

**典型链路层问题**：接口未 **no shutdown**、**封装类型不一致**（如 PPP 与 HDLC）、**VLAN/Trunk 配置不一致**、**MAC 地址冲突**、**MTU 不匹配**。

#### （3）网络层及诊断

- **提供的功能**：**建立、保持和释放**网络层连接的手段，包括**路由选择、流量控制、传输确认、中断、差错及故障恢复**等。
- **基本方法（教材原句）**：排除网络层故障的基本方法是**沿着从源到目标的路径**，查看**相关主机和路由器的路由表**，同时**检查路由器接口的 IP 地址**。
- **关键判断**：如果**路由没有在路由表中出现**，应该通过检查来确定是否已经输入了恰当的**静态路由、默认路由或动态路由**，然后通过**手工配置丢失的路由**来排除故障。

**网络层三查**：**一查路由表有没有这条路 → 二查接口 IP 对不对 → 三查下一跳通不通**。

#### （4）其他层的故障诊断

- **原则（教材原句）**：除上述三层外，其他层都是**由协议、软件实现**其功能的层次，诊断其故障的主要手段是**验证各个层的协议是否可以正常运行**。
- **教材案例（非常经典，务必会讲）**：

**故障现象**：**QQ 即时通讯软件运行正常，但不能浏览网页**。

**分析过程**：

| 步骤 | 内容 |
|---|---|
| ① 看 QQ 用什么 | 即时通信软件在**传输层使用的是 UDP 协议** |
| ② 看网页用什么 | 浏览网页在**应用层是 HTTP 协议**，它在**传输层对应的是 TCP 协议** |
| ③ 得出初步判断 | 应该是 **TCP 协议（或其相关的协议）工作不正常** |
| ④ 进一步验证 | 通过运行 **TCP 协议支持的其他应用层协议**，判断 TCP 协议是否正常 |
| ⑤ 收敛 | 这样**逐渐逼近故障位置**，直到最终排除故障 |

**这个案例的教学价值**：它示范了"**用能通的应用反推不通的协议**"这一诊断思路——**UDP 通、TCP 不通 → 问题在 TCP 层，不在物理层、不在 DNS**。

**四层诊断方法一表汇总**：

| 层次 | 主要排查对象 | 关键命令/手段 | 判断依据 |
|---|---|---|---|
| **物理层** | 连接方式、电缆、端口 | **`show interface`** | 端口状态、协议建立状态、EIA 状态 |
| **数据链路层** | 封装、差错、共享介质 | 查看**主机或路由器的路由表** | 综合判断链路是否正常 |
| **网络层** | 路由、接口 IP | 查**路由表 + 接口 IP 地址** | 路由是否出现、下一跳是否可达 |
| **其他层（传输层及以上）** | 协议、应用程序 | **验证各层协议能否正常运行** | 用同类协议交叉验证 |
