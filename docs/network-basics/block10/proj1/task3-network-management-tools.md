## 知识点

### 1.任务描述：为什么要用工具

**教材原句**：随着网络规模的不断扩大及网络应用的不断发展，所使用的网络设备的**数量和种类也越来越多**。为了满足网络管理的要求，**可网管网络设备**开始在网络中使用，使用可网管网络设备能够使**网络功能发挥到最大**，并**最大限度地保证网络的安全**。

**网络管理工具（或软件）的定义**：协助网络管理人员对网络进行**监视和控制**以及**维护网络运行**的**硬件和软件设施**。

**本任务内容**：介绍一些实际网络管理中**常见的网络管理工具**。

### 2.四大类工具全景（先建框架）

| 类别 | 干什么 | 典型工具 |
|---|---|---|
| **1. IP 和链路工具** | 判断**逻辑链路**是否畅通、验证配置 | arp、ipconfig、ping、netstat、nslookup、hostname、telnet、pathping、tracert、Netdiag |
| **2. 网络分析和诊断工具** | **抓包分析**、测吞吐率、测带宽、分析流量、算子网 | Sniffer Pro、Qcheck、Ping Plotter、IxChariot、Commview、MRTG、IPSubnetter |
| **3. 网络设备管理工具** | **远程登录**设备做配置、备份与升级 | Telnet、超级终端、TFTP、CNA、Cisco Works 2000、ITiMe、ManageEngine |
| **4. 网络维护和恢复工具** | 日常维护、系统重装、备份恢复 | net、at、NEWT Professional、LANView、组策略命令族、ntbackup、recover、USMT、regback |

**一句记忆**：**一类"测通不通"、二类"看数据"、三类"配设备"、四类"护系统"**。

### 3.IP 和链路工具：两类工具别混

**教材原句**：IP 协议和 IP 链路工具不仅经常被用于处理网络的**连通性问题**，而且还被广泛应用于**网络安全故障的诊断与排除**。

| 工具类型 | 判断什么 | 举例 |
|---|---|---|
| **硬件测试工具**（网络测试仪等） | 主要用于判断**物理链路**是否畅通 | 网线测试仪、网络测试仪 |
| **IP 链路测试工具**（软件命令） | 用于测试 **IP 链路**是否正常：**交换机、路由器等网络设备的连接、配置是否正确**，**网卡和网络协议是否正确安装**，**计算机的 IP 地址信息设置是否正确**等——即判断**网络逻辑链路**是否畅通 | ping、tracert、ipconfig 等 |

**一句话区分**：**硬件测"线通不通"，软件测"逻辑通不通"**。

**TCP/IP 提供的一组诊断和管理命令能干什么**：

- 帮助用户得到 **IP 和域名**的信息；
- 帮助用户检测 **Internet 的性能**；
- **跟踪并解决 TCP/IP 网络故障**。

**教材特别说明（易忽略）**：需要注意的是，在**不同的 Windows 版本**下，调试命令**是否存在、使用格式可能有所不同**，可通过 **Help 命令**进行查询。下面介绍的 TCP/IP 实用命令**均在 DOS 窗口中以命令行方式使用**。

### 4.常用 TCP/IP 命令总览表

| 命令 | 主要作用 | 最常用写法 |
|---|---|---|
| **arp** | 显示、删除、添加 **IP 地址与 MAC 地址**的对应表项 | `arp -a`、`arp -d *`、`arp -s IP MAC` |
| **ipconfig** | 显示本机**网络适配器**的物理地址和 IP 地址等配置信息 | `ipconfig`、`ipconfig /all`、`ipconfig /release`、`ipconfig /renew` |
| **ping** | 测试与目标主机**能否成功交换数据包** | `ping 目标`、`ping -t 目标` |
| **netstat** | 显示 **IP、TCP、UDP、ICMP** 相关的统计数据与端口连接情况 | `netstat -a`、`netstat -n`、`netstat -r` |
| **nslookup** | 显示与 **DNS** 有关的参数信息，排查 DNS 故障 | `nslookup 域名`、`nslookup IP` |
| **hostname** | 显示计算机在当前域中的**主机名** | `hostname` |
| **telnet** | 测试指定主机的**指定端口**是否可用 | `telnet 域名 端口` |
| **pathping** | 显示**中间跃点**处的**网络滞后和网络丢失**信息 | `pathping -n 目标` |
| **tracert** | **跟踪路由**，确定数据报访问目标所采取的**路径** | `tracert -d 目标` |
| **Netdiag** | Windows 支持工具中的**网络故障原因诊断**工具 | `netdiag` |

### 5.arp 命令

**原理**：**arp 协议完成了 IP 地址到 MAC 地址的转换**。为了提高效率，主机在完成转换后，会把 **IP 地址及相应的 MAC 地址放入 arp 缓存**中。**arp 命令就是对缓存中的 IP 地址和 MAC 地址对进行显示、删除、添加等操作**。

**命令格式举例**：

```text
arp -a [inet_addr] [-N if_addr] [-v]
arp -d inet_addr [if_addr]
arp -s inet_addr eth_addr [if_addr]
```

**参数说明**：

| 参数 | 含义 |
|---|---|
| **-a** | 通过询问当前协议数据，**显示当前 arp 项**。如果指定了 inet_addr，则**只显示指定计算机**的 IP 地址和物理地址。如果不止一个网络接口使用 arp，则**显示每个 arp 表的项** |
| **-v** | 在**详细模式**下显示当前 arp 项。所有**无效项**和**环回接口**上的项都将显示 |
| **inet_addr** | 指定 **Internet 地址** |
| **-N if_addr** | 显示 **if_addr** 指定的**网络接口**的 arp 项 |
| **-d** | **删除** inet_addr 指定的主机。inet_addr 可以是**通配符 \***，以**删除所有主机** |
| **-s** | **添加**主机，并把 Internet 地址 inet_addr 与物理地址 eth_addr **相关联**。物理地址是用**连字符分隔的 6 个十六进制字节**；该项是**永久的** |
| **eth_addr** | 指定**物理地址** |
| **if_addr** | 如果存在，指定**地址转换表应修改的接口**的 Internet 地址；不存在则使用**第一个适用的接口** |

**三个示例（教材原例）**：

| 输入 | 效果 |
|---|---|
| `arp -a` | 显示当前的 **IP 地址与 MAC 地址对应表** |
| `arp -d *` | 删除当前 IP 地址与 MAC 地址对应表的**所有表项** |
| `arp -s 111.55.85.212 00-aa-00-62-c6-09` | **添加** IP 地址与 MAC 地址的对应关系 |

**考点**：`arp -s` 添加的是**静态（永久）表项**；`arp -d` 支持通配符 **\***。

### 6.ipconfig 命令

**定义**：**内置**于 Windows 的 TCP/IP 应用程序，用于**显示本地计算机网络适配器的物理地址和 IP 地址等配置信息**。这些信息一般用来**检验 TCP/IP 设置是否正确**。

**还能做什么**：当在网络中使用 **DHCP** 服务时，ipconfig 可以**检测计算机中分配到的 IP 地址是否配置正确**，并且可以**释放、重新获取 IP 地址**——这些信息对网络测试和故障排除有重要作用。

#### （1）查看网络适配器信息

**命令格式**：`ipconfig`

- 运行**不带参数**的 ipconfig，可检测本地**所有网络连接**的 IP 地址配置信息：**IP 地址（IP Address）、子网掩码（Subnet Mask）、默认网关（Default Gateway）**，同时也包括 **ADSL 信息**，使用户了解 ADSL 租用了哪个 IP 地址。
- 有时网管员需要得到**网卡的 MAC 地址**，用于 **MAC 地址绑定、远程管理**等，可用 **`ipconfig /all`** 实现：
  - 其中 **Physical Address** 部分就是由"**-**"分隔的 **6 组 16 进制数**表示的 **MAC 地址**；
  - 同时显示该网卡的**其他信息**：网卡类型描述（Description）、是否启用了 DHCP（Dhcp Enabled）以及 IP 地址配置信息等；
  - 在 **Windows IP Configuration** 区域中，显示**主机名（Host Name）、主 DNS 后缀（Primary Dns Suffix）、节点类型（Node Type）、是否开启了 IP 路由（IP Routing Enabled）、是否开启了 WINS 代理（WINS Proxy Enabled）**等。

#### （2）显示所有网络参数

**命令格式**：`ipconfig /all`

显示本机**每一个 IP 网络接口**的信息：**DNS 域名、DNS 服务器的 IP 地址、网卡物理地址、网络接口的 IP 地址以及 DHCP** 等信息。

#### （3）释放原 IP 地址，重新获取 IP 地址

**命令格式**：

```text
ipconfig /release
ipconfig /renew
```

**适用场景（教材原句）**：

- 如果网络中使用了 **DHCP** 服务，客户端计算机就可以**自动获得 IP 地址**；
- 但有时因 **DHCP 服务器或网络故障**等原因，一些客户端计算机不能正常获得 IP 地址，此时系统会**自动为网卡分配一个形如 169.254.x.x 的 IP 地址**；
- 或者有些计算机 IP 地址的**租约到期**，需要**更新或重新获得** IP 地址。

**做法**：先用 `ipconfig /release` **释放**原来的 IP 地址，再用 `ipconfig /renew` **重新获得**一个新的 IP 地址。

**考点提示**：看到 **169.254.x.x** 就应想到"**没有从 DHCP 拿到地址**"，这是 APIPA 自动私有地址，只能与本网段通信、**不能上网**。

### 7.ping 命令（最常用，必掌握）

**主要功能**：确定本地主机是否**能与另一台主机成功交换（发送与接收）数据包**。它根据返回的信息，就可以**推断 TCP/IP 参数是否设置正确、运行是否正常和网络是否通畅**等。

**命令格式**：

```text
ping [-t] [-a] [-n count] [-l size] [-f] [-i TTL] [-v TOS] [-r count] [-s count]
     [-j host-list] [-k host-list] [-w timeout] [-R] [-S srcaddr] [-4] [-6] target_name
```

**参数说明（教材全表）**：

| 参数 | 含义 |
|---|---|
| **-t** | Ping 指定的主机，**直到停止**；若要查看统计信息并继续操作，请键入 **Control-Break**；若要停止，请键入 **Control-C** |
| **-a** | 将**地址解析成主机名** |
| **-n count** | 要发送的**回显请求数** |
| **-l size** | 发送**缓冲区大小** |
| **-f** | 在数据包中设置"**不分段**"标志（仅适用于 IPv4） |
| **-i TTL** | **生存时间**（TTL） |
| **-v TOS** | **服务类型**（仅适用于 IPv4）；该设置已不赞成使用，且对 IP 标头中的服务字段类型**没有任何影响** |
| **-r count** | **记录计数跃点**的路由（仅适用于 IPv4） |
| **-s count** | **计数跃点的时间戳**（仅适用于 IPv4） |
| **-j host-list** | 与主机列表一起的**松散源路由**（仅适用于 IPv4） |
| **-k host-list** | 与主机列表一起的**严格源路由**（仅适用于 IPv4） |
| **-w timeout** | 等待每次回复的**超时时间（毫秒）** |
| **-R** | 同样使用路由标头测试**反向路由**（仅适用于 IPv6） |
| **-S srcaddr** | 要使用的**源地址** |
| **-4** | 强制使用 **IPv4**，为**默认值** |
| **-6** | 强制使用 **IPv6** |

**工作原理**：Ping 命令在执行过程中，通过将 **ICMP 数据包**发送到目标计算机并**侦听应答数据包**来验证与目标计算机的连接。**每个发送的数据包最多等待一秒**，显示已传输和接收的数据包数。

**默认行为（必记）**：默认情况下，传输**四个包含 32 个字节的 ICMP 数据包**；Ping 能以**毫秒**为单位显示**发送请求到返回应答之间的时间量**。

**从结果看什么**：

| 现象 | 说明 |
|---|---|
| **应答时间短** | 数据报**不必通过太多路由器或网络**，连接速度比较快 |
| **TTL 值** | 可以通过 TTL 值**推算数据包经过了多少个路由器** |
| **4 条消息** | 目标主机**当前在线并可以访问**，也表示 **DNS 工作正常** |

**教材实例**：在 DOS 窗口命令行输入 `ping www.sohu.com`，如果收到如图 10-1 所示的 **4 条消息**，既说明目标主机**当前在线并可以访问**，也表示 **DNS 工作正常**。

**重要提醒（教材原句）**：

- **Ping 成功并不一定就代表 TCP/IP 配置正确**——有可能还要执行大量的本地主机与远程主机的数据包交换，才能确保 TCP/IP 配置的正确性；
- 如果执行 **Ping 成功而网络仍无法使用**，那问题很可能出在**网络系统的软件配置**方面——**Ping 成功只保证当前主机与目标主机间存在一条连通的物理路径**。

#### ping 的三大测试场景

**① 测试网卡**

- 使用 `ping 本地IP地址` 或 `ping 127.0.0.1` 进行测试。
- **是否安装了网卡**：成功说明**网卡没有问题**；不成功说明**网卡驱动程序或 TCP/IP 没有正常安装**。可在"控制面板 → 设备管理器 → 网络适配器"中查看网卡是否有一个**黄色的"!"**，如有需**重新安装驱动程序**。
- **是否安装了 TCP/IP**：成功说明网卡 TCP/IP 没有问题；不成功且网卡驱动正常，则应从"控制面板 → 网络连接"查看是否安装了 TCP/IP；如未安装，安装并正确配置后**重启计算机**再次测试。
- **是否配置了 IP 地址和子网掩码**：如果 `ping 127.0.0.1` 成功、但 **ping 本地 IP 地址不成功**，说明**没有正确配置 IP 地址**，应在"本地连接"属性中检查并重新配置。

**② 测试局域网连接**

- 通过 Ping 局域网内其他计算机、服务器的**计算机名或 IP 地址**，可测试**同一网络（或 VLAN）**的连接是否正常，检测 **IP 地址和子网掩码**设置是否正确。
- Ping 不通时：先查 IP 地址与子网掩码；若设置成功仍不通，应对**网络设备和通信介质逐段测试、检查和排除**。

**③ 测试与远程主机的连接**

- 通过 Ping 远程主机的 **IP 地址或域名**，判断网络中的故障，确认**能否连接 Internet**。
- **不能浏览网页时先 Ping 网站域名**：
  - **能 Ping 通** → 计算机与 Internet 连接正常，需检查**本地 DNS 或系统故障**；
  - **不能 Ping 通** → 可能是**对方网站没有运行**，或本地计算机**根本不能连接 Internet**，需检查**本地网关或服务器故障**，确认 **DNS 服务器设置**是否正常；
  - **能 Ping 通 Internet 上的 IP 地址但打不开网页** → 可能是 **DNS 服务器设置有问题**，需 Ping 本地 DNS 服务器并在属性中检查 DNS 设置；
  - **与任何主机连接都超时或丢包率非常高** → 应与 **ISP** 共同检查 Internet 连接，包括**线路、Modem 和路由器**等多方面设置。

**说明（教材原句）**：如果目标主机**不存在或当前不在线**，另外如果目标主机出于**安全性的考虑**设置为**屏蔽 ICMP 信息**，则 ping 命令将返回"**请求超时**""**目标无法到达**"等类似消息。

**三个测试场景一句话记忆**：**先测自己（127.0.0.1）→ 再测邻居（局域网）→ 最后测远方（Internet + DNS）**。

### 8.netstat 命令

**功能**：netstat 作为 Windows **内置**的一个工具拥有强大的功能，可用于显示与 **IP、TCP、UDP 和 ICMP** 协议相关的**统计数据**，一般用于**检验本机各端口的网络连接情况**。

**命令格式**：

```text
netstat [-a] [-b] [-e] [-f] [-n] [-o] [-p protol] [-r] [-s] [-t] [interval]
```

**参数说明**：

| 参数 | 含义 |
|---|---|
| **-a** | 显示**所有连接和侦听端口**，用于确认哪些 TCP/IP 服务进程处于**活动状态**，以及哪些 TCP 连接是**可用**的 |
| **-b** | 显示在创建每个连接或侦听端口时涉及的**可执行程序**。若已知可执行程序承载多个独立组件，则显示**组件序列**：可执行程序名称显示在**底部**，它调用的组件位于**顶部**。注意该选项可能**很耗时**，且在当前用户**权限不足**时可能失败 |
| **-e** | 获取**网卡的状态信息**，如发送分组、接收分组和错误分组的数量等；此选项可以与 **-s** 结合使用 |
| **-f** | 显示**外部地址的完全限定域名** |
| **-n** | 以**数字形式**显示地址和端口号 |
| **-o** | 显示拥有的与每个连接关联的**进程 ID** |
| **-p protol** | 显示 protol 指定的**协议**的连接；protol 可以是 **TCP、UDP、TCPv6、UDPv6**。若与 **-s** 一起用则显示每个协议的统计，此时 protol 可以是 **IP、IPv6、ICMP、ICMPv6、TCP、TCPv6、UDP、UDPv6** |
| **-r** | 显示当前主机的**路由表** |
| **-s** | 显示每个协议**数据包的统计**；默认显示 IP、IPv6、ICMP、ICMPv6、TCP、TCPv6、UDP、UDPv6 的统计 |
| **-t** | 显示当前**连接卸载状态** |
| **[interval]** | 用于**重新显示**选定的统计，指定各个显示类型之间**暂停的秒数**；省略则显示**当前的配置信息** |

**示例输出（教材原例，`netstat -n`）**：

| 协议 | 本地地址 | 外部地址 | 状态 |
|---|---|---|---|
| TCP | 192.168.1.150:1062 | 112.80.180.72:8080 | **ESTABLISHED** |
| TCP | 192.168.1.150:1205 | 220.194.116.116:443 | **CLOSE_WAIT** |
| TCP | 192.168.1.150:3211 | 172.217.163.42:443 | **SYN_SENT** |

**读法（教材原话）**：

- 本机 **1062 端口**与 112.80.180.72:8080 目前处于**可靠连接状态**；
- **1205 端口**与 220.194.116.116:443 处于**连接终止的等待阶段**；
- **3211 端口**与 172.217.163.42:443 处于**请求连接阶段**。

**三种状态对照（讲课补充，便于理解）**：

| 状态 | 含义 |
|---|---|
| **ESTABLISHED** | 连接**已建立**，双方可以收发数据 |
| **CLOSE_WAIT** | 对方已发 **FIN**，本机**等待关闭**（被动关闭方） |
| **SYN_SENT** | 已发出 **SYN**，**等待对方回应**（连接请求阶段） |

**考点**：要查"**本机开了哪些端口、和谁连着**"→ `netstat -a`；要查"**是哪个程序占的端口**"→ `netstat -b`（或 `-o` 看 PID）；要查"**路由表**"→ `netstat -r`。

### 9.nslookup 命令

**功能**：用来显示与 **DNS 有关的参数信息**，也可用来对 **DNS 的故障**进行排除。

**命令格式**：`nslookup [域名 / IP地址]`

**三种用法**：

| 用法 | 效果 |
|---|---|
| `nslookup`（不带参数） | 显示**本地主机设置的 DNS 服务器的主机名和对应的 IP 地址**。执行后进入 **nslookup 子命令运行状态**，提示符为 `>`；此时输入 **help** 可查看所有子命令，输入 **quit 或 exit** 可退出子命令状态，返回 DOS 命令符状态 |
| `nslookup 域名` | **查找并显示该域名对应的 IP 地址**（正向解析） |
| `nslookup IP地址` | **显示该地址对应的域名**（反向解析） |

### 10.hostname 命令

**功能**：显示计算机在**当前域中的主机名**。

**命令格式**：`hostname`

**注意**：它只显示**本机主机名**，与 DNS 解析无关；要查主机名对应的 IP，用 `nslookup` 或 `ping`。

### 11.telnet 命令（端口测试利器）

**功能**：用于**测试指定主机的指定端口是否可用**。

**命令格式**：`telnet ip/域名 port`

**示例**：`telnet www.hevttc.edu.cn 80`

**运行一段时间后显示的信息**：

```text
HTTP/1.1 400 Bad Request
Server: WebServer/4.0.0
Date: Mon, 13 May 2019 00:13:36 GMT
Content-Type: text/html
Content-Length: 277
Connection: close
```

**如何判读（教材原话）**：上述信息说明 www.hevttc.edu.cn 的 **80 端口处于活动状态**，并且显示了该端口所使用的**协议、服务器类型、连接状态**等信息。

**为什么是 400 而不是 200**：telnet 只建立 TCP 连接、**不发送合法的 HTTP 请求**，服务器认为请求格式有误，于是回 **400 Bad Request**——**能收到 400 就说明端口是通的**，这正是本命令的用途。

**说明**：如果只输入 `telnet`，则进入 telnet 的**子命令运行状态**；此时输入 **help** 可查看所有可运行的子命令，输入 **q** 退出子命令状态，返回 DOS 命令符状态。

### 12.pathping 命令

**功能**：Pathping 工具提供有关在**源和目标之间的中间跃点**处**网络滞后和网络丢失**的信息。

**工作过程（教材原句拆解）**：

1. Pathping 在**一段时间内**将多个回响消息发送到**源和目标之间的各个路由器**，然后根据各个路由器返回的数据包**计算结果**；
2. 因为 Pathping 可以表示在**任何特定路由器或连接处**的**数据包的丢失程度**，所以用户可据此确定**可能存在网络问题的路由器或子网**；
3. Pathping 通过**识别路径上的路由器**来执行与 **Tracert 命令相同**的功能；
4. 然后该命令在**一段指定的时间内定期**将 Ping 命令发送到**所有的路由器**，并根据每个路由器的返回数值**计算统计结果**。

**命令格式**：

```text
pathping [-g host-list] [-h maximum_hops] [-i address] [-n] [-p period]
         [-q num_queries] [-w timeout] [-4] [-6] target_name
```

**参数说明**：

| 参数 | 含义 |
|---|---|
| **-g host-list** | 与主机列表一起的**松散源路由** |
| **-h maximum_hops** | 搜索目标的**最大跃点数** |
| **-i address** | 使用指定的**源地址** |
| **-n** | **不**将地址解析成主机名 |
| **-p period** | 两次 Ping 之间**等待的时间**（毫秒） |
| **-q num_queries** | 每个**跃点的查询数** |
| **-w timeout** | 每次回复**等待的超时时间**（毫秒） |
| **-4 / -6** | 强制使用 **IPv4 / IPv6** |

**示例**：`pathping -n www.163.com`，输出先显示"通过最多 **30** 个跃点跟踪到 www.163.com [220.194.234.254] 的路由"，列出 `0 10.1.37.166`、`1 10.1.37.254` 等跃点，再"正在计算统计信息，已耗时 **25 秒**……"，最后给出各跃点的 **RTT / 已丢失 / 发送 = Pct** 统计，并以"**跟踪完成**"结束。

**pathping 与 tracert 的区别（重点）**：

| 对比 | **tracert** | **pathping** |
|---|---|---|
| 主要输出 | **路径**（经过哪些路由器） | **路径 + 每个跃点的丢包率与延迟统计** |
| 耗时 | 短 | **长**（要在一段时间内反复 Ping 每个路由器） |
| 用途 | 判断"**走哪条路**" | 判断"**在哪一跳开始丢包/变慢**" |

### 13.tracert 命令

**功能**：**Tracert（跟踪路由）**是路由跟踪实用程序，用于确定 **IP 数据报访问目标所采取的路径**。Tracert 命令用 **IP 生存时间（TTL）字段**和 **ICMP 错误消息**来确定从一个主机到网络上其他主机的路由。

**工作原理（逐句拆解，必考）**：

1. Tracert 通过向目标发送**不同 IP 生存时间值**的 **ICMP 回应数据包**，确定到目标所采取的路由；
2. 要求路径上的**每个路由器**在转发数据包之前**至少将数据包上的 TTL 递减 1**；
3. 数据包上的 **TTL 减为 0** 时，路由器应将"**ICMP 已超时**"的消息**发回源系统**；
4. Tracert **先发送 TTL 为 1** 的回应数据包，并在随后的每次发送过程中**将 TTL 递增 1**，直到**目标响应**或 TTL 达到**最大值**，从而确定路由；
5. 通过检查中间路由器发回的"**ICMP 已超时**"消息确定路由；
6. **某些路由器不经询问直接丢弃 TTL 过期**的数据包，这在 Tracert 实用程序中**看不到**；
7. Tracert 命令按顺序打印出返回"ICMP 已超时"消息的路径中的**近端路由器接口列表**；
8. 如果使用 **-d** 选项，则 Tracert **不在每个 IP 地址上查询 DNS**。

**命令格式**：

```text
tracert [-d] [-h maximum_hops] [-j host-list] [-w timeout] [-R] [-S srcaddr]
        [-4] [-6] target_name
```

**参数说明**：

| 参数 | 含义 |
|---|---|
| **-d** | **不**将地址解析成主机名 |
| **-h maximum_hops** | 搜索目标的**最大跃点数** |
| **-j host-list** | 与主机列表一起的**松散源路由**（仅适用于 IPv4） |
| **-w timeout** | 等待每个回复的**超时时间**（毫秒） |
| **-R** | 跟踪**往返行程**路径（仅适用于 IPv6） |
| **-S srcaddr** | 要使用的**源地址**（仅适用于 IPv6） |
| **-4 / -6** | 强制使用 **IPv4 / IPv6** |

**成功示例**：数据包必须通过两个路由器（**10.0.0.1** 和 **192.168.0.1**）才能到达主机 **172.16.0.99**；主机默认网关是 10.0.0.1，192.168.0.0 网络上路由器的 IP 是 192.168.0.1。输入 `tracert -d 172.16.0.99`，输出：

```text
Tracing route to 172.16.0.99 over a maximum of 30 hops
  1    2s    3s    2s   10.0.0.1
  2   75ms   83ms   88ms 192.168.0.1
  3   73ms   79ms   93ms 172.16.0.99
Trace complete.
```

**失败示例（教材原例，很有价值）**：目标 192.168.10.99 **没有有效路径**（这可能是**路由器配置的问题**，或者 **192.168.10.0 网络不存在**）：

```text
tracert 192.168.10.99
Tracing route to 192.168.10.99 over a maximum of 30 hops
  1  10.0.0.1  reports: Destination net unreachable.
Trace complete.
```

**判读要点**：看到"**Destination net unreachable**"且**在第一跳就返回**，说明**本地网关不知道该网段怎么走**——查路由或确认网段是否存在。

**tracert 里的"\*"是什么意思**：某一跳显示 `*  *  *`，表示**该路由器没有回应 ICMP 超时消息**（被过滤或直接丢弃），**不代表网络断了**。

### 14.Netdiag 工具

**定位**：Netdiag 是 **Windows Support Tools** 中包含的一个工具，是一个**基于命令行**的网络故障原因诊断工具，可以用它来**测试、验证网络连接**；如果操作系统中**没有安装**，可从互联网**下载**使用。

### 15.网络分析和诊断工具

**总述**：借助网络分析工具，可以对网络中传输的数据进行**有效的捕捉和分析**，从而**发现可能的威胁**，**迅速判断故障的根源**。

**为什么必须做网络性能测试**：优质、高效的网络性能是网络布线系统和网络设备系统所追求的**最终目标**，所有网络规划、设计、配置都是围绕着**网络性能**而展开的。因此网络搭建完成后，都必须进行**网络性能测试**，以验证：

- **拓扑结构的设计**是否合理；
- **网络设备的连接与配置**是否正确；
- **路由设备和交换设备的性能**是否满足需要。

下面几个软件工具**都是免费软件**，可以从互联网下载使用。

#### （1）超级网络嗅探器 Sniffer Pro

- **厂商**：美国 **Network Associates** 公司推出的**网络分析软件**，可用于**网络故障检修与性能管理**，在网络管理中应用非常广泛。
- **主要功能（教材列举）**：

1. **捕获网络流量**进行详细分析；
2. 利用**专家分析系统**诊断问题；
3. **实时监控**网络活动；
4. 收集**网络利用率和错误**等；

- **工作前提（重点）**：Sniffer 程序运行时把网络适配卡（一般为以太网卡）设置为**杂乱（promiscuous）工作模式**。网卡设置为这种模式后，它就可以**接收在网络上传输的每一个信息包**。
- **为什么必须这样**：**通常情况下，网卡只接收和自己的地址有关的信息包**，即传输到本地主机的信息包。为了**绕过标准的 TCP/IP 堆栈**，网卡就必须设置为**混杂模式**；基于 Sniffer 这样的模式，可以分析各种信息包并**描述出网络的拓扑结构和活跃的计算机**。

**"混杂模式"是本节最高频考点**：抓包的前提是网卡**接收所有帧**，而不是只收发给自己的帧。

- **使用条件（考点）**：测试时需使用**两台计算机**，并且**均需运行 Qcheck**。测试中从一台计算机向另一台计算机**发送文件**，然后测试**所消耗的时间**，并自动计算出**传输率**等网络状态数据。

#### （3）网络带宽测试工具

- **性能与带宽的关系**：如果网络**性能**主要取决于**交换和路由设备**的性能，那么网络**带宽**则主要取决于**线路质量**，包括 **Internet 线路、局域网链路**还是**无线网络信号**。网络带宽**决定**着网络性能，没有足够的网络带宽，是无法获得满意的网络性能的。
- **常用工具**：有线带宽测量工具 **Ping Plotter**；无线网带宽测量工具 **IxChariot**。

- **工具性质**：**子网掩码计算器（IPSubnetter）** 是一个方便快捷的、计算 IP 子网的**免费工具**，可自由下载；**可随意调整掩码位**，因此可用来计算**不标准的子网**。
- **输入与输出**：只要输入**点分十进制**的 IP 地址，程序立刻可以判断出它**属于哪类地址**，并显示其**子网位、主机位、符合条件的子网数目、每个子网所包含的有效主机数目、掩码、所属子网地址、子网的广播地址（同时用二进制和十进制显示）** 以及**当前子网所包含的主机范围**。

### 16.网络设备管理工具

**总述**：最常用的网络设备管理方式就是**远程登录**，即由接入网络的计算机**借助某些软件远程登录到网络设备中**，并作相应的配置。

#### （1）Windows 设备管理工具

Windows 集成了许多有价值的应用程序。除"**超级终端**"外，**Telnet** 也经常被用于实现对网络设备（**可网管的交换机、路由器、防火墙**等）的远程管理；此外，借助 **Windows Support Tools** 中的 **Device Console Utility**，还可实现对**服务器硬件设备**的管理。

**① 远程设备登录 Telnet**

- Telnet 是**包含在 TCP/IP 协议中的一项网络服务**，用户**无需安装**，只要安装了 TCP/IP 协议即可**直接运行**。
- 利用 Telnet 为虚拟终端提供**一个标准的端口**，用户**不必了解终端设备的详细信息**即可建立连接。
- 另外，Telnet 还为用户和终端设备提供**一个协商选项的机制**和**一组标准选项**。
- **应用范围**：目前大多数网络设备的**管理和配置**都是通过这种方式进行的，如**网络服务器的更新、路由器的配置、网络防火墙的配置**等。

**② 设备管理控制台——超级终端**

- **作用与 Telnet 基本相同**，但区别在于：**Telnet 只适用于一个远程设备的连接**，而**超级终端还可以通过串行口连接至可网管设备的 Console 端口**进行配置。
- **重要顺序（考点）**：事实上，设备在**可远程 Telnet 管理之前**，**必须借助超级终端**完成其 **IP 地址、用户名和密码**等的基本配置。

**Telnet vs 超级终端对照表**：

| 对比 | **Telnet** | **超级终端** |
|---|---|---|
| 连接方式 | 通过 **TCP/IP 网络**登录 | 可通过**串行口**连接 **Console 端口** |
| 是否需要 IP | **需要**（要能 ping 通设备） | **不需要**（直连串口） |
| 适用阶段 | 设备**已配好 IP** 后的日常管理 | **首次配置**（配 IP、用户名、密码、密码恢复） |
| 同时管理 | 可开多个会话 | 通常**一个**连接 |

#### （2）网络配置管理工具

- **为什么需要**：网络建成后，经过一段时期的运行，特别是**升级、改造和扩展**之后，**拓扑结构可能受到影响**。能**迅速了解拓扑结构**、调整设备间连接，以获取**最大的网络带宽和性能**就显得尤其重要。另外，随着**可网管设备日益增加**，**设备配置的备份和恢复**、**设备映像文件的备份和升级**，也成为保障网络正常运行和网络安全的**必要手段**。
- **为什么多由厂商提供**：由于网络配置管理工具需要**与设备进行有效通信**以获取设备的各种信息，所以这类软件**大都由设备的生产厂商开发、提供**。

**① 简单文件传输协议服务器 TFTP**

- **全称**：**Trivial File Transfer Protocol，TFTP**。
- **定位**：TCP/IP 中用来在**客户机与服务器之间**进行**简单文件传输**的协议，提供**不复杂、开销不大**的文件传输服务。
- **下层**：它**基于 UDP 协议**而实现，是**专门为进行小文件传输**而设计的协议。
- **用途（考点）**：TFTP 服务器可实现**交换机或交换机软件系统的保存和升级**、**配置文件的保存和下载**，使得对交换机的管理变得**简单和快捷**。因此在进行交换机的管理前，**应先安装一台 TFTP 服务器**。
- **常见软件**：**Cisco TFTP Server、华为 TFTP Server** 等。

**② Cisco 网络助手（Cisco Network Assistant，CNA）**

- **定位**：一个**基于 PC** 的网络管理应用，适用于**用户数不超过 250 人**的有线或无线局域网。
- **技术**：通过采用 **Cisco Smartports** 技术，思科网络助手能够**简化**思科网络设备的**配置、部署以及日常管理和维护**。
- **界面与能力**：借助一个**用户友好型 GUI**，提供**集中网络视图**；使网管员能方便地使用**通用服务、生成状态报告、实现密码同步**，并且**远程启动**思科交换机、路由器和接入点的其他设备。

#### （3）企业网络管理工具

- **企业网的特点**：一般由**各部门的局域网**组成，管理时需要**管控全体或局部用户的上网行为**，需要进行**统一的防病毒、防黑客部署**，能够**调控网络带宽、隔离部分网络用户**等，其**管理难度要增大许多**。
- **代表软件**：**Cisco Works 2000、ITiMe、ManageEngine** 等。

### 17.网络维护和恢复工具

**总述**：对网络内计算机的**日常维护与系统重装**，也是网络管理员的重要职责之一。**灵活、有效地使用网络资源**是日常维护顺利进行的重要保障，而应用于客户端的**策略部署**，则是提高系统维护效率的**重要手段**。

#### （1）net 命令

**命令格式**：

```text
net [ ACCOUNTS | COMPUTER | CONFIG | CONTINUE | FILE | GROUP | HELP |
      HELPMSG | LOCALGROUP | PAUSE | SESSION | SHARE | START |
      STATISTICS | STOP | TIME | USE | USER | VIEW ]
```

**说明（三条）**：

1. 通过键入 **`net /?`** 可查阅**所有可用**的 net 命令；
2. 通过键入 **`net help 命令`** 可在命令行中获得 net 命令的**语法帮助**，如 `net help accounts`；
3. 所有 net 命令接受选项 **/yes 和 /no**（可缩写为 **/y 和 /n**）：**/y** 对命令产生的任何交互提示**自动回答"是"**，**/n** 回答"否"。如 `net stop server` 的功能是**结束服务器上的所有服务**，但操作过程中需要**确认**；加 **/y** 后自动回答"是"并关闭服务器服务。

**常用子命令表**：

| 子命令 | 功能 |
|---|---|
| **net view** | 显示网络中**计算机名称列表** |
| **net share** | 管理（显示、增加、删除、更新）**网络共享资源** |
| **net use** | 显示**网络映射与网络连接** |
| **net start** | **启动**系统/网络服务 |
| **net stop** | **停止**系统/网络服务 |
| **net send** | 向其他网络用户**发送信息** |
| **net user** | **添加/修改用户账号** |
| **net group** | **添加/修改网络逻辑组** |
| **net computer** | 在网络逻辑组中**添加或删除计算机** |
| **net config** | **配置网络服务** |

#### （2）系统维护工具

**前提**：在维护过程中，服务器安装网络操作系统后，应**及时安装相关网络服务**。在日常管理维护过程中，应**经常进行相关数据的备份**，以便在**系统重装或数据恢复**时，迅速**复原系统设置和网络服务**，减少**停机/停服务时间**，提高网络服务的有效性。

**① 计算机工作计划的制定 at**

- **用途**：用于**制定计划**，以便系统按照该计划指定的**日期和时间**启动及运行计算机上的**命令、程序**。
- **前提**：at 命令**只能在"计划"服务运行时使用**；在没有参数的情况下使用，则**列出已计划的命令**。
- **命令格式 1**：`at [\\computername] [[id] [/delete] | /delete [/yes]]`
- **命令格式 2**：`at [\\computername] time [/interactive] [/every:date[,...] | /next:date[,...]] "command"`

| 参数 | 含义 |
|---|---|
| **\\computername** | 指定**远程计算机**；省略则在**本地**运行 |
| **id** | 指定给已计划命令的**识别号** |
| **/delete** | **删除**某个已计划的命令；省略 id 则**所有**已计划的命令都会被删除 |
| **/yes** | 需要进一步确认时**均默认为 yes**，与删除所有计划命令一起使用 |
| **time** | 指定**运行计划命令的时间** |
| **/interactive** | 允许计划命令在运行时与当时登录的**用户桌面进行交互** |
| **/`every:date`[,...]** | 指定在**每周（或每月）的特定日期**运行计划命令；省略日期则默认在**每月的当前日**运行 |
| **/`next:date`[,...]** | 指定在**下一个指定日期**运行命令；省略日期则默认在**每月的当前日**运行 |
| **"command"** | 准备运行的 **Windows 命令或程序** |

**② 网络信息收集、管理工具 NEWT Professional**

- 网管员需要掌握网络内计算机的**详细情况**：**计算机名、IP 地址、MAC 地址、操作系统信息**，甚至 **CPU 速度/数量、日期和时间、计算机运行时间、用户名、逻辑组名**等，就可以使用 **NEWT Professional**。
- 该软件是一个**共享软件**，可以通过互联网下载使用。

**③ 客户端信息搜集工具 Jxdev LANView**

- 可以**快速收集**网络内所有客户端的**信息**：**IP 地址、MAC 地址、共享资源、机器名、用户和组名称**；
- 也可以方便地对网络内的**数据包进行捕获和分析**；
- 另外也可用于**检测本地主机**并获取如 **IP 统计、IP 流量、网络连接、Winsock 状态**等信息。

**④ 组策略与活动目录相关命令（一组命令，按"还原—编辑—安装—查看—刷新"记）**

| 命令 | 功能 |
|---|---|
| **dcgpofix** | 组策略管理命令，可以将**默认组策略对象还原到它们的原始状态**；必须是**网络管理员**才有权限使用 |
| **gpedit.msc** | **本机**的组策略管理，可在 DOS 窗口中运行，打开**组策略管理器**进行调整 |
| **dcpromo** | **安装/卸载活动目录**：启动活动目录向导，或实现**无人活动目录安装**，及**活动目录的删除** |
| **gpresult** | **组策略查看**命令：显示用户或计算机的组策略设置和策略的**结果集（RSOP）** |
| **gpupdate** | **组策略刷新**命令：刷新**本地组策略设置**和存储在活动目录中的组策略设置，**包括安全设置** |

**⑤ 备份与恢复类命令**

| 命令 | 功能 | 备注 |
|---|---|---|
| **ntbackup** | **系统状态备份**：在命令提示符下执行系统备份操作 | Windows 自带备份工具 |
| **recover** | **磁盘数据恢复**：从**损坏的磁盘**中尽可能恢复可读取的信息 | 不是"撤销删除"，是抢救坏盘 |
