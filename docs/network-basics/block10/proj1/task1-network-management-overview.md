**项目一导读（教材原句拆解）**：

- **20 世纪 90 年代**，网络规模迅速扩展，随之最主要的问题就是**如何有效进行网络管理**。
- 一个较大的网络通常跨越较大的空间范围，连接**不同类型的局域网**（以太网、FDDI 网等）。
- 计算机网络除计算机设备外，还有大量**网间设备**：集线器、交换机、路由器、网桥等。

- **网络故障诊断**：以网络原理、网络配置和网络运行的知识为基础，从**故障现象**出发，以**网络诊断工具**为手段获取诊断信息，**确定故障点、查找根源、排除故障、恢复网络正常运行**的软件或硬件。

### 3.任务描述：网络管理系统干什么

**教材原句**：网络管理系统的主要功能是**维护网络正常高效地运行**。主要包括：

1. **及时监测**网络出现的故障并**及时处理**；
2. 通过**监测分析运行状况**而**估价系统性能**；
3. 通过对网络的**配置、调整**，更**有效地利用资源**，保证网络高效率地正常运行。

**归纳成三个动词**：**监测 → 分析 → 调整**。

### 4.两种"网络管理系统"标准

从**网络管理体系标准**来看，通常有两种：

| 序号 | 标准 | 制定者 | 说明 |
|---|---|---|---|
| 第一种 | **网络管理系统规程** | **ISO** 推荐 | 理论完整（对应 OSI 七层），但实现复杂、开销大 |
| 第二种 | **简单网络管理协议（SNMP）** | **Internet 中 TCP/IP** 体系 | 简明、清晰，**基于 UDP**，具有**传输快、负载轻**的特点 |

**SNMP 的地位（必考）**：由于 SNMP 简明、清晰，并基于 UDP，具有传输快、负载轻的特点，许多大的计算机网络设备厂商都宣布自己的网络管理体系和产品**支持 SNMP**，从而使 SNMP 成为**事实上的网络互联管理的工业标准**。

**注意措辞的差别**：OSI 那套是"**推荐的**"标准，SNMP 是"**事实上的**"工业标准——一个"法定"，一个"既成事实"。

### 5.三种网络管理模式

从**网络管理模式**来看，一般有三种管理模式。

| 模式 | 核心做法 | 优点 | 缺点 | 典型产品 |
|---|---|---|---|---|
| **集中式** | 全网所有需要管理的数据均存储在**一个集中的数据库**中，统一管理整个网络 | ① 处于**高度集中、易于全面做出决断**的最佳位置；② **网络升级时仅需处理集中点**即可；③ 数据连到统一中央数据库，**易于管理、维护和扩大容量** | ① **中央数据库一旦故障，将导致全网瘫痪**；② 建设网管系统的**链路承载业务量很大**，有时将超出负荷能力 | HP 的 **Open View NMS**、Cabletron Systems 的 **Spectrum**、IBM Tivoli 的 **Net View**、Sun Microsystems 的 **Net Manage** |
| **分级式** | 一个 NMS 作为"**总经理人（Manager）**"，另几个 NMS 作为**经理人**，各管自己管辖的领域（**Managed Entity**），总经理人总体管辖其他经理人所应管辖的部分 | ① **分散了网络/资源的负荷**；② 各网管**更接近被管理单元**；③ **降低了总网管所需收集传输的业务量**；④ 比集中式**可靠** | 比集中式**复杂**，**系统设备价格相应提高** | **HP Open View**（高层和较低层的 NMS）、**Cisco Networks**（较低层 NMS） |
| **分布式** | 一种与**管理系统设备位置无关**的网管系统；虽然与位置无关，但从**收集网管数据**等功能来说，**还是可以集中的** | ① **完全分散了网络/资源的负荷**；② 规模大小**可按需要任意调整**；③ **可靠性很高** | 系统设备**更复杂**一些（需要有**分布应用的架构**）；是一种崭新的、正在迅速发展的技术，**尚无标准** | 尚无统一标准产品 |

**记忆线索**：

- **集中式**——"一个大脑"，最省事也最怕"脑死亡"（单点故障）。
- **分级式**——"总公司 + 分公司"，把负荷摊下去，代价是复杂、贵。
- **分布式**——"没有中心"，位置无关，最可靠但最难做（要分布应用架构、还没有标准）。

**考试常问**：三种模式中**可靠性最高**的是？→ **分布式**；**最容易因单点故障导致全网瘫痪**的是？→ **集中式**。

### 6.网络管理的范畴：管什么

从**网络管理的范畴**来看，主要有以下**四种管理**：

| 序号 | 管理对象 | 具体内容 |
|---|---|---|
| 第一 | 对"**路**"的管理 | 针对**交换机、路由器**等**主干网络**进行管理 |
| 第二 | 对**接入设备**的管理 | 对**客户机、服务器**进行管理 |
| 第三 | 对**行为**的管理 | 针对**用户的使用行为**进行管理 |
| 第四 | 对**资产**的管理 | 统计 **IT 软、硬件**的信息等 |

### 7.网络管理的业务范围：两个角度

网络管理的业务范围可以从**网络系统组成**和**网络维护**两个不同角度考虑。

**（1）从网络系统组成的角度：硬件管理 + 软件管理**

| 类别 | 管理对象 | 要点 |
|---|---|---|
| **硬件管理** | 构成网络的**设备组成** | 网络连接硬件包括**网络接口卡（NIC）、集线器（Hub）、交换机（Switch）、路由器（Router）**等，以及**打印机、扫描仪、绘图仪**等可被共享的外部设备 |
| **软件管理** | 运行于网络上的**操作系统、应用程序**以及**用户账号和存取权限** | **网络操作系统是网络的灵魂**，决定了网络的功能以及不同网络的应用领域，**对网络操作系统的管理是软件管理最重要的部分** |

**（2）从网络维护的角度：网络建设 + 网络维护 + 网络服务**

| 环节 | 具体内容 |
|---|---|
| **网络建设** | 组建网络（**规划拓扑、物理硬件实现、网络协议设置**等）、**新增或升级**网络设备、**规划网络发展**等 |
| **网络维护** | **网络故障检测和维修**（包括硬件和软件）、**网络安全的防护和管理**等 |
| **网络服务** | 因网络用途不同而不同，最常见的是**资源共享、远程登录、文件传输、电子邮件**；另外如网站主页的制作与更新、FTP 站点的建设与管理等，也都可纳入网络管理的业务范围 |

**一句话对照**：**组成角度分"硬/软"，维护角度分"建/维/服"**。

### 8.网络管理员的知识结构与素质

**（1）总要求**：一个真正的网络管理员，应当**熟练掌握服务器的安装、配置和各种服务的实现方式**，掌握**网络设备的性能和基本配置**，以及**网络数据库的一般操作**。

**（2）软件方面**：

- 首先应当掌握**网络操作系统**，构建一个简单的网络、提供一些最基本的服务。
- 其中**最重要**的是：如何实现**管理文件操作系统**，**安全、方便地控制网络上的系统资源**，实现**文件和网络设备的共享、访问**。
- 基本能力：构建能在网络上运行的 **Web 网站服务器、FTP 文件服务器、E-mail 邮件服务器**。
- 高级管理要求：系统的**负载平衡**、高级的**电源管理**、网络灾难后**数据文件的及时恢复**等。

**（3）硬件方面**：

- 必须掌握**系统集成知识**：规划局域网，包括**拓扑规划和子网规划、布线设计、网络设备（交换机、路由器）的安装和配置、服务器的硬件、各种服务的安装和配置、不同操作系统之间的差异、网络安全**等。
- 必须掌握**交换机、路由器的一些基本配置**：利用交换机在网络上**划分 VLAN**，使用路由器实现**不同网络通信流量的转发**。
- 还必须掌握：**网络设备配置的备份和还原**、**网络配置系统的升级**等。

**（4）网络管理员应具备的素质（8 条）**：

1. **自学能力**
2. **外文资料阅读能力**
3. **动手能力**
4. **创新和应变能力**
5. **观察能力**
6. **分析判断能力**
7. **毅力、精力和体力**
8. **沟通能力**

### 9.OSI 网络管理体系：五大管理区域（重点）

**总述**：网络管理系统是保障网络**安全、可靠、高效和稳定**运行的技术保证，已成为整个网络系统不可缺少的重要部分。网络管理涉及网络资源和运行的**规划、组织、监视以及计费和控制**等各个方面。

在 **OSI 的网络管理体系结构**中，包括**配置管理、性能管理、故障管理、安全管理、计费管理**五大管理区域。

**记忆口诀**：**配、性、故、安、计**——"**配**好资源、**测**好性能、**修**好故障、**守**好安全、**算**好费用。

#### （1）配置管理（Configuration Management）

- **为什么需要**：保持网络系统持续、正常运行，相关的软件、硬件设备需要**密切配合**。除传输线路没有问题外，还必须**合理、正确地设置网络设备的参数**。
- **目标**：**监视网络和系统配置信息**，以便**跟踪和管理**对不同的软件、硬件进行的网络操作的效果。
- **配置管理的内容**：对网络系统的参数进行**设置**，把**名称**与被管理对象和被管对象的集合**联系起来**；使被管对象**初始化**并**关闭**被管对象；按照需求，**收集**有关网络状态的信息。
- **配置管理的作用**：监控网络的配置信息，使网络管理人员可以**生成、查询以及修改**硬件/软件的运行参数和条件，以保持网络的正常运行。
- **配置管理的参数和条件**：网络设备、部件的**存在性、名称和关系**；**寻址信息**、运行特性、部件的可用性、信息备份操作条件、**路由控制**等。
- **配置管理功能**：网络内需要监视和控制的内容，网络资源及活动状态，网络资源之间的关系，**新资源的引入和旧资源的删除**等。
- **需要进行的操作**：**鉴别**所有管理对象、给每个对象**分配名字**；**定义**新的管理对象；设置管理对象属性的**初始值**；管理各管理对象之间的**关系**；**改变**管理对象的操作特性、**报告**状态变化；**删除**管理对象。

**小结（教材原句）**：配置管理涉及**定义、收集、监视、控制和使用配置数据**，配置数据包括管理网络中所有资源的**任何静态和动态信息**。配置管理通过修改被管对象的**存在性、属性、状态和关系**来控制被管对象，使网络最大限度地提供其资源和业务。

#### （2）性能管理（Performance Management）

- **目标**：**衡量和呈现网络性能的各个方面**，使人们能在**一个可接受的水平**上维护网络的性能。
- **四个性能指标（判别传输性能）**：

| 指标 | 含义 |
|---|---|
| **网络传输流量** | 网上实际传输的数据量 |
| **传输正确率** | 传输的正确程度（差错多少） |
| **用户响应时间** | 用户发出请求到得到响应的时间 |
| **线路利用率** | 线路被占用的比例 |

- **性能管理包括**：**收集**网管关注的变量的性能参数并**分析**这些数据，以判断是否处于正常状态；根据数据的统计分析进行**调整**，以控制网络性能；为每个重要变量**设定合适的性能范围值**，若超出该值范围即表明出现值得注意的网络故障。管理实体**不断地监视**性能变量，当某个性能范围值被超出时，即**产生报警**，并把报警信息发送到网络管理系统，**提供网络性能报告**。
- **总之**：性能管理包括**收集统计信息、维持和检查系统状态的历史记录、判断系统在正常运行和人为干预条件下的性能**，以及为进行性能管理活动而**改变系统的运行模式**等功能。

#### （3）故障管理（Fault Management）

- **目标**：**自动检测、记录**网络故障并**通知用户**，使网络有效地运行。
- **为什么最重要**：因为故障可以导致网络的**瘫痪**或网络性能的**下降**，所以故障管理是网络管理中**最重要的管理内容之一**。
- **包含内容**：**判断故障特征、隔离故障、修复故障**、对所有因故障涉及的子系统进行修复、**记录**故障的检测及结果等。
- **故障三大类型**：**物理故障、配置故障、系统故障**——相应的故障管理也涉及三大故障管理类型。
- **故障排除操作五个步骤（必背）**：

1. **排定优先顺序**
2. **收集信息**
3. **设想可能的原因**
4. **排除问题**
5. **测试结果**

#### （4）安全管理（Security Management）

- **目标**：按照**本地的管理策略**来**指导和控制**对网络资源的访问，以保证网络**不被侵害**，保证**未经授权的用户不能访问重要信息**。
- **例子**：管理系统能**监视用户对网络资源的登录**，对**不具有合法身份**或**不正确访问**网络资源的用户**加以拒绝**。
- **两类资源**：安全管理子系统将网络资源分为**授权**和**未授权**两大类；无论对**网络外部用户**还是**网络内部用户**，均要对其访问的网络资源进行**限定**。
- **可以完成的操作**：**标记**重要的网络资源（如系统、文件或其他实体）；确定重要的网络资源与**用户集合间的对应关系**；**监视**对网络重要资源的访问；**记录**对重要网络资源的**非法访问**等。

#### （5）计费管理（Accounting Management）

- **别名**：又叫**计账管理**。
- **目标**：**衡量网络的利用率**，以便使一个或一组网络用户能**更规则地**利用网络资源。
- **目的**：保证网络资源被**有效利用和分配**，使用户对网络资源的使用更加**顺畅、有序、公平、合理**。
- **计费方式**：对网络资源的使用可以按**时间**或按**流量**进行计费管理。
- **与性能管理的关系（教材原句）**：为达到合理计费管理的目的，必须通过**性能管理**测量出**资源利用率**的相关信息，来产生**计费依据信息**，并加以评估，以便对资源利用进行优化。

**五大区域一表汇总**：

| 管理区域 | 目标一句话 | 关键动作 |
|---|---|---|
| **配置管理** | 监视网络和系统配置信息 | 设置参数、分配名字、记录状态变化 |
| **性能管理** | 在可接受水平上维护网络性能 | 收集 → 分析 → 调整 → 报警 |
| **故障管理** | 自动检测、记录并通知故障 | 判断特征 → 隔离 → 修复 → 记录 |
| **安全管理** | 控制对网络资源的访问 | 标记资源、定对应关系、监视、记录非法访问 |
| **计费管理** | 衡量网络利用率 | 按时间或流量计费 |

### 10.网络管理发展方向（五个方向）

**背景**：随着网络应用和规模不断增加，网络管理工作越来越繁重，网络故障也频频出现。以前许多企业会简单地通过**再购买服务器**来解决问题，而现在可能会考虑**购买网管软件**来加强网络管理，以优化现有网络性能，网管软件日益受到重视。

**五个主要开发方向**：**网络管理系统（NMS）、应用性能管理（APM）、桌面管理（DMI）、员工行为管理（EAM）、安全管理（SM）**。

#### （1）网络管理系统（NMS）

- **对象**：主要针对**网络设备**进行监测、配置和故障诊断。
- **四项主要功能**：**自动拓扑发现、远程配置、性能参数监测、故障诊断**。
- **两类开发公司**：
  - **通用软件供应商**：开发针对各厂商网络设备的**通用**网管系统，流行的有 **Openview、Micromuse、Concord** 等。
  - **各个设备厂商**：为自己产品设计的**专用** NMS，对自己产品监测、配置功能**非常全面**，可监测通用网管系统无法监测的重要性能指标，还有一些**独特配置功能**；但对其他公司生产的设备**基本上无能为力**。流行的有 **CiscoWorks、NetSight**，国内的 **Linkmanage、iManager**。
- **选择 NMS 要考虑的四个因素**：

| 因素 | 要点 |
|---|---|
| **① 网络拓扑搜索的准确率** | 许多网管系统都提供自动拓扑搜索，但不同产品**结果差别很大**；目前**还没有一种软件可以完全准确**搜索出所有网络设备，特别是**跨网段、包含 VLAN** 时许多自动搜索工具会失效；针对特定设备还需相应协议，如针对 Cisco 设备可采用 **CDP 协议** |
| **② 配置功能是否完善** | 设备厂商的网管**配置功能比较完善**但只针对特定设备；通用产品配置功能**相对弱**但**通用性高**。设备**少或种类多**时，对配置功能要求可降低；设备**多且基本是一个厂商**时，可买该厂商产品，一个**批量修改配置**的功能就能大大减轻工作量 |
| **③ 系统的开放性** | 网管系统**能否和其他网管系统集成**。一个企业很可能购买多种网管系统，导致内部**多套系统共存**；没有**开放接口**，管理人员就不得不通过**不同操作界面**管理不同系统 |
| **④ 特定功能是否能满足** | 特定网络系统有特殊要求。如某宽带系统**病毒发作时会产生大量小于 64 字节的数据包**，造成设备系统崩溃，因此网管系统要能**监测小于 64 字节数据包的转发率**，一旦异常增高能**立刻关闭网络设备** |

#### （2）应用性能管理（APM）

- **定位**：一个**比较新**的网络管理方向，主要指对企业的**关键业务应用**进行**监测、优化**，提高企业应用的**可靠性和质量**，保证用户得到良好的服务。
- **为什么重要**：企业关键业务应用的性能强大，就可以**提高竞争力**，有利于取得商业成功；加强应用性能管理可以产生**巨大商业利益**。
- **三项主要功能**：

| 功能 | 要点 |
|---|---|
| **① 监测企业关键应用性能** | 过去 IT 部门测性能时重点测**硬件组件的利用率**（CPU 利用率、网络传输字节数），虽提供宝贵信息，却**忽视了最重要的因素——最终用户的响应时间**。现在通过**事务处理过程监测、模拟**等手段可**真实测量用户响应时间**，还可报告哪个用户正在使用某应用、使用频率、事务处理是否成功完成等 |
| **② 快速定位应用系统性能故障** | 通过对应用系统各种组件（**数据库、中间件**）的监测，迅速定位故障，如 **Oracle 数据库死锁**等问题 |
| **③ 优化系统性能** | 精确分析各组件占用系统资源情况、中间件与数据库执行效率；根据性能要求**提出专家建议**，保证应用在**整个寿命周期**内使用的系统资源最少 |

- **选择 APM 要考虑的三个因素**：

| 因素 | 要点 |
|---|---|
| **① 应用系统可监测性** | 采用 APM 技术监测应用性能，要求被监测系统**必须支持 APM API**。目前 **Oracle、SAP、WebLogic** 等国外公司产品都支持，但**国内企业开发系统可能不支持** |
| **② 扩展性** | 应用系统变化非常快，扩展性非常重要。如数据量增加后数据库从 **SQL Server 升级到 Oracle**，APM 要能**动态增加监测 Oracle 数据库组件**，而**不需要升级整个 APM 系统** |
| **③ 易用、可自学的故障诊断工具** | 应用系统故障诊断比 NMS 更复杂，不仅要分析网络性能、系统资源，还要分析**系统设置、应用程序效率**。良好的诊断工具**不一定全自动**——全自动智能故障推理系统开发难度极高、会使软件价格急剧上升；可以是**半自动**，但**要有自学功能** |

#### （3）桌面管理系统（DMI）

- **桌面管理环境**：由**最终用户的计算机**组成，这些计算机运行 **Windows、Mac OS** 等操作系统。
- **管理内容**：对**计算机及组件**进行管理，目前主要关注**资产管理、软件分发、远程控制**三个方面。
- **效果**：一方面**减少网管员的劳动强度**，另一方面**增加系统维护的准确性、及时性**。
- **两部分**：这类系统通常分为**管理端**和**客户端**两部分。
- **选择 DMI 要考虑的三个因素**：

| 因素 | 要点 |
|---|---|
| **① 用户自身管理模式** | 桌面管理系统需要在**每台被管理客户机上安装代理（Agent）**，网管人员可**远程控制**被监测客户机，这涉及**客户隐私问题**。用户购买前最好先考虑自身管理模式**是否能支持网管软件的使用** |
| **② 支持的操作系统种类** | Agent 要求能支持企业中**所有操作系统**；当某种操作系统设备**数量较少**时，出于**节约成本**考虑，也可以只买支持**主流操作系统**的产品 |
| **③ 网络带宽占用情况** | 远程控制、软件分发等**传递数据量大**，很可能造成**数据传输阻塞**，因此必须有**数据压缩**功能，以减少带宽占用 |

#### （4）员工行为管理（EAM）

- **两部分**：一部分是**员工网上行为管理（EIM）**，另一部分是**员工桌面行为监测**。
- **代表产品**：国际上 **Websense** 软件**市场占有率较高**，国内推出了类似产品 **NetManage**。
- **Websense 的特点**：可与许多网络产品集成；一般在 **Internet 应用层、网络层**对信息进行控制；对数据根据 **EIM 数据库**进行**过滤**；可定制**因特网访问策略**，根据**用户、团组、部门、工作站或网络**的不同设置不同的互联网访问策略；还有专门的报表工具 **Websense EIM Reporting Tools**。
- **选择该类产品的三个问题**：

| 问题 | 要点 |
|---|---|
| **① 管理规模、软件效率** | EAM 需对**所有 Internet 数据**进行分析，随着网络规模增大、数据量显著增加，**软件效率可能下降，变成网络瓶颈** |
| **② 报告质量** | EAM 报告采集了**海量数据**，如何让管理者从海量数据中**了解员工上网情况、迅速发现异常行为**十分关键 |
| **③ 设置灵活性** | 系统是否能根据企业需求，对员工上网行为从**个人、部门**等角度**灵活设置策略**。用户应用前最好独立或与厂家合作**设计一套管理策略**，再监测产品是否满足需求 |

#### （5）安全管理（SM）

- **定义**：网络安全管理指**保障合法用户对资源安全访问**，**防止并杜绝黑客蓄意攻击和破坏**。
- **包括的功能**：**授权设施、访问控制、加密及密钥管理、认证、安全日志记录**。
- **选择该类软件时可考虑**：系统**自身性能稳定**、系统**协议分析检测能力及解码速率**、**系统升级服务**等。

**五个方向一表速记**：

| 方向 | 管什么 | 一句话功能 | 代表产品 |
|---|---|---|---|
| **NMS** | 网络**设备** | 拓扑发现、远程配置、性能监测、故障诊断 | Openview、CiscoWorks |
| **APM** | **关键业务应用** | 监测应用性能、定位应用故障、优化系统 | 支持 APM API 的产品 |
| **DMI** | **桌面计算机** | 资产管理、软件分发、远程控制 | 管理端 + 客户端架构 |
| **EAM** | **员工行为** | 上网行为管理（EIM）+ 桌面行为监测 | Websense、NetManage |
| **SM** | **安全** | 授权、访问控制、加密与密钥、认证、日志 | — |

### 12.速查表

| 序号 | 考点 | 结论 |
|---|---|---|
| 1 | 网络管理系统的功能 | 维护网络**正常高效**运行：监测故障并处理、分析估价性能、配置调整资源 |
| 2 | 两种体系标准 | ISO 的**网络管理系统规程**（推荐）、TCP/IP 的 **SNMP**（事实上的工业标准） |
| 3 | SNMP 的传输层 | 建立在 **UDP** 之上，**不可靠、无连接**，但**传输快、负载轻** |
| 4 | 三种管理模式 | **集中式、分级式、分布式** |
| 5 | 集中式的致命缺点 | **中央数据库故障导致全网瘫痪** |
| 6 | 分级式的角色 | **总经理人（Manager）** 管**经理人**，经理人管**管辖领域（Managed Entity）** |
| 7 | 分布式的前提 | **与设备位置无关**，需**分布应用架构**，**尚无标准** |
| 8 | 网络管理范畴 | 对**路**、**接入设备**、**行为**、**资产**的管理 |
| 9 | 业务范围两角度 | **系统组成**（硬件 + 软件）、**网络维护**（建设 + 维护 + 服务） |
| 10 | 软件管理最重要的部分 | **网络操作系统的管理** |
| 11 | 管理员素质 | **8 条**：自学、外文阅读、动手、创新应变、观察、分析判断、毅力精力体力、沟通 |
| 12 | OSI 五大管理区域 | **配置、性能、故障、安全、计费** |
| 13 | 性能管理四指标 | **网络传输流量、传输正确率、用户响应时间、线路利用率** |
| 14 | 故障管理三大类型 | **物理故障、配置故障、系统故障** |
| 15 | 故障排除五步骤 | **排定优先顺序 → 收集信息 → 设想可能的原因 → 排除问题 → 测试结果** |
| 16 | 网络管理中最重要之一 | **故障管理**（故障会导致瘫痪或性能下降） |
| 17 | 计费方式 | 按**时间**或按**流量** |
| 18 | 五个发展方向 | **NMS、APM、DMI、EAM、SM** |
| 19 | NMS 四功能 | **自动拓扑发现、远程配置、性能参数监测、故障诊断** |
| 20 | NMS 厂商分类 | **通用软件供应商**（Openview 等）与**设备厂商**（CiscoWorks 等） |
| 21 | APM 最核心的指标 | **最终用户的响应时间**（不是 CPU 利用率） |
| 22 | DMI 三个关注点 | **资产管理、软件分发、远程控制** |
| 23 | EAM 代表软件 | **Websense**（国内 **NetManage**） |
