## 知识点

### 1.任务描述：SNMP 是干什么的

**教材原句**：通过 **SNMP 协议**可以获得**网络每秒传输的数据量和差错率**，**发现并解决网络故障**，方便地**监视网络当前的运行状态**。

**本任务内容**：介绍 SNMP 的**管理模型**及**实现过程**。

**一句话定位**：SNMP 就是网管员用来"**远程问设备要数据**"的那套规则——问的是**流量和差错率**，目的是**发现故障、监视状态**。

### 2.SNMP 的准确定位（必考）

**教材原句**：简单网络管理协议（**Simple Network Management Protocol，SNMP**）是在 **TCP/IP 网络参考模型**中，为实现网络管理而开发的**应用层协议**。它建立在 **TCP/IP 传输层的 UDP 协议**之上，提供的是**不可靠的无连接服务**，以保证信息的**快速传递**和**减少对带宽的消耗**。

**逐句拆解**：

| 关键点 | 内容 | 为什么这样设计 |
|---|---|---|
| **所属体系** | TCP/IP 参考模型 | 与 OSI 的"网络管理系统规程"并列，二者是两套体系 |
| **所在层次** | **应用层** | 注意：是应用层协议，不是传输层 |
| **下层依赖** | **UDP**（传输层） | 不是 TCP |
| **服务性质** | **不可靠、无连接** | 网管数据丢一两个不影响判断，下次轮询还会再来 |
| **设计目的** | **快速传递 + 减少带宽消耗** | 网管本身不能把网络带宽吃掉 |

**易错点提醒**：

- 问"SNMP 工作在哪一层"→ **应用层**。
- 问"SNMP 基于哪个传输层协议"→ **UDP**。
- 问"SNMP 是否可靠"→ **不可靠**，因为 UDP 无连接、不保证送达。
- 不要把 SNMP 和 **SMTP**（邮件）、**SNMP 与 ICMP** 混——ICMP 是**网络层**，SNMP 是**应用层**。

### 3.SNMP 管理模型的三个部分（重点）

**教材原句**：SNMP 管理模型可以分成**三大部分**，分别是**网络管理系统、被管理系统和网管协议**。

**结构示意（文字版）**：

```text
        ┌─────────────────┐   SNMP 协议（PDU）   ┌─────────────────┐
        │  网络管理系统    │ ←─────────────────→ │    被管理系统    │
        │  NMS（管理者）   │      UDP / IP       │  设备 + 代理     │
        └─────────────────┘                     └─────────────────┘
                 ↑                                      ↑
             网管工作站                              MIB（被管对象库）
```

#### （1）网络管理系统（NMS）

- **形态**：通常是在网络中选定的**某个工作站**中装载**网管软件**，该工作站即成为**网管工作站**。
- **管理者驻留**：网管软件中的**管理者**驻留在**网管站点**上。
- **通信方式**：经过**操作原语**向上与**网管应用软件**通信；向下经 **UDP/IP 及物理网**与被管理系统通信。
- **人机界面**：网络管理系统为用户（网管员）提供**人机界面（GUI）**。
- **网管员通过 GUI 能做什么**：**监视网络活动、进行配置、性能调整、故障诊断及排除、进行计费管理**等。

**注意**：NMS 与"管理者（Manager）"不是同一个概念——**NMS 是系统**，**管理者是 NMS 中驻留的软件实体**。

#### （2）被管理系统

- **范围**：被管理的、**所有网络上的设备**，包括**主机、网络适配器（网卡）、集线器、交换机、路由器、网桥、通信服务器**等。
- **分布特点**：这些设备分布在**不同的地理位置**。
- **代理（Agent）**：在各个**可管理的网络设备**中都有一个管理软件，称为**代理**。
- **代理的四项职责（教材原句拆解）**：

| 职责 | 具体内容 |
|---|---|
| ① **自身管理** | 实现对被管设备的**自身管理** |
| ② **监测** | 监测**所在网络设备**及其**周围的局部网络**的工作状况，**收集**网络的有关信息 |
| ③ **响应询问** | 响应网络管理系统中来自管理员的**定期询问**，接收管理者**设置某个变量的指令** |
| ④ **主动报警** | 在某些**紧急事件**发生时**主动**向网络管理系统发出**报警** |

**代理与 NMS 的分工一句话**：**NMS 主动问（轮询），Agent 被动答 + 紧急时主动喊**。

#### （3）SNMP 网管协议

- **作用**：网管协议定义了**管理者和代理之间的通信方法**。
- **PDU**：二者间通信的消息单元称为**协议数据单元（Protocol Data Unit，PDU）**。
- **数量（必考）**：在 **SNMP 2.0** 中共有 **7 种 PDU**。
- **通信关系**：被管理设备和 NMS 间**通过网络管理协议相互通信**。
- **被管设备的状态信息主要包括**（教材列举）：

1. **虚电路的状态和数量**；
2. 接收到**特定类型的错误信息**的数据；
3. **出入设备的报文数和字节数**；
4. **最大的输出队列长度**（对于路由器和其他网络互联设备）；
5. **发送和接收到的广播信息**；
6. **活动和不活动的网络接口**等。

**6 项状态信息记忆线索**：**连接（虚电路）→ 差错 → 流量（报文/字节）→ 队列 → 广播 → 接口**。

### 4.管理信息库（MIB）（重点）

**总述**：所有的**被管理对象**均包含在**管理信息库（Management Information Base，MIB）**中。

**（1）组织结构**：

- MIB 以"**树**"型结构进行组织，其**树叶**为**不同的数据项**。
- 在该树中，**对象标识符**唯一标识了 MIB 的目标。
- **对象标识符是分级结构**，不同部分由**不同的机构**来分配。

**（2）教材的"电话号码"比喻**：

| 电话号 | 对应 MIB |
|---|---|
| 国际电话号码 = **国家号 + 国内号码** | 顶级 MIB 对象标识由 **ISO/国际电工联盟**分配 |
| 国内号码由**各国自己确定**（中国 = 区号 + 本地号码） | 低级对象标识由**相关机构**分配 |
| 某个单位可能还有**分机号** | 更低层的对象标识继续向下细分 |

**结论**：**顶级由 ISO/国际电工联盟分配，低级由相关机构分配**——这种分级分配保证了**全球唯一**。

**（3）代理与 MIB 的关系**：

- **每个网络代理包含一个 MIB**。
- 在 MIB 中保存所有网络设备的**各种配置信息和状态信息**。
- 代理**接受上层管理者的请求并予以响应**，**读取或修改** MIB 中相应的变量值，检测本网设置和本网状态，在**特殊事件**发生时**发出报警报文**。

**（4）NMS 采用"轮询"管理整个网络**：

- 网络管理系统采用**轮询**的方法管理整个网络上的网络设备。
- 在访问某个网络设备时，管理者经该设备上的 **Agent** 访问相应的 **MIB**，可获取该设备**所有类型的变量值**，即该设备的**所有信息内容**。
- NMS 通过轮询访问**全部**网络设备，获取所有 MIB 的内容，对全部内容进行**统计、综合智能分析**，从而实现对整个网络的管理。

**三层数据流一句话**：**NMS 轮询 → Agent 读写 → MIB 提供变量值**。

**为什么说"SNMP 是基于 MIB 的管理"**：SNMP 本身只负责**传 PDU**，真正被管理的东西（配置、状态）全存在 **MIB 的变量**里——所以知识目标第 4 条写的是"理解 SNMP 是**基于管理信息库**的管理过程"。

### 5.网络管理平台

**（1）为什么需要平台**：

- 大型网络常常含有**多个厂商**的设备，网络设备的**种类和数量也很多**，包括台式设备、网络设备以及各种 **WAN** 的通信设备。
- 每个厂商都开发了**自己特有的**网络管理系统和网络应用程序。
- 如何将各应用系统统一为**一个整体的、有机结合的应用系统**，需要有一套**标准和方法**，因此就产生了**开放的、统一的网络管理平台**。

**（2）平台的三项能力**：

| 能力 | 具体说明 |
|---|---|
| **① 统一的标准应用程序接口（API）** | 平台**向上**为各类专用网管应用程序提供**统一的标准 API**；各厂商的专用网管程序经 **API 及平台**可直接管理各自的设备；不同的网管应用程序可利用平台资源得到**集成和统一**，并获得**更高层次的统一管理方案** |
| **② 共享图形用户界面** | 网管平台能支持各种专用应用系统**共享平台提供的 GUI** |
| **③ 创建和维护数据库** | 通过对 **SNMP 各代理的轮询**以及**接收代理发来的报文**，创建和维护各种类型的数据库；内容可包含网络设备的**设置、状态、对象标志符、对象名称、IP 地址、网络拓扑结构图**等，还包括**注册时间**在内的各种事件、**网络通信状态及历史通信量**等记录；此外还能利用**图形工具**为用户界面显示**网络拓扑结构图** |

**（3）纵向 vs 横向（教材最精彩的一句）**：

各厂商的网管软件只是针对其**特定的网络设备**进行**纵向管理**。网管平台能与被管设备通信、访问 MIB，形成**综合数据库**；各厂商的专用网管软件经 **API** 进入平台进行**横向交互配合**，并利用平台提供的**数据库、图形工具和资源**集成一个**更高层的统一管理方案**。

| 对比 | 纵向管理 | 横向配合 |
|---|---|---|
| 谁做的 | **各厂商的专用网管软件** | **网管平台** |
| 管什么 | 只管**自己家的设备** | 跨厂商、跨系统**统一** |
| 手段 | 私有协议/私有界面 | **标准 API + 综合数据库 + 图形工具** |

### 6.网络管理新技术（四个方向）

**背景**：随着网络互联技术飞速发展和广泛应用，人们的工作和生活越来越依赖于信息网络。计算机网络**正常、高效、安全、可靠**地运行将是确保未来社会正常高效运作的**基本前提**。因此人们对网络管理提出了**更高要求**，网络管理技术自身也在不断发展。

目前计算机网络管理技术的发展主要表现在以下**四个方面**：

**（1）必须走分布式管理的道路**

传统**集中式**的网络管理模式在网络规模**急剧膨胀**的现实面前已显得**越来越力不从心**，网络管理**必须走分布式管理的道路**。

**（2）基于 CORBA 的分布式网络管理**

**公共对象请求代理体系结构（Common Object Request Broker Architecture，CORBA）**为分布式的网络管理提供了**有益的启示**；基于 CORBA 的分布式网络管理是一条**现实可行的、可实现多域交叉管理**的方案。

**（3）基于 Web 的网络管理**

**Web 技术的出现**为创建一个**平台独立的通用网络管理系统**提供了一条**新的解决途径**；基于 Web 的网络管理技术的一个**先天优势**是可以**很容易地实现分布式的网络监视和控制**。

**（4）向标准化、智能化、综合化发展**

网络管理的另一个趋势是向**标准化、智能化、综合化**的网络管理方向发展。

**四个方向速记**：**分布式（必然趋势）→ CORBA（多域交叉）→ Web（平台独立、易分布式）→ 标准/智能/综合（总趋势）**。
