任务三 网络管理工具

知识点​

1.任务描述：为什么要用工具​

教材原句：随着网络规模的不断扩大及网络应用的不断发展，所使用的网络设备的数量和种类也越来越多。为了满足网络管理的要求，可网管网络设备开始在网络中使用，使用可网管网络设备能够使网络功能发挥到最大，并最大限度地保证网络的安全。

网络管理工具（或软件）的定义：协助网络管理人员对网络进行监视和控制以及维护网络运行的硬件和软件设施。

本任务内容：介绍一些实际网络管理中常见的网络管理工具。

2.四大类工具全景（先建框架）​

类别干什么典型工具
1. IP 和链路工具判断逻辑链路是否畅通、验证配置arp、ipconfig、ping、netstat、nslookup、hostname、telnet、pathping、tracert、Netdiag
2. 网络分析和诊断工具抓包分析、测吞吐率、测带宽、分析流量、算子网Sniffer Pro、Qcheck、Ping Plotter、IxChariot、Commview、MRTG、IPSubnetter
3. 网络设备管理工具远程登录设备做配置、备份与升级Telnet、超级终端、TFTP、CNA、Cisco Works 2000、ITiMe、ManageEngine
4. 网络维护和恢复工具日常维护、系统重装、备份恢复net、at、NEWT Professional、LANView、组策略命令族、ntbackup、recover、USMT、regback

一句记忆：一类"测通不通"、二类"看数据"、三类"配设备"、四类"护系统"。

3.IP 和链路工具：两类工具别混​

教材原句：IP 协议和 IP 链路工具不仅经常被用于处理网络的连通性问题，而且还被广泛应用于网络安全故障的诊断与排除。

工具类型判断什么举例
硬件测试工具（网络测试仪等）主要用于判断物理链路是否畅通网线测试仪、网络测试仪
IP 链路测试工具（软件命令）用于测试 IP 链路是否正常：交换机、路由器等网络设备的连接、配置是否正确，网卡和网络协议是否正确安装，计算机的 IP 地址信息设置是否正确等——即判断网络逻辑链路是否畅通ping、tracert、ipconfig 等

一句话区分：硬件测"线通不通"，软件测"逻辑通不通"。

TCP/IP 提供的一组诊断和管理命令能干什么：

  • 帮助用户得到 IP 和域名的信息；
  • 帮助用户检测 Internet 的性能；
  • 跟踪并解决 TCP/IP 网络故障。

教材特别说明（易忽略）：需要注意的是，在不同的 Windows 版本下，调试命令是否存在、使用格式可能有所不同，可通过 Help 命令进行查询。下面介绍的 TCP/IP 实用命令均在 DOS 窗口中以命令行方式使用。

4.常用 TCP/IP 命令总览表​

命令主要作用最常用写法
arp显示、删除、添加 IP 地址与 MAC 地址的对应表项arp -a、arp -d *、arp -s IP MAC
ipconfig显示本机网络适配器的物理地址和 IP 地址等配置信息ipconfig、ipconfig /all、ipconfig /release、ipconfig /renew
ping测试与目标主机能否成功交换数据包ping 目标、ping -t 目标
netstat显示 IP、TCP、UDP、ICMP 相关的统计数据与端口连接情况netstat -a、netstat -n、netstat -r
nslookup显示与 DNS 有关的参数信息，排查 DNS 故障nslookup 域名、nslookup IP
hostname显示计算机在当前域中的主机名hostname
telnet测试指定主机的指定端口是否可用telnet 域名 端口
pathping显示中间跃点处的网络滞后和网络丢失信息pathping -n 目标
tracert跟踪路由，确定数据报访问目标所采取的路径tracert -d 目标
NetdiagWindows 支持工具中的网络故障原因诊断工具netdiag

5.arp 命令​

原理：arp 协议完成了 IP 地址到 MAC 地址的转换。为了提高效率，主机在完成转换后，会把 IP 地址及相应的 MAC 地址放入 arp 缓存中。arp 命令就是对缓存中的 IP 地址和 MAC 地址对进行显示、删除、添加等操作。

命令格式举例：

arp -a [inet_addr] [-N if_addr] [-v]
arp -d inet_addr [if_addr]
arp -s inet_addr eth_addr [if_addr]

参数说明：

参数含义
-a通过询问当前协议数据，显示当前 arp 项。如果指定了 inet_addr，则只显示指定计算机的 IP 地址和物理地址。如果不止一个网络接口使用 arp，则显示每个 arp 表的项
-v在详细模式下显示当前 arp 项。所有无效项和环回接口上的项都将显示
inet_addr指定 Internet 地址
-N if_addr显示 if_addr 指定的网络接口的 arp 项
-d删除 inet_addr 指定的主机。inet_addr 可以是通配符 *，以删除所有主机
-s添加主机，并把 Internet 地址 inet_addr 与物理地址 eth_addr 相关联。物理地址是用连字符分隔的 6 个十六进制字节；该项是永久的
eth_addr指定物理地址
if_addr如果存在，指定地址转换表应修改的接口的 Internet 地址；不存在则使用第一个适用的接口

三个示例（教材原例）：

输入效果
arp -a显示当前的 IP 地址与 MAC 地址对应表
arp -d *删除当前 IP 地址与 MAC 地址对应表的所有表项
arp -s 111.55.85.212 00-aa-00-62-c6-09添加 IP 地址与 MAC 地址的对应关系

考点：arp -s 添加的是静态（永久）表项；arp -d 支持通配符 *。

6.ipconfig 命令​

定义：内置于 Windows 的 TCP/IP 应用程序，用于显示本地计算机网络适配器的物理地址和 IP 地址等配置信息。这些信息一般用来检验 TCP/IP 设置是否正确。

还能做什么：当在网络中使用 DHCP 服务时，ipconfig 可以检测计算机中分配到的 IP 地址是否配置正确，并且可以释放、重新获取 IP 地址——这些信息对网络测试和故障排除有重要作用。

（1）查看网络适配器信息​

命令格式：ipconfig

  • 运行不带参数的 ipconfig，可检测本地所有网络连接的 IP 地址配置信息：IP 地址（IP Address）、子网掩码（Subnet Mask）、默认网关（Default Gateway），同时也包括 ADSL 信息，使用户了解 ADSL 租用了哪个 IP 地址。
  • 有时网管员需要得到网卡的 MAC 地址，用于 MAC 地址绑定、远程管理等，可用 ipconfig /all 实现：
    • 其中 Physical Address 部分就是由"-"分隔的 6 组 16 进制数表示的 MAC 地址；
    • 同时显示该网卡的其他信息：网卡类型描述（Description）、是否启用了 DHCP（Dhcp Enabled）以及 IP 地址配置信息等；
    • 在 Windows IP Configuration 区域中，显示**主机名（Host Name）、主 DNS 后缀（Primary Dns Suffix）、节点类型（Node Type）、是否开启了 IP 路由（IP Routing Enabled）、是否开启了 WINS 代理（WINS Proxy Enabled）**等。

（2）显示所有网络参数​

命令格式：ipconfig /all

显示本机每一个 IP 网络接口的信息：DNS 域名、DNS 服务器的 IP 地址、网卡物理地址、网络接口的 IP 地址以及 DHCP 等信息。

（3）释放原 IP 地址，重新获取 IP 地址​

命令格式：

ipconfig /release
ipconfig /renew

适用场景（教材原句）：

  • 如果网络中使用了 DHCP 服务，客户端计算机就可以自动获得 IP 地址；
  • 但有时因 DHCP 服务器或网络故障等原因，一些客户端计算机不能正常获得 IP 地址，此时系统会自动为网卡分配一个形如 169.254.x.x 的 IP 地址；
  • 或者有些计算机 IP 地址的租约到期，需要更新或重新获得 IP 地址。

做法：先用 ipconfig /release 释放原来的 IP 地址，再用 ipconfig /renew 重新获得一个新的 IP 地址。

考点提示：看到 169.254.x.x 就应想到"没有从 DHCP 拿到地址"，这是 APIPA 自动私有地址，只能与本网段通信、不能上网。

7.ping 命令（最常用，必掌握）​

主要功能：确定本地主机是否能与另一台主机成功交换（发送与接收）数据包。它根据返回的信息，就可以推断 TCP/IP 参数是否设置正确、运行是否正常和网络是否通畅等。

命令格式：

ping [-t] [-a] [-n count] [-l size] [-f] [-i TTL] [-v TOS] [-r count] [-s count]
     [-j host-list] [-k host-list] [-w timeout] [-R] [-S srcaddr] [-4] [-6] target_name

参数说明（教材全表）：

参数含义
-tPing 指定的主机，直到停止；若要查看统计信息并继续操作，请键入 Control-Break；若要停止，请键入 Control-C
-a将地址解析成主机名
-n count要发送的回显请求数
-l size发送缓冲区大小
-f在数据包中设置"不分段"标志（仅适用于 IPv4）
-i TTL生存时间（TTL）
-v TOS服务类型（仅适用于 IPv4）；该设置已不赞成使用，且对 IP 标头中的服务字段类型没有任何影响
-r count记录计数跃点的路由（仅适用于 IPv4）
-s count计数跃点的时间戳（仅适用于 IPv4）
-j host-list与主机列表一起的松散源路由（仅适用于 IPv4）
-k host-list与主机列表一起的严格源路由（仅适用于 IPv4）
-w timeout等待每次回复的超时时间（毫秒）
-R同样使用路由标头测试反向路由（仅适用于 IPv6）
-S srcaddr要使用的源地址
-4强制使用 IPv4，为默认值
-6强制使用 IPv6

工作原理：Ping 命令在执行过程中，通过将 ICMP 数据包发送到目标计算机并侦听应答数据包来验证与目标计算机的连接。每个发送的数据包最多等待一秒，显示已传输和接收的数据包数。

默认行为（必记）：默认情况下，传输四个包含 32 个字节的 ICMP 数据包；Ping 能以毫秒为单位显示发送请求到返回应答之间的时间量。

从结果看什么：

现象说明
应答时间短数据报不必通过太多路由器或网络，连接速度比较快
TTL 值可以通过 TTL 值推算数据包经过了多少个路由器
4 条消息目标主机当前在线并可以访问，也表示 DNS 工作正常

教材实例：在 DOS 窗口命令行输入 ping www.sohu.com，如果收到如图 10-1 所示的 4 条消息，既说明目标主机当前在线并可以访问，也表示 DNS 工作正常。

重要提醒（教材原句）：

  • Ping 成功并不一定就代表 TCP/IP 配置正确——有可能还要执行大量的本地主机与远程主机的数据包交换，才能确保 TCP/IP 配置的正确性；
  • 如果执行 Ping 成功而网络仍无法使用，那问题很可能出在网络系统的软件配置方面——Ping 成功只保证当前主机与目标主机间存在一条连通的物理路径。

ping 的三大测试场景​

① 测试网卡

  • 使用 ping 本地IP地址 或 ping 127.0.0.1 进行测试。
  • 是否安装了网卡：成功说明网卡没有问题；不成功说明网卡驱动程序或 TCP/IP 没有正常安装。可在"控制面板 → 设备管理器 → 网络适配器"中查看网卡是否有一个黄色的"!"，如有需重新安装驱动程序。
  • 是否安装了 TCP/IP：成功说明网卡 TCP/IP 没有问题；不成功且网卡驱动正常，则应从"控制面板 → 网络连接"查看是否安装了 TCP/IP；如未安装，安装并正确配置后重启计算机再次测试。
  • 是否配置了 IP 地址和子网掩码：如果 ping 127.0.0.1 成功、但 ping 本地 IP 地址不成功，说明没有正确配置 IP 地址，应在"本地连接"属性中检查并重新配置。

② 测试局域网连接

  • 通过 Ping 局域网内其他计算机、服务器的计算机名或 IP 地址，可测试**同一网络（或 VLAN）**的连接是否正常，检测 IP 地址和子网掩码设置是否正确。
  • Ping 不通时：先查 IP 地址与子网掩码；若设置成功仍不通，应对网络设备和通信介质逐段测试、检查和排除。

③ 测试与远程主机的连接

  • 通过 Ping 远程主机的 IP 地址或域名，判断网络中的故障，确认能否连接 Internet。
  • 不能浏览网页时先 Ping 网站域名：
    • 能 Ping 通 → 计算机与 Internet 连接正常，需检查本地 DNS 或系统故障；
    • 不能 Ping 通 → 可能是对方网站没有运行，或本地计算机根本不能连接 Internet，需检查本地网关或服务器故障，确认 DNS 服务器设置是否正常；
    • 能 Ping 通 Internet 上的 IP 地址但打不开网页 → 可能是 DNS 服务器设置有问题，需 Ping 本地 DNS 服务器并在属性中检查 DNS 设置；
    • 与任何主机连接都超时或丢包率非常高 → 应与 ISP 共同检查 Internet 连接，包括线路、Modem 和路由器等多方面设置。

说明（教材原句）：如果目标主机不存在或当前不在线，另外如果目标主机出于安全性的考虑设置为屏蔽 ICMP 信息，则 ping 命令将返回"请求超时""目标无法到达"等类似消息。

三个测试场景一句话记忆：先测自己（127.0.0.1）→ 再测邻居（局域网）→ 最后测远方（Internet + DNS）。

8.netstat 命令​

功能：netstat 作为 Windows 内置的一个工具拥有强大的功能，可用于显示与 IP、TCP、UDP 和 ICMP 协议相关的统计数据，一般用于检验本机各端口的网络连接情况。

命令格式：

netstat [-a] [-b] [-e] [-f] [-n] [-o] [-p protol] [-r] [-s] [-t] [interval]

参数说明：

参数含义
-a显示所有连接和侦听端口，用于确认哪些 TCP/IP 服务进程处于活动状态，以及哪些 TCP 连接是可用的
-b显示在创建每个连接或侦听端口时涉及的可执行程序。若已知可执行程序承载多个独立组件，则显示组件序列：可执行程序名称显示在底部，它调用的组件位于顶部。注意该选项可能很耗时，且在当前用户权限不足时可能失败
-e获取网卡的状态信息，如发送分组、接收分组和错误分组的数量等；此选项可以与 -s 结合使用
-f显示外部地址的完全限定域名
-n以数字形式显示地址和端口号
-o显示拥有的与每个连接关联的进程 ID
-p protol显示 protol 指定的协议的连接；protol 可以是 TCP、UDP、TCPv6、UDPv6。若与 -s 一起用则显示每个协议的统计，此时 protol 可以是 IP、IPv6、ICMP、ICMPv6、TCP、TCPv6、UDP、UDPv6
-r显示当前主机的路由表
-s显示每个协议数据包的统计；默认显示 IP、IPv6、ICMP、ICMPv6、TCP、TCPv6、UDP、UDPv6 的统计
-t显示当前连接卸载状态
[interval]用于重新显示选定的统计，指定各个显示类型之间暂停的秒数；省略则显示当前的配置信息

示例输出（教材原例，netstat -n）：

协议本地地址外部地址状态
TCP192.168.1.150:1062112.80.180.72:8080ESTABLISHED
TCP192.168.1.150:1205220.194.116.116:443CLOSE_WAIT
TCP192.168.1.150:3211172.217.163.42:443SYN_SENT

读法（教材原话）：

  • 本机 1062 端口与 112.80.180.72:8080 目前处于可靠连接状态；
  • 1205 端口与 220.194.116.116:443 处于连接终止的等待阶段；
  • 3211 端口与 172.217.163.42:443 处于请求连接阶段。

三种状态对照（讲课补充，便于理解）：

状态含义
ESTABLISHED连接已建立，双方可以收发数据
CLOSE_WAIT对方已发 FIN，本机等待关闭（被动关闭方）
SYN_SENT已发出 SYN，等待对方回应（连接请求阶段）

考点：要查"本机开了哪些端口、和谁连着"→ netstat -a；要查"是哪个程序占的端口"→ netstat -b（或 -o 看 PID）；要查"路由表"→ netstat -r。

12.pathping 命令​

功能：Pathping 工具提供有关在源和目标之间的中间跃点处网络滞后和网络丢失的信息。

工作过程（教材原句拆解）：

  1. Pathping 在一段时间内将多个回响消息发送到源和目标之间的各个路由器，然后根据各个路由器返回的数据包计算结果；
  2. 因为 Pathping 可以表示在任何特定路由器或连接处的数据包的丢失程度，所以用户可据此确定可能存在网络问题的路由器或子网；
  3. Pathping 通过识别路径上的路由器来执行与 Tracert 命令相同的功能；
  4. 然后该命令在一段指定的时间内定期将 Ping 命令发送到所有的路由器，并根据每个路由器的返回数值计算统计结果。

命令格式：

pathping [-g host-list] [-h maximum_hops] [-i address] [-n] [-p period]
         [-q num_queries] [-w timeout] [-4] [-6] target_name

参数说明：

参数含义
-g host-list与主机列表一起的松散源路由
-h maximum_hops搜索目标的最大跃点数
-i address使用指定的源地址
-n不将地址解析成主机名
-p period两次 Ping 之间等待的时间（毫秒）
-q num_queries每个跃点的查询数
-w timeout每次回复等待的超时时间（毫秒）
-4 / -6强制使用 IPv4 / IPv6

示例：pathping -n www.163.com，输出先显示"通过最多 30 个跃点跟踪到 www.163.com [220.194.234.254] 的路由"，列出 0 10.1.37.166、1 10.1.37.254 等跃点，再"正在计算统计信息，已耗时 25 秒……"，最后给出各跃点的 RTT / 已丢失 / 发送 = Pct 统计，并以"跟踪完成"结束。

pathping 与 tracert 的区别（重点）：

对比tracertpathping
主要输出路径（经过哪些路由器）路径 + 每个跃点的丢包率与延迟统计
耗时短长（要在一段时间内反复 Ping 每个路由器）
用途判断"走哪条路"判断"在哪一跳开始丢包/变慢"

13.tracert 命令​

功能：**Tracert（跟踪路由）**是路由跟踪实用程序，用于确定 IP 数据报访问目标所采取的路径。Tracert 命令用 IP 生存时间（TTL）字段和 ICMP 错误消息来确定从一个主机到网络上其他主机的路由。

工作原理（逐句拆解，必考）：

  1. Tracert 通过向目标发送不同 IP 生存时间值的 ICMP 回应数据包，确定到目标所采取的路由；
  2. 要求路径上的每个路由器在转发数据包之前至少将数据包上的 TTL 递减 1；
  3. 数据包上的 TTL 减为 0 时，路由器应将"ICMP 已超时"的消息发回源系统；
  4. Tracert 先发送 TTL 为 1 的回应数据包，并在随后的每次发送过程中将 TTL 递增 1，直到目标响应或 TTL 达到最大值，从而确定路由；
  5. 通过检查中间路由器发回的"ICMP 已超时"消息确定路由；
  6. 某些路由器不经询问直接丢弃 TTL 过期的数据包，这在 Tracert 实用程序中看不到；
  7. Tracert 命令按顺序打印出返回"ICMP 已超时"消息的路径中的近端路由器接口列表；
  8. 如果使用 -d 选项，则 Tracert 不在每个 IP 地址上查询 DNS。

命令格式：

tracert [-d] [-h maximum_hops] [-j host-list] [-w timeout] [-R] [-S srcaddr]
        [-4] [-6] target_name

参数说明：

参数含义
-d不将地址解析成主机名
-h maximum_hops搜索目标的最大跃点数
-j host-list与主机列表一起的松散源路由（仅适用于 IPv4）
-w timeout等待每个回复的超时时间（毫秒）
-R跟踪往返行程路径（仅适用于 IPv6）
-S srcaddr要使用的源地址（仅适用于 IPv6）
-4 / -6强制使用 IPv4 / IPv6

成功示例：数据包必须通过两个路由器（10.0.0.1 和 192.168.0.1）才能到达主机 172.16.0.99；主机默认网关是 10.0.0.1，192.168.0.0 网络上路由器的 IP 是 192.168.0.1。输入 tracert -d 172.16.0.99，输出：

Tracing route to 172.16.0.99 over a maximum of 30 hops
  1    2s    3s    2s   10.0.0.1
  2   75ms   83ms   88ms 192.168.0.1
  3   73ms   79ms   93ms 172.16.0.99
Trace complete.

失败示例（教材原例，很有价值）：目标 192.168.10.99 没有有效路径（这可能是路由器配置的问题，或者 192.168.10.0 网络不存在）：

tracert 192.168.10.99
Tracing route to 192.168.10.99 over a maximum of 30 hops
  1  10.0.0.1  reports: Destination net unreachable.
Trace complete.

判读要点：看到"Destination net unreachable"且在第一跳就返回，说明本地网关不知道该网段怎么走——查路由或确认网段是否存在。

tracert 里的"*"是什么意思：某一跳显示 * * *，表示该路由器没有回应 ICMP 超时消息（被过滤或直接丢弃），不代表网络断了。

15.网络分析和诊断工具​

总述：借助网络分析工具，可以对网络中传输的数据进行有效的捕捉和分析，从而发现可能的威胁，迅速判断故障的根源。

为什么必须做网络性能测试：优质、高效的网络性能是网络布线系统和网络设备系统所追求的最终目标，所有网络规划、设计、配置都是围绕着网络性能而展开的。因此网络搭建完成后，都必须进行网络性能测试，以验证：

  • 拓扑结构的设计是否合理；
  • 网络设备的连接与配置是否正确；
  • 路由设备和交换设备的性能是否满足需要。

下面几个软件工具都是免费软件，可以从互联网下载使用。

16.网络设备管理工具​

总述：最常用的网络设备管理方式就是远程登录，即由接入网络的计算机借助某些软件远程登录到网络设备中，并作相应的配置。

（1）Windows 设备管理工具​

Windows 集成了许多有价值的应用程序。除"超级终端"外，Telnet 也经常被用于实现对网络设备（可网管的交换机、路由器、防火墙等）的远程管理；此外，借助 Windows Support Tools 中的 Device Console Utility，还可实现对服务器硬件设备的管理。

① 远程设备登录 Telnet

  • Telnet 是包含在 TCP/IP 协议中的一项网络服务，用户无需安装，只要安装了 TCP/IP 协议即可直接运行。
  • 利用 Telnet 为虚拟终端提供一个标准的端口，用户不必了解终端设备的详细信息即可建立连接。
  • 另外，Telnet 还为用户和终端设备提供一个协商选项的机制和一组标准选项。
  • 应用范围：目前大多数网络设备的管理和配置都是通过这种方式进行的，如网络服务器的更新、路由器的配置、网络防火墙的配置等。

② 设备管理控制台——超级终端

  • 作用与 Telnet 基本相同，但区别在于：Telnet 只适用于一个远程设备的连接，而超级终端还可以通过串行口连接至可网管设备的 Console 端口进行配置。
  • 重要顺序（考点）：事实上，设备在可远程 Telnet 管理之前，必须借助超级终端完成其 IP 地址、用户名和密码等的基本配置。

（2）网络配置管理工具​

  • 为什么需要：网络建成后，经过一段时期的运行，特别是升级、改造和扩展之后，拓扑结构可能受到影响。能迅速了解拓扑结构、调整设备间连接，以获取最大的网络带宽和性能就显得尤其重要。另外，随着可网管设备日益增加，设备配置的备份和恢复、设备映像文件的备份和升级，也成为保障网络正常运行和网络安全的必要手段。
  • 为什么多由厂商提供：由于网络配置管理工具需要与设备进行有效通信以获取设备的各种信息，所以这类软件大都由设备的生产厂商开发、提供。

① 简单文件传输协议服务器 TFTP

  • 全称：Trivial File Transfer Protocol，TFTP。
  • 定位：TCP/IP 中用来在客户机与服务器之间进行简单文件传输的协议，提供不复杂、开销不大的文件传输服务。
  • 下层：它基于 UDP 协议而实现，是专门为进行小文件传输而设计的协议。
  • 用途（考点）：TFTP 服务器可实现交换机或交换机软件系统的保存和升级、配置文件的保存和下载，使得对交换机的管理变得简单和快捷。因此在进行交换机的管理前，应先安装一台 TFTP 服务器。
  • 常见软件：Cisco TFTP Server、华为 TFTP Server 等。

② Cisco 网络助手（Cisco Network Assistant，CNA）

  • 定位：一个基于 PC 的网络管理应用，适用于用户数不超过 250 人的有线或无线局域网。
  • 技术：通过采用 Cisco Smartports 技术，思科网络助手能够简化思科网络设备的配置、部署以及日常管理和维护。
  • 界面与能力：借助一个用户友好型 GUI，提供集中网络视图；使网管员能方便地使用通用服务、生成状态报告、实现密码同步，并且远程启动思科交换机、路由器和接入点的其他设备。

（3）企业网络管理工具​

  • 企业网的特点：一般由各部门的局域网组成，管理时需要管控全体或局部用户的上网行为，需要进行统一的防病毒、防黑客部署，能够调控网络带宽、隔离部分网络用户等，其管理难度要增大许多。
  • 代表软件：Cisco Works 2000、ITiMe、ManageEngine 等。

（2）系统维护工具​

前提：在维护过程中，服务器安装网络操作系统后，应及时安装相关网络服务。在日常管理维护过程中，应经常进行相关数据的备份，以便在系统重装或数据恢复时，迅速复原系统设置和网络服务，减少停机/停服务时间，提高网络服务的有效性。

① 计算机工作计划的制定 at

  • 用途：用于制定计划，以便系统按照该计划指定的日期和时间启动及运行计算机上的命令、程序。
  • 前提：at 命令只能在"计划"服务运行时使用；在没有参数的情况下使用，则列出已计划的命令。
  • 命令格式 1：at [\\computername] [[id] [/delete] | /delete [/yes]]
  • 命令格式 2：at [\\computername] time [/interactive] [/every:date[,...] | /next:date[,...]] "command"
参数含义
\computername指定远程计算机；省略则在本地运行
id指定给已计划命令的识别号
/delete删除某个已计划的命令；省略 id 则所有已计划的命令都会被删除
/yes需要进一步确认时均默认为 yes，与删除所有计划命令一起使用
time指定运行计划命令的时间
/interactive允许计划命令在运行时与当时登录的用户桌面进行交互
/every:date[,...]指定在每周（或每月）的特定日期运行计划命令；省略日期则默认在每月的当前日运行
/next:date[,...]指定在下一个指定日期运行命令；省略日期则默认在每月的当前日运行
"command"准备运行的 Windows 命令或程序

② 网络信息收集、管理工具 NEWT Professional

  • 网管员需要掌握网络内计算机的详细情况：计算机名、IP 地址、MAC 地址、操作系统信息，甚至 CPU 速度/数量、日期和时间、计算机运行时间、用户名、逻辑组名等，就可以使用 NEWT Professional。
  • 该软件是一个共享软件，可以通过互联网下载使用。

③ 客户端信息搜集工具 Jxdev LANView

  • 可以快速收集网络内所有客户端的信息：IP 地址、MAC 地址、共享资源、机器名、用户和组名称；
  • 也可以方便地对网络内的数据包进行捕获和分析；
  • 另外也可用于检测本地主机并获取如 IP 统计、IP 流量、网络连接、Winsock 状态等信息。

④ 组策略与活动目录相关命令（一组命令，按"还原—编辑—安装—查看—刷新"记）

命令功能
dcgpofix组策略管理命令，可以将默认组策略对象还原到它们的原始状态；必须是网络管理员才有权限使用
gpedit.msc本机的组策略管理，可在 DOS 窗口中运行，打开组策略管理器进行调整
dcpromo安装/卸载活动目录：启动活动目录向导，或实现无人活动目录安装，及活动目录的删除
gpresult组策略查看命令：显示用户或计算机的组策略设置和策略的结果集（RSOP）
gpupdate组策略刷新命令：刷新本地组策略设置和存储在活动目录中的组策略设置，包括安全设置

⑤ 备份与恢复类命令

命令功能备注
ntbackup系统状态备份：在命令提示符下执行系统备份操作Windows 自带备份工具
recover磁盘数据恢复：从损坏的磁盘中尽可能恢复可读取的信息不是"撤销删除"，是抢救坏盘
USMT用户状态迁移工具：对用户进行状态迁移和设置默认不随操作系统安装；需把安装盘的 \VALUEADD\MSFT\USMT 文件夹下所有文件复制后运行相应程序
regback注册表备份工具：在系统运行期间对注册表进行备份默认不随操作系统安装，需从安装盘上查找、运行使用

18.任务实施​

  1. 启动计算机，在搜索工具中以"网络管理工具"为关键词进行搜索。
  2. 浏览搜索结果中关于 Ping 命令使用方法的叙述。
  3. 搜索关于 ipconfig 命令使用方法及主要参数的叙述。
  4. 检索在进行网络管理使用 Ping 命令时应注意的访问顺序。
  5. 按照《计算机网络基础综合模拟实训》中"项目十六 TCP/IP 协议常用网络工具的使用"的方法与步骤，使用命令进行网络管理工作。

19.速查表​

序号考点结论
1网络管理工具的分类IP 和链路工具、网络分析和诊断工具、网络设备管理工具、网络维护和恢复工具
2硬件测试仪测什么物理链路是否畅通
3IP 链路工具测什么逻辑链路是否畅通（设备连接与配置、网卡与协议、IP 地址设置）
4arp 的作用显示/删除/添加 IP 与 MAC 的对应表
5arp 加静态项arp -s IP MAC，永久项；arp -d * 清空所有
6ipconfig 不带参数显示 IP 地址、子网掩码、默认网关（含 ADSL 信息）
7看 MAC 地址ipconfig /all 的 Physical Address
8169.254.x.x 说明没有从 DHCP 获得地址（自动专用地址）
9释放/续租 IPipconfig /release → ipconfig /renew
10ping 的协议ICMP
11ping 默认发几个包4 个，每个 32 字节
12ping 停止键Control-C（查看统计继续用 Control-Break）
13ping 127.0.0.1 的作用测网卡与 TCP/IP 是否正常
14ping 成功但上不了网问题多在软件配置（如 DNS）
15能 ping 通 IP 但打不开网页DNS 服务器设置有问题
16netstat 的作用显示 IP/TCP/UDP/ICMP 统计与端口连接情况
17看路由表netstat -r
18ESTABLISHED / CLOSE_WAIT / SYN_SENT已建立 / 等待关闭 / 请求连接
19nslookup 的作用查 DNS：域名查 IP、IP 查域名
20telnet 的作用测试指定主机的指定端口是否可用
21收到 400 Bad Request 说明端口是通的
22pathping 与 tracert 的差别pathping 多给每跳丢包率与延迟统计
23tracert 的原理用 TTL 递增 + ICMP 超时消息确定路由
24tracert 第一跳就报 Destination net unreachable网关不知道目标网段的路由
25Netdiag 的结果标识Passed / Failed
26Sniffer Pro 的前提网卡设为混杂（promiscuous）模式
27Sniffer 能分析多少协议至少 450 种
28Qcheck 的厂商与套件NetIQ 的 Chariot suite；需两台计算机
29有线/无线带宽测试工具Ping Plotter / IxChariot
30流量分析工具Commview、MRTG
31子网计算工具IPSubnetter（可算不标准子网）
32远程管理设备的两种方式Telnet（网络）与超级终端（Console 串口）
33首次配置必须先用什么超级终端（先配 IP、用户名、密码）
34TFTP 基于什么协议UDP，专为小文件传输设计
35CNA 支持多少人不超过 250 人的局域网
36net 命令自动确认/y；net /? 查所有命令
37at 命令的前提"计划"服务必须运行
38gpresult 输出什么RSOP（策略结果集）
39默认不随系统安装的工具USMT、regback
