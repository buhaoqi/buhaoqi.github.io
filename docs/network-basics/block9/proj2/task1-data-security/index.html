任务一 数据安全

知识点​

1.项目二要学什么？​

项目导读（教材原句拆解）：

  • 数据安全是保护数字信息免遭未经授权的访问、披露、修改或复制的技术；数据安全技术可以保护数据免受意外或故意威胁，并保持数据信息的机密性、完整性和可用性。
  • 网络病毒是一种计算机病毒，也可称为恶意软件（Malware），它可以在执行过程中自我复制，通过修改其他计算机程序或插入病毒代码使其受到感染；网络病毒通过网络快速传播，目的是破坏系统、浪费资源、删除、泄露或窃取数据。
  • 防火墙（Firewall）是一种保障信息安全的设备或软件，依照特定规则允许或禁止传输的数据通过；可以是一台专门的硬件，也可以是运行在硬件上的软件。
  • Windows 防火墙是 Windows 操作系统中系统自带的软件防火墙。

项目二的四个任务地图：

任务内容关键词
任务一 数据安全数据加密、数字信封、数据压缩、数据备份、RAID对称／非对称、公钥私钥
任务二 网络病毒网络病毒的特点与防治基于主机／基于服务器
任务三 黑客攻击黑客与入侵者、攻击目的、攻击过程、攻击手段三阶段、六种工具
任务四 Windows 系统的防火墙启动、功能、入站规则与出站规则三种连接方式

一句话串起四个任务：数据本身要加密备份（任务一）→ 病毒要防（任务二）→ 人要防（任务三）→ 边界要守（任务四）。

2.任务描述：什么是数据安全​

数据安全是指为数据处理系统建立和采用的技术和管理的安全保护，保护计算机硬件、软件和数据不因偶然和恶意的原因遭到破坏、更改和泄露。

手段与目标：通过采用各种技术和管理措施，使网络系统正常运行，从而确保网络数据的可用性、完整性、保密性。

建立网络安全保护措施的目的：确保经过网络传输和交换的数据不会发生增加、修改、丢失和泄露等。

本任务的四块技术：数字加密 → 数字信封 → 数据压缩 → 数据备份（含 RAID）。

3.数据加密的六个基本术语​

数据加密：把原来一个较大范围的人（或计算机）都能够读懂、理解和识别的信息（可以是语音、文字、图像和符号等），通过一定的方法（算法），使之成为一些晦涩难懂的或者偏离信息原意的信息，从而达到保障信息安全的过程。

术语定义记法
明文人或计算机可以直接识读和理解的信息原文，可以是文本、数字化语音流或数字化视频信息
密文通过数据加密的手段，将明文变换成晦涩难懂的信息看不懂的那一串
加密过程将明文转变成密文的过程明文 → 密文
解密过程加密的逆过程，即将密文还原为明文的过程密文 → 明文
密码体制加密和解密过程都是通过特定的算法来实现的，这一算法称为密码体制算法本身
密钥由使用密码体制的用户随机选取的、唯一能控制明文与密文之间进行可逆变换的关键，通常是随机字符串打开算法的"钥匙"

加密与解密必须遵循的一个重要原则：明文与密文的相互变换是可逆变换，并且只存在唯一的、无误差的可逆变换。

一句话区分"体制"和"密钥"：密码体制是公开的算法（锁的构造），密钥是保密的那个随机串（唯一的那把钥匙）。同一把锁配不同的钥匙，安全性就落在钥匙上。

4.对称数据加密技术​

别称：密钥加密、对称加密。

核心：加密和解密过程均采用同一把秘密钥匙（密钥），通信双方都必须具备这把钥匙，并保证这把钥匙不被泄漏。

"分发密钥"：通信双方采用对称加密技术进行通信时，两方必须先约定一个密钥，这种约定密钥的过程称为分发密钥。

完整流程四步：

  1. 双方先约定（分发）密钥；
  2. 发送方用这一密钥 + 合适的加密算法，把明文变为密文；
  3. 密文到达接收方；
  4. 接收方用解密算法（通常是加密算法的逆运算），并把密钥作为算法的一个运算因子，把密文还原为与发送方一致的明文。

按加密的数据形式再分两类：

类型英文做法特点
块加密Block Cipher对一个个定长的数据块进行加密，数据块之间的关系不依赖于加密过程两个数据块内容一样时，加密后得到的密文也完全一样
流加密Stream Cipher对数据流加密，加密过程带有反馈性：前一个字节加密的结果作为后一字节加密的密钥安全性更强

对称加密的主要缺点（教材点明）：加密算法和解密算法通常是公开的，因此保证密钥的安全性非常重要；这种对密钥安全性的过分严格要求，使得分发密钥的过程变得非常困难。→ 这正是非对称加密要解决的问题。

5.非对称数据加密技术​

起点：1976 年美国密码学家 Diffie 和 Hellman 在文章《密码学的新方向》（New Directions in Cryptography）中提出。

公钥密码体制：以公钥密码体制为代表的密码技术称为非对称密码技术，其算法称为公开密钥算法。它的"崭新思想"是——在不降低保密程度的基础上，不仅加密算法本身可以公开，甚至加密用的密钥也可以公开。

密钥对：加密和解密使用一个密码对，一个用于加密，另一个用于解密，分别称为加密密钥和解密密钥，也称为公钥和私钥；它们在数学上彼此关联。

谁公开、谁保密：加密密钥（公钥）可以向外界公开；解密密钥（私钥）由自己保管，必须严格保密。

记忆口诀：公钥是"信箱投递口"（谁都能投），私钥是"信箱钥匙"（只有自己能开）。

6.表 9-2：对称密码技术和非对称密码技术的比较​

项目对称密码技术非对称密码技术
密码个数1 个2 个
算法速度较快较慢
算法对称性对称，解密密钥可从加密密钥中推算出来不对称，解密密钥不能从加密密钥中推算出来
主要应用领域数据的加密和解密对数据进行数字签名、确认、鉴定、密钥管理和数字封装等
典型算法实例DES、Triple-DES、RC2、RC4、IDEA 和 Skipjack 等Diffie-Hellman、RSA、椭圆曲线加密等

读表三条结论（考试高频）：

  1. 看密码个数：1 个 → 对称；2 个 → 非对称。
  2. 看速度：快的是对称（适合加密大量数据），慢的是非对称（适合加密少量数据，如密钥、摘要）。
  3. 看用途：加密数据用对称，签名与密钥管理用非对称。

7.数字信封（本任务重点）​

定义：数字信封是一种综合利用了对称加密技术和非对称加密技术两者的优点进行信息安全传输的技术。它既发挥了对称加密算法速度快、安全性好的优点，又利用了非对称加密算法密钥管理方便的优点。

为什么需要它：只用一个都不行——对称加密快但密钥难分发；非对称加密密钥好分发但速度慢。数字信封就是"用快的加密数据，用慢的保护那把钥匙"。

工作过程（四步）：

  1. 发送方用对称密钥加密信息内容，得到密文；
  2. 发送方把这个对称密钥用接收方的公开密钥加密——这一步加出来的东西就叫数字信封；
  3. 将数字信封和密文一起发送给接收方；
  4. 接收方首先用自己的私有密钥打开数字信封，得到对称密钥；然后用对称密钥解开密文。

两个术语：

术语做法谁能还原
数字信封打包使用对方的公钥将**加密密钥（对称密钥）**进行加密只有对方的私钥才能还原
数字信封拆解使用接收方的私钥将加密过的对称密钥解密接收方自己

图 9-2 的数字信封工作过程（左右两栏对照）：

环节发送方一侧接收方一侧
准备明文 →（对称密钥 + 加密过程）→ 数据密文——
封装密钥对称密钥 →（接收方公钥 + 加密过程）→ 被加密的密钥（数字信封）——
传输两件东西一起走：密文 + 数字信封收到密文 + 数字信封
开信封——数字信封 →（接收方私钥 + 解密过程）→ 取回对称密钥
解密——密文 →（对称密钥 + 解密过程）→ 明文

一句话记住数字信封："里层用对称，外层用非对称；对称钥匙坐进非对称的信封里"。

8.数据压缩​

定义：数据压缩是通过减少计算机中所存储数据或计算机之间通信数据的冗余度，达到增大数据密度，最终减少数据在存储介质或通信媒体中所占空间的一种技术。

理论依据（两个简单特性）：关于将字符串的一种表示方式转化为另一种新的表示方式的理论——新的表示方式包含了相同的信息，但其长度较原来的表示方式应尽可能短。

为什么要压缩：

  • 许多数据处理应用程序需要非常大的存储容量支持，且这类应用数量还在急剧增长；
  • 计算机通信网络剧增，网络上传输的数据量非常大；
  • 结论：压缩需要存储的数据和需要传输的数据，能大大减少存储和通信费用。

常见压缩工具：WinRAR、WinZip、Gzip 等。

9.数据备份​

定义：把文件或数据库从原来存储的地方复制到其他地方的过程。

目的：在设备发生故障或发生其他威胁数据安全的灾害时保护数据，将数据遭受破坏的程度减到最小。

适用对象：拥有大型计算机的网络的日常事务之一；中小型企业系统管理员每天必做的工作之一；个人计算机用户也非常必要（只不过常被忽略）。

按备份数据的特点分三种：

类型做法空间与时间典型场景
完全备份将指定目录下的所有数据都备份到磁盘或磁带等外存设备占用比较大的外存空间，耗费较长的备份时间（因为对不重要的数据也备份）通常只在系统第一次运行时进行一次
增量备份数据有变动或变动达到指定的数值时才备份，且只备份增加的部分占用空间比完全备份小得多Windows 中许多系统软件按此方式，如 DNS 服务器之间、WINS 服务器之间的数据库同步；常常进行
系统备份对整个系统进行备份（系统中同样有许多重要数据）占用空间通常也比较大一般每隔几个月或每隔一年左右进行一次

按存储介质分六种：软盘备份、磁带备份、可移动存储备份、可移动硬盘备份、本机多硬盘备份、网络备份。

三种备份的选择逻辑：第一次全备打底 → 平时只做增量 → 整机隔几个月做一次系统备份。

10.RAID 技术概述​

提出者与时间：美国加州大学伯克利分校的 D. A. Patterson 教授在 1988 年提出。

名称演变：

  • RAID = Redundant Arrays of Inexpensive Disks，直译为"廉价冗余磁盘阵列"，简称"磁盘阵列"；
  • 后来字母 I 被改作 Independent，RAID 就成了"独立冗余磁盘阵列"——只是名称的变化，实质性的内容并没有改变。

技术实质：利用若干台小型硬磁盘驱动器，在控制器协调下按一定的组合条件而形成的一个大容量、响应快、高可靠的存储子系统。

三个好处（因果链）：

  1. 多台驱动器并行工作 → 大大提高了存储容量和数据传输率；
  2. 采用了纠错技术 → 极大地提高了可靠性；
  3. 对应用程序透明 → 无需应用程序为容错做工作。

按工作模式分的级别：RAID0、RAID1、RAID2、RAID3、RAID4、RAID5、RAID6、RAID7、RAID10、RAID53 等（教材只介绍常用的四级）。

11.四种常用 RAID 级别​

（1）RAID0（Data Stripping）——无冗余无校验​

  • 最少磁盘数：至少两个磁盘驱动器。
  • 做法：把数据分成从 512 字节到数兆字节的若干块（数据条带），交替写到磁盘中——第 1 段写到磁盘 1，第 2 段写到磁盘 2，如此下去；到达最后一个磁盘后，就写到磁盘 1 的下一分段。
  • 优点：分割数据把 I/O 负载平均分配到所有驱动器，驱动器可以同时读写，性能显著提高。
  • 缺点：没有数据保护能力，一个磁盘出故障，数据就会丢失。
  • 适用：不适用于对可靠性要求高的关键任务环境；适合视频生产和编辑、图像编辑。

（2）RAID1（Disk Mirror）——镜像磁盘阵列​

  • 做法：每一个磁盘驱动器都有一个镜像磁盘驱动器，镜像盘随时保持与原盘内容一致。
  • 优点：安全性较高，能快速恢复被损坏的数据。
  • 缺点：只有一半的磁盘空间被用来存储数据；为实时保持一致性，控制器负载相当大。
  • 适用：对数据安全性要求很高、且要求能快速恢复被损坏数据的场合。

（3）RAID3——带奇偶校验码的并行传送​

  • 做法：用一个专门的磁盘存放所有校验数据，其余磁盘进行分散数据的读写。
  • 读：只需在数据存储盘中找到相应数据块读取即可。
  • 写：必须计算与该数据块同处一个带区的所有数据块的校验值，并把新值重新写入校验块 → 无形中增加了系统开销。
  • 坏盘时：该盘上所有数据块必须用校验信息重新建立；若要读的数据块正好在坏盘上，必须同时读取同一带区中所有其他数据块，再按校验值重建 → 系统速度减慢。
  • 最大不足：校验盘很容易成为整个系统的瓶颈，经常有大量写入操作时会导致整个 RAID 系统性能下降。
  • 适用：数据密集型环境或单一用户环境，尤其适合访问较长的连续记录，例如数据库和 Web 服务器等。

（4）RAID5——无独立校验盘的奇偶校验磁盘阵列​

  • 做法：把校验块分散到所有的数据盘中；用特殊算法可计算出任何一个带区校验块的存放位置。
  • 优点：任何对校验块的读写操作都会在所有 RAID 磁盘中均衡，从而消除了产生瓶颈的可能；整体性能较为优良，是被广泛应用的一种方案。
  • 最少磁盘数：为了具有 RAID5 级的冗余度，至少需要 3 个磁盘。
  • 适用：I/O 密集、高读／写比率的应用程序，如事务处理等。
  • 实现方式：可通过磁盘阵列控制器硬件实现，也可通过某些网络操作系统软件实现。

共同点（RAID0～RAID5）：不论何时有磁盘损坏，都可以随时拔出损坏的磁盘再插入好的磁盘（需要硬件上的热插拔支持），数据不会受损，失效盘的内容可以很快重建，重建工作由 RAID 硬件或 RAID 软件完成。

RAID0 的"特殊身份"：RAID0 不提供错误校验功能，所以有人说它不是严格意义上的 RAID——这也是 RAID0 被称为 0 级 RAID 的原因。

读表三问（考试最爱）：

  1. 谁没有容错？ 只有 RAID0（因此它"不是严格意义上的 RAID"）。
  2. 谁最"费"容量？ RAID1 只剩 50%（因为是镜像，一份数据存两遍）。
  3. 谁用校验？ RAID3 与 RAID5，可用容量都是 （n−1）/ n；区别在于 RAID3 校验集中在专用盘（易成瓶颈），RAID5 校验分散（无瓶颈）。

13.RAID 的选型（教材结论段）​

为什么服务器一定要 RAID：

  • 当前计算机整个系统的速度瓶颈主要是硬盘；
  • 在普通计算机中磁盘慢一些并不是太严重，但服务器中不允许——服务器必须随时响应来自四面八方的服务请求，这些请求大多与磁盘上的数据有关；
  • 所以服务器的磁盘子系统必须要有很高的输入／输出速率，为了数据安全还要有一定的容错功能。

选型三句：

  1. 要得到高的安全性和最快的恢复速度 → 用 RAID1；
  2. 要在容量、容错和性能上折中 → 用 RAID5；
  3. 大多数数据库服务器的典型配置：操作系统和数据库管理系统所在的磁盘驱动器用 RAID1，数据库的数据文件则存放于 RAID5 的磁盘驱动器上。

为什么这样配：系统盘求稳（坏了好恢复），数据盘求容量与性能平衡。
