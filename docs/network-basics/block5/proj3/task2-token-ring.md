## 知识点

### 1.令牌环技术是怎么来的？

**令牌环介质访问控制技术最早开始于 1969 年贝尔实验室的 Newhall 环网**，最有影响的令牌环网是 **IBM Token Ring**。在 **IEEE 802.5** 中标准化的环叫**令牌环**，它是在 **IBM Token Ring 协议**的基础上发展与形成的。

| 时间/主体 | 事件 |
|-----------|------|
| **1969 年，贝尔实验室** | **Newhall 环网**——令牌环技术的起点 |
| **IBM** | **IBM Token Ring**——最有影响的令牌环网 |
| **IEEE 802.5** | 在 IBM Token Ring 协议基础上标准化，称**令牌环** |

### 2.IEEE 802.5 标准定义了哪些内容？

IEEE 802.5 标准定义了 **1Mb/s 和 4Mb/s** 带宽下使用**屏蔽双绞线**在**客户机和介质之间**的连接，用于处理**令牌环传送访问方式**以及与之相关的**物理层标准**和**介质访问控制方法**。

**概念上包括 4 个部分**：

| 组成部分 | 对应 OSI |
|----------|----------|
| **逻辑链路控制（LLC）** | 与 MAC 一起等效于 OSI 的**第 2 层（数据链路控制）** |
| **介质访问控制（MAC）** | 同上 |
| **物理层** | 相当于 OSI 的**第 1 层（物理层）** |
| **传输介质** | **本身并不包含在物理层之内** |

**注意这个易错点**：很多教材把"传输介质"算作物理层的一部分，而 802.5 的表述是**四部分并列**，**介质不含在物理层之内**。

### 3.IEEE 802.5 规定了哪四项技术？

| 技术 | 内容与作用 |
|------|------------|
| **（1）单令牌协议** | **环中只能存在一个令牌**，这样可以**简化优先级与环出错恢复功能**的实现 |
| **（2）优先级位** | 令牌环支持**多优先级**方案，它通过**优先级位**来设定**令牌的优先级** |
| **（3）监控站** | 环中设置一个**中央监控站**，通过**令牌监控位**执行**环维护**功能 |
| **（4）预约指示器** | 通过**令牌预约**，控制每个站点利用空闲令牌发送**不同优先级的数据帧所占用的时间** |

**为什么强调"单令牌"**：环上如果同时存在两个令牌，就会出现两个站点同时发送、数据互相破坏——**单令牌是"无冲突"的前提**，也让优先级和差错恢复的逻辑大大简化。

### 4.IEEE 802.5 定义了多少种 MAC 帧？用来做什么？

IEEE 802.5 标准定义了 **25 种 MAC 帧**，用于完成**环维护**功能，这些功能主要包括：

1. **环监控器竞争**
2. **环恢复**
3. **环查询**
4. **新站点入环**
5. **令牌丢失处理**
6. **多令牌处理**
7. **站点撤出**
8. **优先级控制**

**这 8 项就是"令牌环为什么复杂"的答案**——环是一个闭合回路，任何一处站点故障、令牌丢失或多出令牌，都必须有专门的机制把环"救回来"。

### 5.Token Ring 的工作原理是怎样的？

Token Ring 网络采用 **802.5 标准**，在令牌环中，站点通过**环接口**连接成**物理环形**。

**令牌的本质**：令牌是一种**特殊的 MAC 控制帧**，令牌帧中有**一位表示令牌忙/闲的标志位**。

**正常工作时**：令牌总是沿着物理环**单向、逐站传送**，传送顺序**与站点在环中排列的顺序相同**（图 5-7：A → B → C → D → E → A）。

**一次完整的数据传送过程**（以 A 站向 C 站发送为例）：

| 步骤 | 动作 |
|------|------|
| **① 等待令牌** | 如果站点 A 有数据要发送，它**必须等待空闲令牌的到来** |
| **② 置忙** | 当站点 A 获得空闲令牌后，它将令牌的**忙/闲标志位由"闲"置为"忙"** |
| **③ 传送数据** | 然后把**数据帧**送上环传送 |
| **④ 逐站转发** | 站点 **B、C、D 将依次接收到**数据帧（环上逐站传递） |
| **⑤ 目标站确认** | 如该数据帧的**目标地址是 C 站点**，则 C 站点在**正确接收**该数据帧后，**在帧中标志出帧已被正确接收和复制** |
| **⑥ 源站回收** | 当 A 站点**重新接收到自己发出的、并已被目标站点正确接收**的数据帧时，它将**回收**已发送的数据帧 |
| **⑦ 释放令牌** | 并将"**忙**"令牌改成"**空闲**"令牌，再将空闲令牌向它的**下一站点**传送 |

**这个机制的精妙之处**：

- **数据帧绕环一周回到源站**才被回收 → 源站能**确认**对方是否收到（"已被正确接收和复制"的标志就是确认）
- **令牌只有一个** → 任何时刻至多一个站点在发送 → **不会冲突**
- **传递顺序固定** → 每个站点获得令牌的**最大等待时间可计算** → **实时性可保证**

### 6.Token Ring 与 Token Bus 有什么共同点和不足？

**相似的特点**：

1. 网络中站点**两次获得令牌之间的最大间隔时间是确定的**，因而适用于对**数据传输实时性要求较高**的应用环境
2. **网络通信和负荷较重**时表现出**很好的吞吐率与较低的传输延迟**，因而适用于**通信和负荷较重**的应用环境

**共同的不足**：**它们都需要实现复杂的环维护功能**（令牌丢失、多令牌、站点入环/退环、环恢复等）。

### 7.令牌环与令牌总线对比

| 比较项 | Token Bus（802.4） | Token Ring（802.5） |
|--------|--------------------|---------------------|
| **物理拓扑** | **总线型** | **环型**（站点经环接口连成物理环） |
| **逻辑结构** | **逻辑环**（顺序由协议配置，与物理连接顺序无关） | **物理环即逻辑环**（传送顺序＝站点排列顺序） |
| **令牌传递** | 按逻辑环顺序 | 沿物理环**单向、逐站** |
| **传输介质** | 同轴电缆、双绞线 | **屏蔽双绞线**（1Mb/s、4Mb/s） |
| **标准** | IEEE **802.4** | IEEE **802.5** |
| **典型实现** | **ARCNet** | **IBM Token Ring** |
| **共同优点** | 令牌间隔确定、重载吞吐率高延迟低 | 同左 |
| **共同缺点** | 环维护复杂 | 环维护复杂 |

### 8.令牌环为什么不会发生冲突？

**根本原因有三条**：

1. **令牌唯一**（单令牌协议）——同一时刻**只有一个站点持有令牌**
2. **持有才能发送**——没有令牌的站点**只能接收、转发**，不能发送
3. **环上单向逐站传递**——数据沿固定方向流动，**不存在两路信号在同一介质上叠加**的场合

对比 CSMA/CD：以太网站点"**听到空闲就发**"，而传播延时会让两个站点同时误判为空闲，于是**冲突不可避免**；令牌环是"**拿到令牌才发**"，**访问权是授予的而不是争来的**。
