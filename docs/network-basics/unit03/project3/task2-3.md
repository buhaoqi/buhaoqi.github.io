## 知识点

### 1.应用层是什么

- 应用：就是指计算机或手机中安装的各种软件。
- 应用层规定了应用程序之间如何通信(交换信息)
- 应用层负责制定应用程序之间通信的协议规则。
- 应用层是为应用程序之间实现通信的协议的集合。
  - 简言之：应用层就是通信协议层。
  - 写信格式和对话规则，比如 HTTP、SMTP、DNS；
  - 它定义了数据长什么样、双方怎么交互，并且它产生的报文确实会被下层传输
- 应用层是OSI参考模型中的第 7 层，也是最高层。
- 为应用程序提供访问网络服务的接口和协议。
- 应用层不等于浏览器、微信、邮件客户端等具体软件，而是这些软件在通信时使用的网络协议和服务规范。
- 支持常见网络功能，如网页浏览、邮件、文件传输、域名解析、远程登录等
- 为应用程序提供访问网络服务的接口

> 应用层是应用进程之间通信所遵循的协议规则、数据格式、语义和交互时序的集合。

### 2.应用层的职责是什么
- 应用层只管“语义”。意思是：数据代表什么含义、要做什么事
- 应用层指关心通信规则和消息内容本身

### 3.应用层的功能特点
OSI 模型最靠近用户的一层，为应用程序提供网络服务；
不为 OSI 其他层提供服务，只为模型外的应用程序提供服务；
负责通信应用程序建立连接、同步，协商差错纠正、数据完整性；
协议数量最多、最复杂。

### 4.常见应用层协议

- 网页浏览：**HTTP、HTTPS**
- 文件传输：**FTP、TFTP**
- 电子邮件：**SMTP、POP3、IMAP**
- 域名解析：**DNS**
- 远程登录：**Telnet、SSH**
- 网络管理：**SNMP**
- 动态主机配置：**DHCP**

### 5.数据单位

应用层处理的数据通常称为 **报文 / 消息（Message）**。

### 6.简单区分会话层、表示层、应用层各自核心作用

答：

会话层：管理通信会话（建立 / 维持 / 断开连接，同步检查点）；
表示层：处理数据的表示形式（格式转换、加密压缩）；
应用层：直接给用户应用程序提供网络服务。

### 7.OSI高 3 层共同特点是什么？
答：包含会话层、表示层、应用层。
共同特点：
①处理的信息单位都是报文；
②提供面向用户的服务；
③端到端的数据处理，不考虑信息怎么传输。

## 应用层

### 举例：微信图片

1. 微信（应用层程序）拿到图片文件。
2. 调用应用层协议，把图片打包成应用层报文，标记发给谁。
3. **交给下一层（表示层）**继续处理。

模拟报文(真实报文不会明文裸传，是私有加密协议)

```
【应用层报文】
头部标记：目标用户ID：0086-张三
头部标记：发送方ID：0086-我
头部标记：消息类型：图片
头部标记：图片文件名：海边.jpg
头部标记：图片大小：2.3MB
——————————
数据载荷：（图片二进制数据）
```

报头标记写明

- 是谁发、

- 什么类型的数据（图片/文字）**

### 发送端：照片什么时候进入应用层？
当应用程序决定把照片发到网络时，比如：

- 浏览器上传照片
- 微信发送图片
- 邮件添加附件
- FTP 上传文件

应用程序会读取照片文件，把照片字节流交给某个**应用层协议**处理，比如：

- HTTP / HTTPS
- FTP
- SMTP
- 微信私有协议等

这时，照片数据就**进入应用层**。

更准确地说：

> 应用程序把照片交给应用层协议进行封装的那一刻，照片进入应用层处理范围。

在应用层里，照片可能被：

- 放进 HTTP 请求体；
- 做成 MIME 附件；
- 用 base64 编码；
- 分块、压缩、加密；
- 加上文件名、类型等元信息。

此时照片是**应用层报文的一部分**。

### 发送端：照片什么时候离开应用层？

应用层协议把照片封装好后，会生成一个应用层报文，比如：

```http
POST /upload HTTP/1.1
Host: example.com
Content-Type: multipart/form-data

...照片二进制数据...
```

然后这个应用层报文被交给下面的**传输层**，比如 TCP 或 UDP。

这一刻：

> 照片数据离开应用层，进入传输层处理。

注意：照片并没有消失，它变成了 TCP/UDP 载荷的一部分，继续往下走：

应用层 → 传输层 → 网络层 → 链路层 → 物理层

所以“离开应用层”不是离开网络，而是**不再由应用层协议处理，改由传输层处理**。

---

### 接收端：照片什么时候进入应用层？

数据经过网络到达接收端后，会从下往上走：

物理层 → 链路层 → 网络层 → 传输层 → 应用层

当传输层把重组好的数据交给应用层协议时，比如：

- Web 服务器收到 HTTP 请求；
- FTP 服务器收到文件数据；
- 邮件服务器收到 SMTP 数据；
- 微信服务器收到图片消息。

这时，照片数据**进入接收端的应用层**。

应用层协议开始解析：

- HTTP 服务器解析 multipart；
- 邮件客户端解析 MIME；
- FTP 服务器接收文件流；
- 私有协议解析图片消息。

然后提取出照片的原始字节。

---

### 接收端：照片什么时候离开应用层？

当应用层协议解析完成，把照片字节流交给接收方的应用程序时，照片就**离开应用层**。

比如：

- HTTP 服务器把照片交给后端程序；
- 后端程序把照片保存到磁盘；
- 微信把照片显示到聊天窗口；
- 邮件客户端把附件保存到本地。

这时照片进入的是：

> 应用程序、文件系统、相册、数据库等，不再是网络协议栈的应用层。

---

### 用一张表总结

| 阶段       | 发送端                                          | 接收端                                      |
| ---------- | ----------------------------------------------- | ------------------------------------------- |
| 进入应用层 | 应用程序读取照片，交给 HTTP/FTP/SMTP 等协议封装 | 传输层把数据交给 HTTP/FTP/SMTP 等应用层协议 |
| 在应用层   | 照片成为应用层报文载荷，可能被编码、分块、加密  | 应用层协议解析报文，提取照片数据            |
| 离开应用层 | 应用层报文交给 TCP/UDP，进入传输层              | 应用层把照片字节流交给应用程序保存/显示     |

---

### 关键理解

1. **应用层不实际搬运照片**，搬运靠 TCP/IP、网卡、路由器等。
2. 但照片必须经过应用层协议的**封装和解封装**。
3. “进入应用层”= 照片开始被应用层协议处理。
4. “离开应用层”= 照片不再由应用层协议处理，交给下层或交给应用程序。
5. 如果照片只是本地查看，不经过网络，那它根本不经过应用层网络协议栈。

一句话：

> **发送端：应用程序把照片交给应用层协议时进入，应用层封装完交给 TCP/UDP 时离开。接收端：传输层把数据交给应用层协议时进入，应用层解析完交给应用程序时离开。**
