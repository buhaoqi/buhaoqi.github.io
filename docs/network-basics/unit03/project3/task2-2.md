### 2.简述表示层的功能。
关心传输信息的语法与语义；负责:

- 语法转换
- 语法协商
- 连接管理；
- 完成数据格式转换、
- 数据加密
- 数据压缩
- 解决不同计算机数据表示方式不兼容问题。

### 3.什么是表示层语法转换？

语法转换是表示层的核心功能:

- 发送端将主机本地的**抽象语法**转换为通信双方约定好的**传送语法**；
    - **抽象语法**：计算机本机内部使用的数据 / 编码格式（主机本地的表示方式）
    - **传送语法**：通信双方协商确定，在网络上传输时统一使用的数据格式
- 数据到达接收端后，接收端表示层执行反向转换，把传送语法再转换成接收主机自身的抽象语法。
- 以此消除不同计算机数据表示格式的差异，保证通信双方能够读懂数据。

例：ASCII 编码计算机发送 HELLO 给 EBCDIC 编码计算机，表示层完成编码转换，保证双方读懂信息。

> 记忆口诀：发送：抽象语法 → 传送语法；接收：传送语法 → 抽象语法

## 表示层


### 1.表示层是什么
- 表示层（Presentation Layer）是 OSI 七层模型中的第 6 层，位于应用层之下、会话层之上。
- 应用层负责确定消息要表达什么；表示层负责翻译编码格式，消除两台主机数据表示形式的差异，保证接收方应用层看懂报文。
- 它的核心任务是：处理通信双方在数据表示形式上的差异，确保一个系统应用层发出的数据，能被另一个系统的应用层正确理解。“应用层写好报文”和“这个报文能被对方正确理解”是两回事。
- 表示层则是数据表示规则层
    - 表示层不是把应用层报文“再写一遍”，而是对应用层数据做表示形式上的处理，保证对端能正确还原。
- 表示层管“语法”：这些数据用什么编码、什么格式、怎么压缩、怎么加密、字节怎么排列。
    - 数据长什么样、
    - 怎么编码
    - 怎么转换
- 应用层管“语义”：这是什么请求、要做什么、交互规则是什么。


示例
```
**场景**：计算机A（ASCII编码），计算机B（EBCDIC编码）
1. 应用层（A）：写好报文，内容是`HELLO`。应用层只管语义，只知道报文含义是“发送HELLO”，直接交给下层。
> 👉 这一步：**应用层写好了报文**。
> 报文在A内部是ASCII编码：`48 45 4C 4C 4F`。

2. 如果**没有表示层**：比特流原样传到B。B的应用层拿到这串编码，在本机EBCDIC编码体系里，`48 45 4C 4C 4F`**并不代表HELLO**，对方看不懂。
> 👉 说明：报文虽然写好了，但对方不能正确理解。

3. **表示层介入（核心任务）**
发送方A的表示层，把本地ASCII编码，转换成网络标准传送语法；接收方B的表示层，再把标准编码转换成本机EBCDIC编码。
最后交给B的应用层时，B的应用层读到`HELLO`，读懂报文含义。

✅一句话总结：
应用层负责写出**要表达什么内容**；表示层负责翻译数据格式，解决两边机器编码体系不一样的问题，保证对方应用层看得懂这份报文。

```
### 表示层的本质

> 不同系统之间的数据语法翻译层。

它不负责把数据从 A 传到 B，也不负责决定“这是网页请求还是邮件发送”。  
它负责的是：上层交给它的数据，应该以什么格式、什么编码、什么结构表示，才能让对方看懂。

比如：

- 一台机器用 ASCII，另一台用 EBCDIC，怎么转换？
- 一台机器是大端字节序，另一台是小端字节序，怎么统一？
- 中文网页用 UTF-8，对方系统只认 GBK，怎么转？
- 图片是 JPEG 还是 PNG？视频是 MPEG 还是 H.264？
- 数据要不要压缩？要不要加密？

这些都属于表示层关注的问题。

### 表示层示例

应用层写的是“业务消息”，不是最终比特表示

比如 HTTP 应用层写了一个请求：

```http
GET /index.html HTTP/1.1
Host: example.com
```

这看起来已经是“报文”了，但还有很多问题没解决：

- 这些字符用 ASCII、UTF-8 还是别的编码？
- 响应体是 HTML、JSON、JPEG 还是视频？
- 内容要不要 gzip 压缩？
- 要不要 TLS 加密？
- 整数、浮点数用大端还是小端？
- 结构化数据怎么序列化？

这些都不是 HTTP 的业务语义，而是数据表示问题。

在 OSI 中，这类问题就划给表示层。

---

### 2. 表示层解决的是“语法”，不是“语义”

可以这样区分：

| 层次 | 关注点 |
|---|---|
| 应用层 | 说什么、做什么，如“获取网页”“发送邮件” |
| 表示层 | 怎么说、怎么表示，如 UTF-8、JPEG、gzip、TLS、序列化 |

例如：

- 应用层说：我要发一封邮件。
- 表示层说：邮件正文用 UTF-8，附件用 Base64 编码，图片用 JPEG。
- 应用层说：我要调用一个远程接口。
- 表示层说：参数用 JSON 还是 Protobuf，字节序怎么统一。

表示层不会改变“这是 HTTP 请求”这个语义，它只改变这些数据的表示形式。

---

### 3. 为什么需要单独抽出来？

因为不同系统的数据表示可能完全不同：

- 字符编码不同：ASCII、EBCDIC、UTF-8、GBK
- 字节序不同：大端、小端
- 文件格式不同：JPEG、PNG、GIF
- 数据结构表示不同：JSON、XML、ASN.1、Protobuf
- 安全与效率需求：加密、压缩

如果每个应用层协议都自己处理这些，会非常重复：

- HTTP 要自己处理编码、压缩、加密
- SMTP 也要自己处理
- FTP 也要自己处理
- 每个 RPC 协议也要自己处理

OSI 的想法是：把这些通用问题交给表示层，应用层专注业务逻辑。

---

### 4. 那为什么现实中感觉不到表示层？

因为实际互联网用的是 TCP/IP 模型，它没有独立的表示层和会话层。

表示层的功能被拆到了下面这些地方：

- HTTP 的 `Content-Type`、`Content-Encoding`、`charset`：规定数据表示
- JSON/XML/Protobuf 序列化库：负责数据结构表示
- gzip：负责压缩
- TLS：负责加密
- MIME/Base64：负责邮件附件编码

所以，现实中不是“没有表示层”，而是表示层功能被应用层、TLS、序列化库吸收了。

你说“应用层已经写好报文了”，其实在很多情况下，应用层已经把表示层的活也干了。  
如果严格按 OSI 分工，应用层只产生业务消息，表示层才负责把它变成可传输、可解释的表示形式。

---

### 2. 主要功能

表示层通常负责以下几类工作：

#### 1）数据格式转换
不同计算机体系结构、操作系统、编程语言对数据的表示可能不同。  
表示层负责把它们转换成通信双方都能理解的格式。

例如：
- 整数、浮点数的表示转换
- 大端序和小端序转换
- 不同文件格式之间的转换

#### 2）字符编码转换
常见字符编码包括：
- ASCII
- EBCDIC
- Unicode
- UTF-8
- UTF-16
- GBK

表示层负责字符编码的转换，保证文本不乱码。

#### 3）数据加密与解密
表示层可以为数据提供保密性，例如在发送前加密，接收后解密。  
现实中，TLS/SSL 常被拿来举例，因为它提供加密功能。  
但严格说，TLS 在实际协议栈中位于应用层和传输层之间，不完全等同于 OSI 的表示层。

#### 4）数据压缩与解压缩
为了减少传输数据量，表示层可以对数据进行压缩。  
例如：
- 文本压缩：gzip
- 图片压缩：JPEG、GIF、PNG
- 音视频压缩：MPEG、MP3、H.264

接收方再解压缩，恢复成应用层能处理的数据。

#### 5）序列化与反序列化
把程序中的数据结构转换成字节流，或者把字节流还原成数据结构。  
例如：
- JSON
- XML
- Protocol Buffers
- Java 序列化

这些在实际中常由应用层库完成，但功能上属于表示层范畴。

---

### 3. 表示层与相邻层的关系

| 层次 | 关注点 |
|---|---|
| 应用层 | 业务语义和交互规则，如 HTTP 请求网页 |
| 表示层 | 数据语法和表示形式，如 UTF-8、JPEG、加密、压缩 |
| 会话层 | 对话管理，如建立、维持、同步会话 |
| 传输层 | 端到端进程通信，如 TCP/UDP |

可以这样理解：

- 应用层说：“我要发一个网页请求。”
- 表示层说：“这个请求里的文本用 UTF-8 编码，内容要不要压缩，要不要加密。”
- 会话层说：“我们之间的对话怎么开始、怎么维持、怎么结束。”
- 传输层说：“我负责把数据从你的进程送到对方的进程。”

---

### 4. 现实中的表示层

在互联网实际使用的 TCP/IP 模型中，并没有独立的表示层和会话层。  
它们的功能通常被合并到应用层中，由具体协议或库来实现。

例如：
- HTTP 头里的 `Content-Type`、`Content-Encoding`、`charset` 决定了数据表示；
- TLS 负责加密；
- gzip 负责压缩；
- JSON/XML 负责结构化数据表示；
- JPEG/MPEG 负责多媒体编码。

所以，OSI 的表示层更像一个理论上的功能划分，而不是现实中必须独立存在的一层协议。

---

### 5. 一句话总结

表示层是 OSI 第 6 层，本质是数据语法翻译层。它负责数据格式转换、字符编码、加密解密、压缩解压缩等，确保不同系统之间能够正确理解彼此的数据表示。
