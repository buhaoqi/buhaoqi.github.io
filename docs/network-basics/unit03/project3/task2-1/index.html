任务二 会话层

  1. 什么是 “会话”？
  2. 会话层是什么？
  3. 简述会话层的主要功能。
  4. 会话连接和传输连接之间有哪 3 种关系？
  5. 会话层半双工通信如何协调数据发送？
  6. 会话层的同步服务（检查点）作用是什么？
  7. 写出常见会话层协议。

知识点​

1.什么是“会话”​

这里的“会话”不是日常说的“登录状态”那么简单，而是指：

两个应用进程为了完成某项任务，而进行的一次持续交互过程。

例如：

  • 你登录网银后，查询、转账、退出，这一系列交互可以看作一个会话
  • 一次数据库连接后，执行多条 SQL，也可以看作一个会话
  • 一次视频会议从建立到结束，也是一个会话

会话层关心的是：这个交互过程怎么建立、怎么维持、怎么同步、怎么结束。

2.会话层是什么​

会话层（Session Layer）是 OSI 七层模型中的第 5 层，位于表示层之下、传输层之上。它的核心任务是：在两个应用进程之间建立、管理、维护和终止“会话”，并控制它们之间的对话过程。

如果用前面几层的话来对比：

  • 应用层：管业务语义，比如“我要访问网页”“我要发邮件”
  • 表示层：管数据语法，比如 UTF-8、JPEG、压缩、加密
  • 会话层：管对话过程，比如“我们怎么开始聊、谁先说、聊到哪了、怎么结束、断了怎么恢复”
  • 传输层：管端到端的数据传输，比如 TCP/UDP 把字节流送过去

所以，会话层不是传数据的，也不是定义数据格式的，而是应用进程之间对话的管理层。

3.简述会话层的主要功能。​

会话层：管对话的开启、维持与结束；协调收发；打检查点，断点续传。

  • 在两个网络节点之间建立、维护、释放面向用户的连接，
  • 管理控制会话，保障会话数据可靠传输；
  • 协调通信（全双工 / 半双工，半双工使用数据令牌控制发送权）；
  • 设置检查点实现同步，故障时可从检查点恢复重传。

会话层就像管聊天的主持人，负责两台电脑之间的“对话”。

  1. 开启对话、维持对话、对话结束后关掉连接；（会话层负责建立、保持、断开两台主机之间的通信对话）
  2. 管理这次对话，保证对话的数据正常传递；（管理这次对话；协调通信双方收发数据）
  3. 协调双方说话方式：可以双方同时说话（全双工），也可以轮流说话（半双工）。轮流说话时用“令牌”，拿到令牌的一方才有资格发消息；（半双工模式依靠令牌轮流发送）
  4. 在传输的数据里打上标记（检查点）。一旦网络中断，不用从头重新传全部数据，从最近的标记位置继续传就行。（设置数据检查点，网络中断后，从最近的检查点继续传输数据。）

好比两个人打电话：

  • 建立会话 = 拨通电话
  • 维持会话 = 保持通话不挂断
  • 释放会话 = 挂掉电话
  • 令牌（半双工）= 对讲机，拿到对讲机的人才能说话，不能两个人同时讲
  • 检查点 = 听录音，听到一半断线，不用从头听，直接回到上次听到的位置继续。

4.会话连接和传输连接之间有哪 3 种关系？​

一对一关系；一对多关系；多对一关系。

  1. 一对一：1 个会话连接对应 1 个传输连接。一次对话，单独占用一条通道。
  2. 一对多：1 个会话连接先后对应多个传输连接。一次对话，可以换多条通道传输。
  3. 多对一：多个会话连接共用 1 个传输连接。多段对话，复用同一条通道。

一句话口诀：一会一通道；一会换多通道；多会话共用一通道。

5.会话层半双工通信如何协调数据发送？​

使用数据令牌协调会话，只有拿到令牌的用户才能发送数据；接收方想要发送时，可请求获取令牌，由发送方决定何时释放令牌。

6.会话层的同步服务（检查点）作用是什么？​

在数据流中定义检查点，把会话分割成会话单元；网络故障中断后，可以从最后一个检查点继续重传，不用从头重传。例：下载 100MB 文件到 95MB 断线，从 95MB 的检查点恢复。

7.写出常见会话层协议。​

结构化查询语言 SQL、远程过程调用 RPC。

会话层​

2. 会话层的主要功能​

1）会话建立、维护和释放​

会话层负责在通信双方之间建立会话，并在通信结束后有序释放会话。
它要保证双方都准备好，并且结束时不会丢失未完成的数据。

2）对话控制​

决定通信双方谁在什么时候发送数据。
例如：

  • 半双工：一方说完，另一方再说
  • 全双工：双方可以同时说
  • 通过令牌控制发言权

这就像开会时主持人控制谁先发言。

3）同步与检查点恢复​

如果一次会话要传很多数据，中途网络断了怎么办？
会话层可以在数据流中插入同步点，相当于“检查点”。

这样中断后，可以从最近的检查点继续，而不必从头开始。
例如传一个大文件，传到 70% 断了，可以从中断点继续，而不是重传全部。

4）活动管理​

把一次会话分成多个逻辑活动单元，每个活动可以独立完成或回滚。
这样上层可以更灵活地组织复杂交互。

5）异常恢复​

会话层可以报告上层会话中的错误，并协助恢复或有序终止会话。

3. 会话层与传输层的区别​

很多人容易把“会话”和“连接”混在一起。

概念含义
传输层连接端到端的数据通道，如 TCP 连接
会话层会话应用进程之间的对话逻辑和状态

区别在于：

  • 一个 TCP 连接可以承载多个会话，比如 HTTP/2 多路复用
  • 一个会话也可以跨多个连接，比如断线重连后继续同一个业务会话
  • TCP 关心字节流是否可靠送达
  • 会话层关心对话是否有序、可同步、可恢复、可结束

所以，TCP 连接不等于会话层会话。

4. 现实中为什么感觉不到会话层？​

因为互联网实际使用的 TCP/IP 模型没有独立的会话层和表示层。
OSI 的会话层功能通常被合并到应用层中，由具体协议或框架实现。

例如：

  • HTTP Cookie / Session：Web 应用自己维护用户会话
  • TLS Session / Session Ticket：安全会话恢复
  • RPC / gRPC：维护调用会话上下文
  • SIP：建立、修改、终止多媒体会话
  • SMB / NetBIOS：有会话服务功能
  • 数据库连接会话：连接后保持事务和状态

这些功能上类似 OSI 会话层，但它们并不单独作为一层存在。

5. 一句话总结​

会话层是 OSI 第 5 层，本质是应用进程之间对话的管理层。它负责会话的建立、维护、同步、恢复和终止，控制双方如何有序交流。现实中 TCP/IP 没有独立会话层，这些功能通常由应用层协议和框架实现。

对，但要加两个限定：

  1. 它管理的是“会话控制规则”，不是应用业务规则；
  2. 它记录的是“会话控制状态”，不是用户购物车、登录身份、订单内容这类业务状态。

所以更准确地说：

会话层负责定义和执行会话管理规则，并维护会话进行过程中的控制状态。它不是记录所有会话内容，而是记录“对话进行到哪、谁在说、能否恢复、怎么结束”。

1. 会话层管理哪些规则？​

在 OSI 理论中，会话层主要管这些：

  • 会话建立：双方怎么开始一次对话
  • 会话维持：对话期间怎么保持有效
  • 对话控制：谁先发、谁后发、能不能同时发
  • 同步：在数据流中插入同步点，相当于检查点
  • 恢复：中断后能不能从同步点继续
  • 活动管理：把会话分成多个逻辑活动，分别完成或回滚
  • 会话释放：怎么有序结束对话
  • 异常报告：会话出错时通知上层

这些是会话控制规则，不是“HTTP 怎么请求网页”“图片怎么编码”这类规则。

2. 会话层记录哪些状态？​

它记录的是会话控制状态，例如：

  • 会话是否已建立
  • 当前处于哪个活动
  • 当前同步点在哪里
  • 谁持有发言令牌
  • 是否处于半双工/全双工控制中
  • 是否发生异常
  • 是否可以从某个检查点恢复
  • 会话是否正在释放

这些状态的作用是：
让一次持续交互有秩序、可协调、可恢复、可结束。

但它通常不记录：

  • 图片数据本身
  • 网页内容
  • 用户身份和权限
  • 购物车内容
  • 订单信息
  • 数据库事务的具体业务数据

这些属于应用层或应用框架。

3. 和现实中的“会话状态”区分开​

现实中我们常说的“Session 状态”，比如：

  • 用户登录状态
  • Cookie 里的 Session ID
  • 购物车
  • 权限信息

这些是应用层业务会话状态，不是 OSI 会话层状态。

在 TCP/IP 模型中，没有独立的会话层。
OSI 会话层的功能通常被应用层、TLS、SIP、数据库连接、RPC 框架等吸收。

例如：

  • Web：Cookie、Session、JWT 记录用户业务会话
  • TLS：Session Ticket 记录安全会话恢复信息
  • SIP：管理多媒体会话建立和终止
  • 数据库：连接会话管理事务和状态
  • gRPC：调用上下文管理

它们做的是类似会话层的事，但通常混合了应用层业务状态。

4. 一句话总结​

会话层是管理会话控制规则、维护会话控制状态的功能层。它记录的是“对话怎么进行、进行到哪、能否恢复、怎么结束”，而不是记录图片、订单、用户身份等业务内容。现实中这些功能多由应用层和各类框架实现。
