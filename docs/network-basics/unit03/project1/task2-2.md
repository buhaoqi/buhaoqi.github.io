## 知识点

### 1.对等实体与对等层

|概念|实体|对等实体|传输实体|对等层|对等层协议|
|-----|-----|-----|-----|-----|-----|
|定义|每层执行功能的模块|异机同层的实体|特指传输层实体|异机同层|对等实体之间通信时遵守的规则|
|应用层|应用程序、服务进程|客户端浏览器-服务端Web服务器||应用层 ↔ 应用层|HTTP、HTTPS、DNS、FTP、SMTP|
|表示层|数据编码/加密模块|客户端SSL加密-服务端SSL解密||表示层 ↔ 表示层|SSL/TLS、JPEG、ASCII|
|会话层|会话管理程序|客户端会话管理模块 ↔ 服务器会话管理模块||会话层 ↔ 会话层|RPC、SDP|
|传输层|TCP、UDP|主机A的TCP模块↔主机B的TCP模块|TCP 模块、UDP 模块|传输层 ↔ 传输层|TCP、UDP|
|网络层|路由模块、IP协议|主机A的IP模块↔主机B的IP模块||网络层 ↔ 网络层|IP、ICMP、ARP|
|链路层|网卡驱动、交换机|交换机 ↔ 交换机||链路层 ↔ 链路层|以太网协议 (Ethernet)、PPP|
|物理层|网卡、网线、集线器|网卡 ↔ 网卡||物理层 ↔ 物理层|RJ45 接口规范、光纤编码标准、曼彻斯特编码|


注意：

- 高三层：没有硬件实体。硬件只到网络层、链路层、物理层
- 低四层：既有软件也有硬件实体
- 对等层之间通信的特点：通信是虚拟通信，它们之间的通信是使用下一层提供的服务来实现的。


### 2.网络协议是什么
||网络协议是什么|
|---|---|
|定义|网络协议是为计算机网络中进行数据交换而建立的规则、标准或约定的集合。|
|组成|语义、语法、时序|
|语义|数据格式|
|语法|数据含义|
|时序|先后顺序|


### 3.协议是水平的

||协议是水平的|
|---|---|
|定义|同一网络中不同主机的对等层，要安装运行相同的网络协议，主机间才能进行有效通信|
|解释|协议作用于不同主机的对等层（水平方向），对等实体之间依靠协议通信，因此协议是水平的|
|例子|主机 A 传输层 TCP ↔ 主机 B 传输层 TCP|



### 4.服务是什么

||服务是什么|
|---|---|
|定义|下层实体为上层实体提供的通信功能|


### 5.服务是垂直的
||服务是垂直的|
|---|---|
|定义|N层实体利用N-1层实体所提供的服务，向N+1层实体提供功能更强大的服务，概括为“服务是垂直的”。|
|解释|协议作用于不同主机的对等层（水平方向），对等实体之间依靠协议通信，因此协议是水平的|
|例子|主机 A 传输层 TCP ↔ 主机 B 传输层 TCP|

注意

- 对等实体之间：**协议**（水平，同一层）
- 上下相邻层之间：**服务**（垂直，下层给上层提供服务，没有协议）

### 6.下层为上层提供的服务分为哪两类


|对比项|面向连接服务|无连接服务|
| ---- | ---- | ---- |
|连接建立|通信双方在传输数据**之前，先建立一条专属连接**，传输完再释放连接|不用提前建立连接，每个数据包独立，直接发送|
|数据顺序|数据包按顺序到达，有序|每个分组独立路由，可能乱序、重复、丢失|
|可靠性|可靠（可差错校验、重传）|不保证可靠，尽力而为|
|资源占用|建立连接时预留资源，开销大|不预留资源，开销小，速度快|
|典型例子|TCP（传输层）|UDP、IP|

通俗理解

- **面向连接**：打电话。先拨号接通（建立连接），然后说话，说完挂断（释放连接）。通话内容顺序不会乱。
- **无连接**：寄明信片。每张明信片单独寄出，各自走不同路线，可能晚到、丢失、顺序颠倒，不用提前跟收件人“建立通道”。

注意：
- 向连接 ≠ 一定可靠；无连接 ≠ 一定不可靠。
- 比如 ATM 是面向连接但是不可靠。（选择题坑点）

### 7.接口是什么

接口是同一主机内相邻两层实体的边界，规定上下层之间交换信息的规则，上层通过接口来使用下层提供的服务。

接口只负责本机内部相邻层的数据传递，不是两台主机之间的通信。


**服务访问点 SAP 就是接口，上层通过接口调用下层提供的服务。**


注意

- **协议**：对等层实体之间的规则（两台主机，同层）
- **接口**：相邻层之间的规则（同一主机，上下层）



### 8.SAP是什么？

- SAP就是服务访问点(Service Access Point)
- N层的SAP是N层实体提供服务给N+1层的地方，可以理解为下层实体之间的逻辑传输通道。
- SAP是下层对高层提供服务的一个入口
- 每一层的SAP都有一个唯一标明它的地址，一个N层可能存在多个SAP。

### 9.接口和SAP的关系是什么？
- 接口是为其他实体提供服务的入口，是一个大的概念；
- SAP是下层对高层提供服务的一个入口，是对高层的一个逻辑接口；
- 接口包含SAP，也还包括其他服务提供方式。


### 10.数据单元是什么

- OSI分层后，层与层之间传输信息时，信息需要被打包成一块一块的数据。
- 数据单元就是每层传输信息的数据块。

### 11.数据单元的分类
|名称|全称|说明|组成|特点|
| ---- | ---- | ---- | ---- | ---- |
|PDU|协议数据单元|对等实体间交换的数据单元|本层头部 + SDU|对等实体靠PDU通信，各层PDU有别名（段/分组/帧/比特）|
|SDU|服务数据单元|上层交给下层的服务数据|纯数据载荷|上层的PDU，到下层就变成下层的SDU；不加下层协议头|
|IDU|接口数据单元|相邻层接口处传输的数据单元|SDU + 接口控制信息|**只在接口短暂存在**，下层收到后丢掉接口控制信息，取出SDU|

### 12.服务原语是什么

原语就是上下层之间传递信息时发出的命令。

- 上层实体通过服务原语请求下层提供服务
- 下层通过服务原语向上层返回结果


四类标准服务原语（必背）

1. **请求（Request）**：上层 → 下层。上层要求下层启动某个服务（比如请求建立连接）
2. **指示（Indication）**：下层 → 上层。下层通知上层，发生了某个事件（对方请求连接）
3. **响应（Response）**：上层 → 下层。上层对收到的指示做出应答（同意建立连接）
4. **确认（Confirm）**：下层 → 上层。下层通知上层，本次请求操作已经完成

注意：
- **协议**：对等实体（两台主机同层）之间的规则
- **接口**：同一主机相邻层的边界
- **服务原语**：**跨接口传递的命令**，用来调用服务

来个判断题？
> 服务原语是对等实体之间交换信息的规则（ ）

答案：错误。服务原语是**同一主机相邻上下层之间**调用服务的指令。
**对等实体之间交换信息的规则是协议**，不是服务原语。
