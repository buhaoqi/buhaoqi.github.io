## 开场



## 现实世界中的“对象”

奇奇：现实世界由什么组成？

村长：由一个个“对象”组成。 

奇奇：那到底什么是对象？

在生活中，“对象”这个词有两层意思：

- 狭义的对象，指恋爱中的对方。
- 广义的对象，指行为或思维的目标事物。

按照这个定义，可以说万物皆对象。  
你眼睛能看到的，
耳朵能听到的，
或者脑子里能够想到的一个具体事物，
都可以叫对象。
水杯是对象。
手机是对象。
青蛙是对象。
一辆汽车也是对象。

所有对象都有两个共同点：
- 特征：对象有什么
- 行为：对象会干什么

比如：一只青蛙（播放歌曲）

我们在向别人介绍青蛙时
第一，看它有什么特征。
- 颜色：绿色
- 眼睛：2 只
- 嘴：1 张
- 腿：4 条

第二、看他会干什么

- 呱呱叫
- 跳水：会“扑通”一声跳下水

所以，一只青蛙，其实就是：
一些特征 + 一些行为。

如果世界上真有上帝，那上帝一定是按照“一张嘴、两只眼、四条腿、会叫会跳”这张特征行为说明书，造出了青蛙这个对象。



## 编程世界中的“对象”

在编程这个虚拟世界里，程序员就是"造物主"。  
受到上帝造物的启发，
程序员可以通过“特征”和“行为”来创造“万物“，模仿现实世界。
这就是面向对象。

不过，程序员不可能每造一只青蛙，
都重新写一遍代码。
所以，
我们会先涉及一张图纸。
以后需要青蛙，
按图纸创建就行了。
这张图，就叫：类（Class）。

类就是用来描述“一类事物的共性”长什么样、能做什么的模板。
所以，类就是事物的抽象，比如：人类、鸟类。

如果想创建“青蛙“对象。首先要创建青蛙类。
接下来这两段代码，

```csharp
class Frog
{
    // 属性（特征）
    public string Color = "绿色";
    public int Eyes = 2;
    public int Legs = 4;

    // 方法（行为）
    public void Croak()
    {
        Console.WriteLine("呱呱呱！");
    }

    public void Jump()
    {
        Console.WriteLine("扑通一声跳下水！");
    }
}
```
到这里，一个简单的青蛙类就创建好了。

有了这张图纸之后，我们就可以用 `new` 关键字，把类变成真正的对象实体：

```csharp
Frog frog = new Frog();
```

new 的意思就是：按照图纸，真正早一只青蛙出来。
这里的 `frog`，就是我们根据 `Frog` 类造出来的对象。

奇奇：那类（Class）和对象（Object）到底是什么关系？

请记住这句话：

> 类是图纸，对象是按图纸造出来的实物。

- `Frog` 是类——它是一张说明书，描述了青蛙有什么属性、能做什么方法。
- `frog` 是对象——它是实实在在存在于内存里的那个“青蛙”。

你可以有一张 `Frog` 图纸，然后造出无数只青蛙对象：  
`frog1`、`frog2`、`frog3`……  
每只青蛙都可以有自己的颜色、自己的叫声，互不干扰。

类，从来不是对象。
它只是制造对象的一张图纸。
真正在程序中干活的，
永远都是对象。

## 属性与方法

在编程语言中，我们把“特征”叫做属性（Property），把“行为”叫做方法（Method）。

方法有一个最明显的标志——名字后面永远跟着一对小括号 `()`，因为方法要“执行”某个功能，括号就是启动按钮。

所以，最终结论是：

> 类（Class）是属性和方法的集合，是设计图纸。  
> 对象（Object）也是属性和方法的集合，但它是图纸造出来的具体实物。

## 静态成员 VS 实例成员

那属性和方法该怎么调用呢？

记住一个核心规则：

如果属性和方法前面带有 static 关键字（叫静态成员），就通过类名.成员名来调用。
如果属性和方法前面没有 static 关键字（叫实例成员），就必须先创建对象，再通过对象名.成员名来调用。

举个例子，我们下一节课要学的这行代码：

Console.WriteLine("你好");

Console 是一个类（控制台工具包）。
WriteLine 是一个方法（功能按钮），因为它带有一对小括号。
由于 WriteLine 是静态方法，我们直接通过类名 Console 来调用它，不需要创建对象。

这样你就理解了：Console.WriteLine() 能直接用，是因为微软把它设计成了静态成员。以后你看到别人写的代码里有 类名.方法名()，你马上就能反应过来——"噢，这是个静态方法！"

这就是你开窍的第一步。


## 结束语

最后，请你记住今天最重要的两句话：

> 类（Class）就是设计图纸，用来定义属性和方法。  
> 对象（Object）就是根据图纸造出来的实物，真正活在内存里。  
> 没有类，造不出对象；没有对象，程序跑不起来。

### 一句话说透（课堂开场白）

> 在 C# 中，对象（Object）就是“在程序运行时，存在于内存中的一块具体数据空间”。

---

### 拆解成“三个维度”讲给学生听（90% 初学者听完这个就悟了）

#### 1. 从“内存视角”看 —— 对象就是“一块地皮”
- 你用 `new` 关键字时，计算机就在内存里给你划了一块地。
- 这块地上种着这个对象的所有属性值（比如年龄 `18`、姓名 `"张三"`）。
- 你拿着这块地的门牌号（内存地址），就能找到它、修改它。

#### 2. 从“代码视角”看 —— 对象就是“变量的值”
- 你声明 `Student zhangsan = new Student();`
- 这里的 `zhangsan` 是“门牌号”（引用），而 `new Student()` 造出来的那个东西，才是真正的对象。
- 对象不是变量名，变量名是贴在你家门上的标签。

#### 3. 从“功能视角”看 —— 对象就是“数据和动作的打包盒”
- 它把数据（属性）和动作（方法）绑在一起。
- 比如一个 `Dog` 对象，里面包着 `Name = "旺财"`（数据），还包着 `Bark()`（动作）。
- 你只需要操作这个对象，不用关心它的内部是怎么组织的。

---

### ⚠️ 灵魂拷问：`int` 是对象吗？（100% 会被问到）

这个问题必须提前准备好答案，否则学生会炸锅：

- 严格说：`int a = 10;` 里的 `a` 在大多数情况下不是对象，它是一个值类型，直接存数据在栈上，没有“门牌号”。
- 但是：当它调用 `.ToString()` 时，C# 会悄悄把它“装箱”，临时包装成一个对象。所以你可以说“`int` 可以表现得像对象”，但不能说“`int` 天生就是对象”。

> 课堂金句：“`int` 是‘便签纸’，直接写数字；对象是‘房产证’，指向一套房子。两者都能用，但内存里住的地方完全不同。”

---

### 那 `Console` 是对象吗？

不是！ 这是最关键的纠正：

- `Console` 是一个静态类，它是“工具包”，不是“对象”。
- 你不能写 `new Console()`，因为微软没打算让你“造出多个控制台”。
- 你是在调用工具包里的功能（`WriteLine`、`ReadLine`），而不是在操作一个具体的控制台对象。

## 三、代码长什么样

村长：接下来，我们瞄一眼代码长什么样。**不用背，今天只是混个眼熟。**

```csharp
// 这是一个模板（类）
class Cat
{
    // ========== 特征：编程里叫“属性” ==========
    public string Color = "绿色";
    public int Eyes = 2;
    public int Legs = 4;

    // ========== 行为：编程里叫“方法” ==========
    
    // 实例方法：必须由具体的猫对象来调用
    public void 捉老鼠()
    {
        Console.WriteLine("呱呱呱！");
    }
    public void Jump()
    {
        Console.WriteLine("扑通一声跳下水！");
    }

    // == 静态方法：属于模板本身，不属于某一只猫 ==

    // 静态方法：直接用类名调用，不需要创建对象
    public static void DescribeSpecies()
    {
        Console.WriteLine("猫是两栖动物，幼体用鳃呼吸，成体用肺和皮肤呼吸。");
    }

    // 静态方法：可以用来统计跟整个“猫物种”相关的信息
    public static void ShowGeneralInfo()
    {
        Console.WriteLine("猫属于脊索动物门、两栖纲、无尾目。");
    }
}
```
看到了吗？代码完美对应了我们刚才说的内容：

- 模板名字叫 `Cat`（这就是**类**）。
- 里面的变量（颜色、腿数）就是**特征**，编程里叫**属性**。
- 里面的函数（叫、跳）就是**行为**，编程里叫**方法**。

仔细看，我这里写了四种方法，其中前面两个没有 `static`，后面两个带有 `static`。这个 `static` 就是今天最关键的知识点。
 
## 四、实例方法 —— 必须由对象来调用

村长：有了这张 `Cat` 模板，我们怎么造出一只猫对象呢？只需要一个 `new` 关键字：

```csharp
// 按模板 new 一个，就造出了一只实实在在的猫对象
Cat Cat = new Cat();  
```

这里的 `Cat`（小写 f）就是那个**活生生、在内存里占据空间的对象**。

你可以用同一个 `Cat` 模板，造出 `Cat1`、`Cat2`、`Cat3`... 成千上万只猫，它们互不干扰。



现在这只叫 `Cat` 的对象就活在内存里了。

奇奇：模板造好了，对象也造出来了，怎么让它干活呢？怎么让它干活呢？

村长：好。我们得告诉这只**具体的猫**（`Cat`）去叫。

比如想让它叫一声：

```csharp
Cat.捉老鼠();  // 输出：呱呱呱！
```

注意看，我们用的是**对象的名字 `Cat`** 去调用 `捉老鼠()`方法。

这种**必须通过“对象”才能调用**的方法，就叫**实例方法**。因为它强调的是“这个具体的实物”在干嘛。没有这只具体的猫，就发不出叫声。

> **实例方法 = 具体对象才能干的事**

再举个例子：

```csharp
Cat Cat1 = new Cat();
Cat Cat2 = new Cat();

Cat1.捉老鼠();  // 猫1叫
Cat2.捉老鼠();  // 猫2叫
// 每只猫各叫各的，互不干扰
```


## 五、静态方法 —— 不需要对象，直接用类名调用

奇奇：村长，那有没有不用创建对象就能调用的方法呢？

村长：有！就是带 `static` 关键字的**静态方法**。

你想啊，有些功能和"某个具体的猫"没关系，它描述的是**整个猫物种**共性。

比如："猫是两栖动物"这个信息，它是客观事实，属于整个猫物种。你不需要专门抓一只猫过来才能说这句话吧？

直接通过**类名 `Cat`** 就能调用：

```csharp
Cat.DescribeSpecies();  // 输出：猫是两栖动物，幼体用鳃呼吸，成体用肺和皮肤呼吸。
Cat.ShowGeneralInfo();  // 输出：猫属于脊索动物门、两栖纲、无尾目。
```

注意看区别：

- `Cat.捉老鼠()` —— 用的是**对象名**（小写 `Cat`），因为"叫"是这只具体的猫在叫。
- `Cat.DescribeSpecies()` —— 用的是**类名**（大写 `Cat`），因为"描述物种信息"不需要某一只具体的猫，它是整个类的公共知识。

> **静态方法 = 属于模板本身的功能，不需要具体对象就能用**


## 一句话总结区别

> **没有 `static` 的（实例成员）** —— 必须 `对象名.方法名()`（比如 `Cat.捉老鼠()`，是"这只猫在叫"。）。
> **带有 `static` 的（静态成员）** —— 直接 `类名.方法名()`（比如 `Cat.DescribeSpecies()`，是"关于猫这个物种的知识"）。


打个比方：

- **静态方法**像贴在墙上的"食堂菜单"，你看一眼就知道今天有什么菜，不需要专门找一个人来问。
- **实例方法**像厨师炒菜，你必须有一个具体的厨师对象，他才能真正动手炒。

所以以后你看到别人写的代码里有 `类名.方法名()`，马上就能反应过来——**"噢，这是个静态方法！"**

这就是你开窍的第一步。

村长：好了奇奇，今天所有的内容，都围绕那一句话展开：**类是模板，对象是实物。**

最后帮你梳理一下完整的逻辑链：

1. 现实世界的事物 = **特征** + **行为**。
2. 编程世界用**类（Class）**这张模板来定义这些特征和行为。
3. 用 `new` 把模板变成实实在在的**对象（Object）**。
4. **实例方法**（无 `static`）必须由具体的对象来调用，比如 `Cat.捉老鼠()`。
5. **静态方法**（有 `static`）属于类本身，直接用类名调用，比如 `Cat.DescribeSpecies()`。

**【结束语】**

## 参考文案

“思想” = 世界观（认为世界由物体及其相互作用构成）。
“范式” = 方法论（如何用代码具体实现这种世界观，如封装、继承、多态）。

严格来说，面向对象编程是一种编程范式，但它的哲学基础是一种思想。两者是“操作方法”和“世界观”的区别。

从“范式”的定义来解释：范式 = 一种公认的模式/风格。OOP提供了具体的结构规则（类、对象、消息传递），定义了代码应该如何组织和编写。这就是范式。
从“思想”的定义来解释：思想 = 对问题空间的认知方式。OOP认为世界由对象构成（认知论）。这就是思想。

这个问题问得非常专业，触及了计算机科学术语的核心。我的回答是：**严格来说，它是一种“编程范式”（Programming Paradigm），但它的底层驱动力和内核，是一种“思想”（Design Philosophy）。**

两者并不冲突，而是“**世界观**”与“**方法论**”的关系。为了从定义上把它说透，我们需要看“范式”和“思想”在编程领域的准确定义：

1. 从“范式”的定义来看（权威答案）

在计算机科学中，**编程范式**指的是**编码的风格、模式或方法论**。它定义了一门语言“能怎么用”以及“鼓励怎么用”的框架。

-   OOP 完美契合“范式”的定义，因为它提供了一套**具体的结构化规则**：封装、继承、多态。它规定了代码的组织形式（类/对象）、数据流转方式（消息传递）和设计模式（工厂、单例等）。
-   在学术分类中，OOP 通常隶属于**命令式范式**（Imperative Paradigm）下的一个重要分支。与它并列的是**声明式范式**（如 SQL）和**函数式范式**（如 Haskell）。

**结论一**：当你讨论代码怎么编写、程序怎么架构时，OOP 是一种**范式**。

---

2. 从“思想”的定义来看（本质内核）

**编程思想**指的是程序员如何看待和抽象现实世界，也就是一种**认知论**。

-   面向过程的思想是：“我要完成什么步骤？”
-   面向对象的思想是：“**我要把世界拆解成哪些‘事物’，它们之间是怎么协作的？**”

这个“万物皆对象”的理念，并不规定具体的代码语法，它是一种**看待问题域的视角**。在没有 OOP 语言之前，程序员依然可以用“对象”的视角去设计模块，只是在用 C 语言（面向过程）去模拟实现。

**结论二**：当你讨论如何分析业务、如何从现实中抽象出类时，OOP 是一种**思想**。

---

3. 最终权威定义：它们是什么关系？

**“思想”是大脑里的“世界观”，“范式”是代码里的“方法论”。**

你可以这样记忆：

-   **说它是“思想”**，是因为它教你：**“别总想着先做哪一步，先想想这件事该由‘谁’去负责。”**（这是抽象的）。
-   **说它是“范式”**，是因为它给了你具体的工具：**“既然你决定由‘对象’负责，那就必须用 `class` 定义属性，用 `new` 实例化，用 `override` 实现多态。”**（这是落地的）。

---

给初学者的通俗类比：

-   **思想（思想层面）**：相当于你想做一顿“川菜”。这是一种菜系理念，强调“麻辣鲜香”的思路。
-   **范式（落地层面）**：相当于你拿到了“川菜菜谱”和“烹饪流程”。它规定了你必须先放油、再放花椒辣椒、最后爆炒（这就是具体的规则/范式）。

**所以，最严谨的一句话是：**
> **面向对象首先是一种源于现实认知的“设计思想”，其具体实现方式则被计算机科学定义为一种“编程范式”。在学术和技术文档中，我们通常称它为“面向对象范式（OOP）”。**
