进程内存布局详解

视频字幕总结与翻译​

一、进程与虚拟内存​

操作系统同时管理着数十个进程，每个进程执行特定程序或其一部分的代码。

  • 你的浏览器是一个进程
  • 你常用的IDE是一个进程
  • 甚至管理打印机的后台服务也是一个进程

进程本质上是一个正在运行的程序实例，拥有自己的内存和资源。

二、虚拟内存 vs 物理内存​

进程不能直接访问物理内存，而是操作一个虚拟地址空间，由操作系统负责将其映射到物理地址空间。

虚拟内存和物理内存都被划分为相同大小的块：

  • 虚拟内存中的块称为 页（Page）
  • 物理内存中的块称为 帧（Frame）

三、进程虚拟内存的分区​

进程的虚拟内存被划分为多个区域（Segment），每个区域有特定用途：

区域用途
代码段（Text/Code）存放可执行指令
数据段（Data）存放已初始化的全局/静态变量
BSS段存放未初始化的全局/静态变量
堆（Heap）动态分配内存
栈（Stack）函数调用、局部变量
内核空间操作系统保留区域

四、为什么要分区？（三个核心理由）​

1. 安全性 🔒​

每个内存区域都有特定的访问权限：

  • 代码段：只读 + 可执行（防止代码被修改）
  • 栈和堆：可读 + 可写 + 不可执行（防止注入攻击）

⚠️ 如果代码、栈、堆混在一起，访问权限就无法有效实施，会敞开漏洞的大门。

2. 访问模式不同 ⚡​

  • 栈：按可预测的顺序增长和收缩 → 分配/释放极快
  • 堆：用于动态、随机的内存分配 → 适合大小变化的请求

如果把两者混在一起，会显著降低栈操作的性能。

3. 隔离Bug 🐛​

  • 分离代码、数据、栈、堆可以防止意外覆盖
  • 像缓冲区溢出这类问题，不容易污染其他区域的数据

五、各区域详解​

📘 代码段（Text / Code Segment）​

  • 包含程序的可执行指令
  • 从二进制文件（编译后的代码）加载到内存
  • 通常标记为只读，防止程序修改自身代码
  • 大小 = 加载整个程序代码所需的空间

📗 数据段（Data Segment）​

  • 存放已初始化的全局变量和静态变量
  • 这些值需要显式存储在可执行文件中，程序启动时加载到内存

📄 BSS段（Block Started by Symbol）​

  • 存放未初始化的全局变量和静态变量
  • 加载到内存时，自动初始化为 0
  • 不需要存储在可执行文件中 → 减小了文件体积，加载更快

💡 为什么分开Data和BSS？

  • Data段的值必须从文件读取
  • BSS段只需分配内存并批量清零（不用从文件读）
  • 如果混在一起，所有全局/静态变量都得从文件加载 → 更慢

📦 堆（Heap）​

用于动态分配内存（如 C 的 malloc，C++ 的 new）。

内存分配器（Allocator） 的工作：

  1. 跟踪哪些内存空闲、哪些在使用
  2. 程序申请内存时 → 找到合适的空闲块 → 标记为已占用 → 返回地址
  3. 程序释放内存时 → 回收该块，供后续使用

⚠️ 内存泄漏（Memory Leak）：

  • 程序分配了堆内存，但从未释放
  • 该内存块一直不可用，直到进程退出
  • 累积下去 → 可用内存耗尽 → 程序崩溃

📈 堆的地址方向：通常从低地址向高地址扩展（向上增长）

📚 栈（Stack）​

  • 简单、自动的存储区域
  • 后进先出（LIFO） 结构 → 所以叫"栈"
  • 地址方向：从高地址向低地址扩展（向下增长）

栈帧（Stack Frame） 包含：

  • 函数的局部变量
  • 传递的参数
  • 返回地址（调用者的位置）
  • 其他辅助数据

🔁 函数嵌套越深 → 栈上叠加的帧越多

💥 栈溢出（Stack Overflow）：

  • 栈大小有限（通常 1~8 MB，取决于操作系统）
  • 原因：
    • 递归函数没有正确终止
    • 函数调用链过深
    • 局部变量异常大

六、栈 vs 堆：性能差异​

对比项栈堆
分配方式移动一个指针（栈顶指针）查找合适的空闲块 + 更新内部数据结构
释放方式移动指针回去（弹帧）标记为可用（可能涉及合并空闲块）
速度🚀 极快（单指针操作）🐢 较慢（需要分配器介入）

💡 栈的核心高效原理：

压栈时，栈指针前进一个栈帧的大小；弹栈时，指针后退同样的距离。 一步指针移动 = 一次内存分配/释放，就这么简单。

七、内核空间（Kernel Space）​

虚拟内存的最顶端区域预留给操作系统内核。

  • 这些页映射到物理内存中的内核空间
  • 允许程序执行特权操作，例如：
    • 读写存储设备
    • 通过网络发送数据

八、总结​

区域内容特性
代码段可执行指令只读 + 可执行
数据段已初始化的全局/静态变量从可执行文件加载
BSS段未初始化的全局/静态变量自动清零，不占文件体积
堆动态分配的内存手动申请/释放，较慢
栈函数调用、局部变量自动管理，极快
内核空间操作系统高特权级操作
