在软件工程和 .NET 的世界里，**运行时（Runtime）**之前通常统称为**编译时（Compile-time）**。

但若要细分“代码环境”的阶段，具体可以分为以下三个层面：

### 1. 设计时 (Design-time)
这是**程序员写代码时**的环境，发生在你按下“启动”按钮之前。

- **环境**：Visual Studio、VS Code 等 IDE（集成开发环境）。
- **做的事**：编写源代码、利用 IntelliSense（智能提示）补全、进行语法检查（波浪线）、配置项目属性。
- **关键角色**：**程序员**和**代码编辑器**。此时 CLR 还未介入，代码只是一堆文本文件（`.cs`）。

### 2. 编译时 (Compile-time)
这是**代码从文本变成程序集**的阶段，是连接“源码”和“运行”的桥梁。

- **环境**：**编译器**（C# 编译器，即 Roslyn）和 **MSBuild** 构建工具。
- **做的事**：编译器读取你的 `.cs` 源码，进行语法分析和类型检查，最终将 C# 代码编译成**中间语言（CIL）**，并生成 `.dll` 或 `.exe` 文件（程序集）。
- **关键角色**：**编译器**。如果这个阶段出错，你会看到红色的编译错误提示（CS开头的错误码）。

### 3. 部署时 (Deploy-time) / 启动时
这是**程序集放在目标机器上，准备被 CLR 加载**的阶段。

- **环境**：操作系统和文件系统。
- **做的事**：将生成的 `.dll` 文件拷贝到服务器或用户的电脑上。当用户双击 `.exe` 或托管进程调用你的程序集时，CLR 才开始被激活并加载这些文件。

---

### 💡 核心总结（对照关系）

| 阶段 | 环境/角色 | 产物 |
| :--- | :--- | :--- |
| **设计时** (Write-time) | IDE、开发者 | 源代码文件 (`.cs`) |
| **编译时** (Compile-time) | **编译器** (Roslyn) | 中间语言 CIL（生成 `.dll`） |
| **运行时** (Runtime) | **CLR** + JIT（即时编译器） | 本机机器码（CPU 执行） |

---

### 🧠 进阶小贴士

你可能会听到“.NET 中的 **‘编译时’** 其实分为两个阶段”这种说法：

1. **C# 源码 → CIL**（编译时，由 C# 编译器完成，输出 `.dll`）。
2. **CIL → 本机代码**（执行时，由 JIT 编译器完成，发生在 CLR 运行时环境内）。

因此，严格来说，**只要进程还在运行，只要 CPU 还在执行指令，就永远处于“运行时环境”**。而在此之前的任何准备动作（写、编译、拷贝），都可以统称为**开发构建阶段**。
