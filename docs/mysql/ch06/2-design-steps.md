## 知识点

数据库设计通常分为**六个阶段**：

### 1. 需求分析

- **任务**：调查、收集和分析用户对数据与处理的需求；
- **方法**：访谈、问卷调查、观察业务流程、查阅文档；
- **成果**：**数据字典**、**数据流图（DFD）**、需求规格说明书；
- 是整个设计过程的**基础**，需求分析的准确性直接决定设计质量。

### 2. 概念结构设计

- **任务**：在需求分析基础上，对信息进行抽象，建立**独立于具体 DBMS 的概念模型**；
- **方法**：自顶向下、自底向上、逐步扩张、混合策略；常用 **E-R 模型**；
- **成果**：**E-R 图**（实体-联系图）；
- 特点：与硬件、软件无关，是现实世界到机器世界的中间层次。

### 3. 逻辑结构设计

- **任务**：将概念结构（E-R 图）转换为某个 DBMS 支持的**逻辑模型**（本教程为关系模型）；
- **内容**：实体和联系转换为关系模式、确定主键与外键、关系模式规范化（通常到 3NF）；
- **成果**：一组关系模式（数据库模式）。

### 4. 物理结构设计

- **任务**：为逻辑模式选取适合应用环境的**物理结构**（存储结构和存取方法）；
- **内容**：确定存储引擎、索引设计、文件组织、聚簇设计、存取路径；
- **成果**：数据库的物理设计方案；
- 依赖于具体的 DBMS 和硬件环境。

### 5. 数据库实施

- **任务**：根据设计结果建立数据库、装载数据、编写应用程序、调试运行；
- **内容**：用 DDL 创建库、表、索引、视图等对象；用 DML 录入初始数据；程序编码与测试；
- **成果**：可运行的数据库系统。

### 6. 数据库运行与维护

- **任务**：数据库投入运行后的日常维护与优化；
- **内容**：
  - 数据的备份与恢复；
  - 安全性与完整性控制；
  - 性能监控与调优（索引调整、查询优化）；
  - 数据库重组与重构；
  - 根据用户反馈进行修改和扩充。

| 阶段 | 主要任务 | 主要成果 |
| --- | --- | --- |
| 需求分析 | 收集分析用户需求 | 数据字典、数据流图 |
| 概念结构设计 | 建立概念模型 | E-R 图 |
| 逻辑结构设计 | 转换为关系模式 | 关系模式集合 |
| 物理结构设计 | 确定存储与存取方法 | 物理设计方案 |
| 数据库实施 | 建库、装数据、编程 | 可运行的系统 |
| 运行与维护 | 维护、优化、扩充 | 持续运行的系统 |

## 考点提示

- 高频考点：数据库设计的六个阶段及其顺序，各阶段的主要任务与成果。
- 易错点：E-R 图是**概念结构设计**阶段的成果，关系模式是**逻辑结构设计**阶段的成果——常考连线题。
- 需求分析是基础，概念设计独立于具体 DBMS，物理设计依赖具体 DBMS。
