## 知识点

### 1. 数据库设计的基本概念

**数据库设计**是指根据给定的应用环境，构造**最优的数据库模式**，建立数据库及其应用系统，使之能够有效地存储和管理数据，满足用户的各种信息需求和处理需求。

- 数据库设计是信息系统开发的**核心环节**；
- 目标：数据冗余小、数据独立性强、完整性好、易维护、效率高；
- 数据库设计具有**技术和管理的双重性**，需要数据库设计人员与用户密切配合。

### 2. 数据库设计的基本原则

1. **以用户需求为中心**：充分理解并准确表达用户需求；
2. **数据独立性原则**：数据与程序分离，提高可维护性；
3. **数据共享与最小冗余原则**：减少重复存储，避免数据不一致；
4. **数据完整性原则**：保证数据的正确性、有效性和相容性；
5. **规范化原则**：关系模式应满足一定的范式要求（通常到 3NF）；
6. **安全性原则**：设置合理的用户权限，保护数据安全；
7. **可扩展性（可维护性）原则**：适应未来需求变化；
8. **效率原则**：兼顾存储效率和查询效率。

### 3. 数据库设计的方法

| 方法 | 说明 |
| --- | --- |
| **直观设计法（手工试凑法）** | 凭经验设计，适合小型简单系统，质量难以保证 |
| **规范设计法** | 按步骤、分阶段进行设计，如基于 E-R 模型的设计方法、基于范式理论的设计方法 |
| **计算机辅助设计法** | 使用 CASE 工具（如 PowerDesigner、ERwin、MySQL Workbench）辅助设计 |
| **自动化设计法** | 使用工具自动生成数据库模式（了解） |

常用的规范设计方法：

- **新奥尔良方法**：将数据库设计分为需求分析、概念设计、逻辑设计、物理设计四个阶段；
- **基于 E-R 模型的设计方法**：用 E-R 图描述概念结构，再转换为关系模式；
- **基于关系模式规范化的设计方法**：以规范化理论指导逻辑设计。

## 考点提示

- 高频考点：数据库设计的目标与基本原则（数据共享、冗余小、完整性、独立性）。
- 易错点：数据库设计不仅是技术工作，还需要用户参与；设计原则是常考简答题。
- 常考"数据库设计的核心问题"——设计合理的数据模式（数据结构与联系）。
