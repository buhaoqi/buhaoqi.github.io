## 知识点

### 1. 函数依赖的基本概念

**函数依赖（Functional Dependency，FD）**：设关系 R 中有属性 X 和 Y，若对于 X 的每一个值，Y 都有**唯一确定**的值与之对应，则称 **Y 函数依赖于 X**，记作 `X → Y`。

- X 称为**决定因素**，Y 称为被决定因素；
- **完全函数依赖**：Y 完全依赖于 X，且 Y 不依赖于 X 的任何真子集，记作 `X —F→ Y`；
- **部分函数依赖**：Y 依赖于 X 的某个真子集，记作 `X —P→ Y`；
- **传递函数依赖**：`X → Y`，`Y → Z`（Y 不函数决定 X），则 `X → Z` 为传递依赖。

**示例**：`选课(学号, 课程号, 成绩, 课程名)`

- `(学号, 课程号) → 成绩`：完全函数依赖；
- `(学号, 课程号) → 课程名`，而 `课程号 → 课程名`：课程名对主码是**部分函数依赖**；
- `学号 → 系名`，`系名 → 系主任`，则 `学号 → 系主任` 是**传递函数依赖**。

### 2. 关系模式规范化的目的

- **减少数据冗余**，避免同一信息重复存储；
- **避免数据更新异常**（修改异常、插入异常、删除异常）；
- **保证数据完整性**；
- 使结构更合理、清晰，便于维护。

> 规范化程度并非越高越好，范式过高可能导致查询需要更多连接，降低效率；实际设计中通常达到 **3NF** 即可。

### 3. 第一范式（1NF）

**定义**：关系模式 R 的每个分量都是**不可再分的原子值**，即**属性的原子性**。

- 1NF 是关系模式的最低要求，不满足 1NF 就不是关系数据库；
- 不满足示例：`学生(学号, 姓名, 联系方式(电话, 邮箱))` —— 联系方式可再分。

**规范化方法**：将复合属性拆分为简单属性：

```
学生(学号, 姓名, 电话, 邮箱)
```

### 4. 第二范式（2NF）

**定义**：在 1NF 基础上，每个**非主属性完全函数依赖于候选码**，即**消除非主属性对码的部分函数依赖**。

- 主要针对**组合主键**的情况；
- 若主键是单属性，则自动满足 2NF。

**示例**：`选课(学号, 课程号, 成绩, 课程名)`，主键为 `(学号, 课程号)`

- 成绩完全依赖于组合主键 ✔
- 课程名只依赖于课程号（部分依赖）✘

**分解为 2NF**：

```
选课(学号, 课程号, 成绩)     —— 主键 (学号, 课程号)
课程(课程号, 课程名)         —— 主键 课程号
```

### 5. 第三范式（3NF）

**定义**：在 2NF 基础上，每个**非主属性既不部分依赖于码，也不传递依赖于码**，即**消除非主属性对码的传递函数依赖**。

**示例**：`学生(学号, 姓名, 系名, 系主任)`

- `学号 → 系名`，`系名 → 系主任`，存在传递依赖 `学号 → 系主任` ✘

**分解为 3NF**：

```
学生(学号, 姓名, 系名)       —— 主键 学号，外键 系名
系(系名, 系主任)             —— 主键 系名
```

### 6. 关系模式规范化的基本方法

1. 确定函数依赖集，找出候选码；
2. 判断是否满足 1NF（消除非原子属性）；
3. 判断是否满足 2NF（消除部分依赖，分解为多个关系）；
4. 判断是否满足 3NF（消除传递依赖，继续分解）；
5. 分解时遵循**无损连接性**和**保持函数依赖**原则；
6. 结合实际需求，权衡规范化程度与查询效率。

| 范式 | 要求 | 消除的问题 |
| --- | --- | --- |
| **1NF** | 属性不可再分（原子性） | 消除复合属性 |
| **2NF** | 1NF + 非主属性完全依赖候选码 | 消除部分函数依赖 |
| **3NF** | 2NF + 非主属性不传递依赖候选码 | 消除传递函数依赖 |

> 三者关系：3NF ⊂ 2NF ⊂ 1NF（满足 3NF 必然满足 2NF 和 1NF）。

## 考点提示

- 高频考点：1NF/2NF/3NF 的定义及判断，部分依赖与传递依赖的区分。
- 易错点：2NF 消除**部分依赖**，3NF 消除**传递依赖**——常考判断题。
- 常考题型：给出关系模式和函数依赖，判断属于第几范式并分解为高一级范式。
