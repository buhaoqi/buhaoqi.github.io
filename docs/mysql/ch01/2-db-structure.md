## 知识点

### 1. 数据库系统的组成

从**硬件、软件、数据、人员**四个方面理解：

| 组成部分 | 说明 |
| --- | --- |
| 硬件 | 服务器、存储设备、网络设备等 |
| 软件 | 操作系统、DBMS、开发工具、应用程序 |
| 数据 | 数据库中存储的各种数据及元数据（数据字典） |
| 人员 | 数据库管理员（DBA）、系统分析员和数据库设计人员、应用程序员、最终用户 |

从**结构层次**看，数据库系统采用三级模式结构，并通过两级映像实现数据独立性。

### 2. 三级模式结构

三级模式结构是数据库系统内部的抽象层次，由外模式、模式、内模式三级构成。

#### （1）外模式（External Schema）

- 又称**子模式**或**用户模式**；
- 是某个用户或应用程序所看到和使用的**局部数据的逻辑结构**；
- 是数据库用户的数据视图，与安全保密密切相关；
- 一个数据库可以有**多个**外模式。

#### （2）模式（Schema）

- 又称**逻辑模式**或**概念模式**；
- 是数据库中**全体数据的整体逻辑结构和特征**的描述；
- 是数据库系统的**核心和中心层**，与具体应用和具体硬件无关；
- 一个数据库**只有一个**模式。

#### （3）内模式（Internal Schema）

- 又称**存储模式**或**物理模式**；
- 描述数据的**物理结构和存储方式**（如记录的存储格式、索引、压缩、加密等）；
- 一个数据库**只有一个**内模式。

> 记忆口诀：**外模式看局部、模式看全局、内模式看存储**；外模式可多个，模式和内模式各一个。

### 3. 两级映像

三级模式之间通过两级映像实现转换：

#### （1）外模式 / 模式映像

- 定义外模式与模式之间的对应关系；
- 当**模式改变**（如增加新的关系、新的字段）时，只需修改映像，外模式可以不变，应用程序不必修改；
- 保证了数据的**逻辑独立性**。

#### （2）模式 / 内模式映像

- 定义模式与内模式之间的对应关系；
- 当**内模式改变**（如更换存储设备、改变存储结构、添加索引）时，只需修改映像，模式可以不变，应用程序不必修改；
- 保证了数据的**物理独立性**。

### 4. 数据独立性

数据独立性是指应用程序与数据之间相互独立，数据结构的改变尽可能不影响应用程序。

| 类型 | 含义 | 由谁保证 |
| --- | --- | --- |
| **逻辑独立性** | 数据库的整体逻辑结构（模式）改变时，用户的外模式不变，应用程序不必修改 | 外模式 / 模式映像 |
| **物理独立性** | 数据的物理存储结构（内模式）改变时，逻辑结构（模式）不变，应用程序不必修改 | 模式 / 内模式映像 |

> 说明：三级模式、两级映像和数据独立性是对"掌握数据库系统的结构与特点"这一考点的细化，是否作为必考内容以正式考试要求为准。

## 考点提示

- 高频考点：三级模式的名称、数量（外模式多个，模式/内模式各一个）及各自定义。
- 易错点：外模式/模式映像 → **逻辑**独立性；模式/内模式映像 → **物理**独立性，两者不可混淆。
- 数据库系统特点中的"数据独立性高"即由这两级映像实现。
